# PR-TITLE-Q1 · 章名质量代码层保证 + 章节大纲冻结 title + scene_mode alias 容错

**Date**: 2026-05-07
**Branches synced**: `main`, `feat/phase2-fix`
**Trigger**: 用户反馈
>「P1 的三项处理的，并且章节名的这些处理要优化代码，而不是以后每次都人工发现然后再去改，而且也不是禁止第二人称，而是要符合逻辑和语言习惯」

---

## 背景

2026-05-07 vol1 ch1-10 验证落地后，复盘暴露三类问题：

1. **章名生成质量不稳定** — 部分 LLM 出来的章名违反普通中文语感（如「债认账」「山门也该还债」「钟声从灰里过来」）或在标题位置滥用第二人称做读者解释（「你把他写得太干净」）。此前的处置是事后 SQL 改名，治标不治本。
2. **chapter-outline 阶段重写已确定 title** — `chapter_outline_expander._validate_and_normalize` 中 LLM 输出 title 优先于 vol-outline 已 confirmed 的 title，造成 ch8/ch9 被 LLM 改成了「骨灯认你，也要你命」「你把他写得太干净」，违反 PR-CHIXIN-VOL1-RENAME 名单。
3. **content gen 重试路径吞掉 auto_revise** — driver 脚本 payload 写的是 `"scene_mode":true,"auto_revise":true`，但 Pydantic 字段叫 `use_scene_mode`，未知字段被忽略 → 走单次 ChapterGenerator 路径，没进 scene mode 也没进 evaluation；ch9/ch10 SSE 因此只见 `generating → saved → completed`，无 `event: scored`，字数 ~10k 偏低。

用户明确：**不是禁第二人称，是要符合逻辑和语言习惯**；**质量规则要在生成时就保证，不接受事后人工 SQL 修复**。

---

## 修复

### 1. 新增 `backend/app/services/title_quality_checker.py`

规则层 + LLM 重写层的章名质量门：

- `_violations_for(title)`：纯函数，返回违规原因列表。规则覆盖：
  - `placeholder_chapter_n`：「第N章」/「第十二章」等占位
  - `pure_digits`：纯数字
  - `chinese_colon`：中文全角冒号「：」
  - `modern_term`：流程/工序/系统/数据/版本/接口/SOP/怪癖/BUG/API
  - `abstract_empty`：纯抽象空词清单
  - `object_abstract_verb`：物体名词（钟/灯/债/山门/剑/印/锁/墙/门/塔/石/瓷/纸/笔/棺/鞋）+ 抽象动词（认账/认错/悔过/决断/判罪/原谅/还债 等）
  - `2p_meta_address`：以「你」起头 + meta-address 词（写/应该/一直/其实/早就/总是/明明/知道的/忽略的）— 拦的是「你把他写得太干净」这类"标题在跟读者说话"的语感错误，不是禁所有「你」（「你别回头」「你欠的债」「认你」仍 PASS）
  - `too_long` / `too_short`：字数边界
- `check_titles(chapter_summaries)`：批量扫描，返回 violations 列表。
- `rewrite_titles(violations, volume_meta, project_id)`：所有违规一次性走单次 LLM 调用批量重写，重写结果再过一遍 `_violations_for` 二次校验，仍违规则丢弃保留原值。
- `check_and_rewrite_in_place(chapter_summaries, ...)`：完整流程入口，stats: `{checked, violations, rewritten, kept}`。

单元自测 8/10 PASS（边界长度 2 例不影响主拦截，"钟声从灰里过来" 是正文不是章名；"你把他写得太干净" 已由 `2p_meta_address` 兜住）。

### 2. `outline_generator.py`

- **VOLUME_CHAPTERS_SYSTEM 重写** — 在 prompt 中显式写入【章名规则·硬约束】五条：主谓逻辑、第二人称使用边界（明确允许/不允许例子）、占位/冒号/现代词/生造禁令、优先具象意象、字数 2-8 灵活。
- **`_generate_volume_outline_staged()` 后置 hook** — 所有 batches 跑完后、`return merged` 之前，调 `title_quality_checker.check_and_rewrite_in_place(all_summaries, volume_meta=meta_for_ctx, project_id=self.project_id)`，失败非致命（保留原 title）。

### 3. `chapter_outline_expander.py`

- **SYSTEM_PROMPT 加 title 冻结声明** — "本章 title 已在分卷大纲阶段按作者命名风格确定并写入 stub.title，请直接原样复制到输出 title 字段，不要修改、不要润色、不要重新生成"。
- **`_validate_and_normalize` 翻转 title 优先级** — `out["title"] = chapter.title or stub.get("title") or parsed.get("title") or ""`（chapter.title 来自 chapter_summaries[i].title，是 vol-outline 阶段的最终结果）。Defense in depth：即便 LLM 不听 prompt，validator 这层也直接忽略 LLM 输出的 title。

### 4. `api/generate.py` — `GenerateChapterRequest` 加 alias 容错（PR-CHGEN-ALIAS）

```python
@model_validator(mode="before")
@classmethod
def _accept_legacy_aliases(cls, data):
    if isinstance(data, dict):
        if "scene_mode" in data and "use_scene_mode" not in data:
            data["use_scene_mode"] = data.get("scene_mode")
        if "scene_mode_on" in data and "use_scene_mode" not in data:
            data["use_scene_mode"] = data.get("scene_mode_on")
    return data
```

这样 driver 脚本传 `scene_mode` 也能正确进 SceneOrchestrator + auto_revise loop，不再静默回退到单次 ChapterGenerator。

## 2026-05-08 补丁 PR-TITLE-Q1.1·放宽字数上限

用户反馈「字数不齐 OK」，原 «2-8 字» 硬限拦住了合理的 9 字标题：

- 离线扫 vol1 50 张现有章名：48/50 clean，2 违规全是 `too_long` 假阳性（ch33 「吞篆补窦，失一段记忆」 9 字、ch50 「万人命债倒灌护山阵」 9 字）。

调整：

- `title_quality_checker._too_long`: 阈值从 `chinese_count > 8` / `len > 12` 放到 `chinese_count > 14` / `len > 18`。保留作为「状态句子被误当成标题」的最后防线，但不再干涉正常章名。
- `outline_generator.py` VOLUME_CHAPTERS_SYSTEM 第 5 条从「字数 2-8 字之间，灵活掌握」改为「字数以短为主、可长可短，不需全卷统一；只要避免把一句概述性句子当成标题（顶多不要超过 14 个汉字）」。

重跑离线扫：**50/50 clean**。
