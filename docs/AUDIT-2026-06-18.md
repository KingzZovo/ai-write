## 🔴 严重 — 立即处理

### 1. `DISABLE_AUTH=1` 正运行在部署 `.env`
`backend/app/main.py:191` `AuthMiddleware` 首行逃生舱：

```python
if os.getenv("DISABLE_AUTH", "0") == "1":
    return await call_next(request)
```

线上 `.env` 设了 `DISABLE_AUTH=1` → **整个 `/api/*` 无鉴权**：任意访问者可读写全部项目、触发生成（烧 LLM 额度）、导出全文、改 prompt。

### 2. 暴露面：nginx + 前端绑 `0.0.0.0`
`docker-compose.yml`：数据存储均锁 `127.0.0.1`（postgres/redis/qdrant/neo4j/backend:8000），但
- `frontend` → `3100:3000`（全网卡）
- `nginx` → `8080:80`（全网卡），且 `/api/` 直接反代到无鉴权 backend。

第1+2条叠加 = **公网任意访问**，为当前最大实际风险。

### 3. 管理端点鉴权可被未签名 JWT 绕过
`backend/app/api/admin_usage.py:38` `_caller_username` 用
`jwt.decode(token, options={"verify_signature": False})` 取 `sub`，依赖
"AuthMiddleware 已验签"。但 `DISABLE_AUTH=1` 时中间件被跳过 →
手搓 `{"sub":"king"}` 未签名 JWT 即可过 `_require_admin`
（`ADMIN_USERNAMES=king`），调用实体物化 / 配额改写等管理操作。
`backend/app/middlewares/quota.py:60` 同样信任未验签 token。

**已修复（本轮）**：两处改为独立验签，详见 `docs/AUDIT-2026-06-18.md` 末"已执行"。

### 4. 硬编码默认凭据
`backend/app/api/auth.py:19-24`：未设 `AUTH_PASSWORD_HASH` 时回退内置 bcrypt
hash，默认用户名 `king`。线上 `.env` 未设 → 默认口令有效。关掉 `DISABLE_AUTH`
后这是唯一防线，必须设自定义 hash。
