# SSE 客户端结束、错误与残稿保留

日期：2026-10-07。未部署。

## 问题

共用 apiSSE 原先把 EOF 当成功，把 JSON 解析和应用回调置于同一个 catch，导致回调错误或坏帧可能被追加成正文。RewriteMenu 没有 onEvent，所以服务端 error 事件不会阻止采用已有的半截输出。章节工作区在没有后端 generation_interrupted 事件的网络失败时会恢复旧正文；修订开始后仍沿用上一版本的 saved 标记。

## 改动

- 当前后端各入口均发送单行 JSON 和 [DONE]。读取器仅以 [DONE] 正常结束；无结束标记的 EOF、读取失败、无效 JSON/非对象事件走 onError，再且仅一次 onDone。
- 支持逐字节 UTF-8、CRLF 和 data: 后无空格，不将协议数据或回调异常作为小说正文。
- 无事件类型的 error，以及 error/failed 终态事件传给 onError。具名 revise_error/save_failed 保留给调用方，因为后端可能继续保存与验收；本地复核发现并修正了最初把所有 error 字段视作终止的实现。
- finally 中取消 reader 并释放锁。主动取消依据 AbortSignal 和异常名称识别，兼容不同环境下 DOMException 不属于 Error 的情况。
- 工作区收到未确认保存的正文后发生传输失败，保留编辑区片段并标草稿。新修订开始清除上一候选的保存确认，避免半稿误标已保存。
