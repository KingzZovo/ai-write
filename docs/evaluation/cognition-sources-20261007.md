# 逐章认知账本、来源边界与耐久提取

## 原问题

旧 character_cognitions 每个角色只有全书累计 knows/does_not_know，无法区分信息来自哪章或哪个正文版本。重写早期章节会读到后文认知，改稿/删章后也无法撤销旧信息。提取借用通用 evaluation 路由、截去正文中部、最多保留十项，解析失败与无变化都返回空数组。

## 实现

新增迁移 a1001929 和 chapter_cognition_extractions，保存章节身份、完整来源凭据、变化数组、绑定输出的哈希与 pending/running/queued/completed/failed/obsolete 状态。同一章节版本唯一；旧累计表不删、不伪造来源，只有显式 legacy 管理函数可读取，生成不使用。

ContextPack、SSE 修订、后台生成、后台评审、手动评审五处都传入当前章边界。读取仅合并之前的 completed 正文所对应的 completed 认知记录；校验作品、全书章号唯一性、正文/标题/卷关系/状态等来源指纹及逐字引文。改稿、删章、转草稿、移卷、重编号和重复章号不依赖后台清理即可排除旧认知。重新从有效变化重建，前文“未知”不会被已失效后文“得知”永久覆盖。

新 chapter_cognition Registry 任务继承 extraction 的端点与输出预算，拥有独立 schema；全文输入、不再硬编码 800 输出上限或十项截断。严格解析（含重复字段）与逐字依据校验，允许一次格式修复，180 秒总期限；空数组只有在明确有效返回时才表示无变化。模型调用不占用本模块持久化事务。

保存通知 outbox 在同一数据库事务内创建实体和认知两类任务后才确认；插入失败两者及通知确认一起回滚。直接提取和重放共享项目事实租约，模型后重新核对并锁住当前源再发布。原文变化则作废，取消/失败保存可重试状态。每分钟的恢复调度发送 pending 工作，失败、运行或排队超过五分钟可重新投递；重复消息由项目租约和已完成结果复用保护。队列确认提交后才发消息，发消息失败或进程中止也不丢工作。恢复到曾经作废的正文版本可重新排队。

日志筛选和任务名称补充“章节认知变化”，不改默认模型。

## 验证

- 50 项针对性测试通过（15.58 秒）：真实 PG 的历史边界、旧账本排除、标题/正文/草稿/删除/移卷/重复章号、输出篡改、完整长正文、已完成复用、模型阶段作者改稿、失败两次、取消及租约释放、消息失败再投、恢复旧版、真实 Registry 预算 9000、通知交接事务以及迁移升级/降级/再升级。
- 迁移往返保留作者正文与旧累计账本；没有在正式数据库执行迁移。
- 前端 97 项通过，TypeScript 类型检查通过。
- 后端最终全量 **1911 passed，4 条既有 warnings，286.63 秒**。

按 shadow-mind 无可信只读隔离环境回退条款，进行本地架构及正确性两轮独立复核：确认所有应用 load_ledger 调用都传边界，通知确认与两类任务创建同事务，模型阶段不持行锁，旧版本不能发布为当前事实，取消和投递失败没有静默完成。复核补充了旧正文恢复后的 obsolete→pending 路径，以及新任务的 UI 名称。

## 未完成与限制

逐字证据只证明能定位，不证明模型对角色知情、猜测、误解的解读正确。本批尚未进行新提示的真实中文正文对照，不宣称提取质量合格。已有 apply_changes 的字符串合并、每人物 knows/does_not_know 各 30 项的渲染前容量，以及约 1200 字提示预算仍存在；所有原始逐章变化保存在新表，后续可调整召回而不丢原始数据。

没有批量调用模型重建历史无来源账本；旧完成章节须经过明确的重建流程，不能假定已拥有新来源记录。恢复调度容许重复消息，长期排队会重投，实际跨进程与 ARM 调度仍需验收。迁移和源码均未部署到 ARM 隔离环境或正式生产。实体/认知租约共用，吞吐及 500 万字认知读取成本仍待专项测量。
