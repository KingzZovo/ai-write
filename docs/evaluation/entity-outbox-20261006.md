# 正文保存事务待办（2026-10-06）

## 范围与实现

上批 a1001924 的提取记录在任务开始时才创建，保存后的首次消息失败或提交前任务提前消费可能永久漏掉正文。本批 a1001925 使用 PostgreSQL 触发器，把 completed 非空正文的来源变更和作者保存放进同一事务。

- `entity_source_outbox` 每章保留一条最新通知，单调 revision 防并发旧消费者确认新通知。正文、标题、状态、卷身份、局部/全书章号变更触发；摘要和字数单独变更不触发。
- 卷的作品归属或卷序变更也捕获其 completed 章节。直接 SQL、ORM 和已有生成/回滚保存入口均受数据库约束覆盖。
- `entity_outbox.py` 每批至多50章，在同一 PG 事务建立来源绑定的提取记录并按 revision 确认通知；不用模型或消息服务。失败一起回滚，重复消费不重置既有提取状态。
- Beat 每30秒转交一次；既有60秒实体恢复任务负责投递。已有即时发送保留作低延迟路径，不能代替事务待办。
- 无法核实来源的通知轮转到队尾保留，允许以后修复全书章号或状态，不捏造事实。
- 迁移不回填历史小说，不自动发动全库模型重建。生产启用必须运行迁移；单纯 metadata.create_all 不安装触发器。
