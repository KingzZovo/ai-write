# 自动生成与同步手动评审的稿件来源

ChapterEvaluator新增chapter_source，存在chapter_id时在模型调用前对实际输入正文/细纲生成摘要，成功解析后随EvaluationResult返回。没有章节ID的旧调用继续来源未知，失败结果不伪造有效评审。

ChapterEvaluation增加可空source_json，迁移a1001933（父a1001932）。流式初评/末轮复评、后台生成评审、同步手动评审四处保存实际评审返回的来源，不以保存时的新正文倒推。同步手动响应还返回来源和parse_failed/failure_reason，避免失败哨兵分数缺少说明。

最新评审接口对保存表结果使用同一来源核对；旧行source_json为NULL仍显示unknown，不回填历史来源。原EvaluateTask来源记录继续兼容。

## 验证

- 61项来源/后台任务/作者要求/结束原因/验收回归，加46项评审提示词/JSON恢复/合同/失败原因回归，共107 passed。
- 新增6项离线覆盖模型执行时细纲变化仍保留原输入摘要、保存表读取的三种来源状态、四处写入接线、历史列可空。写入接线为AST检查，不等于完整流式/后台流程实测。
- 新增1项真实PG门禁，核对来源持久化及改稿后的changed状态；仅成功收集，未执行。
- AST与git diff --check通过，静态迁移唯一head为a1001933；没有实际执行迁移。
- 按shadow-mind无可靠只读隔离回退，冻结后本地复核调用前快照、模型结果到四处持久化、同步响应与旧行兼容，以及发布顺序。检查时移除了误加到非评审保存调用上的字段，最终只有四处ChapterEvaluation构造使用source_json。

## 发布与剩余

必须先迁移a1001933再发布新API/worker；否则ORM查询新列会失败。此次未更新运行环境或共享CPA。真实数据库DDL与往返、完整ASGI/Celery/浏览器、模型与文学质量验收仍待完成。

来源标记只覆盖章节身份、正文和细纲，不代表风格、前后章、认知或作者要求没变；内容恢复到相同值也不能证明中间从未编辑。它是历史评审的内容核对，不是全面版本锁或文学合格凭证。
