# 人物后台恢复批次耗时边界

默认一批最多20个项目，每项目投影等待120秒、失败退避写入最多15秒，逐项目累加可超过40分钟；最初的图待办扫描没有整批时限。每分钟投递的新消息可能继续积压。

新增 `services/recovery_deadline.py`，为作者人物档案及删除恢复的公共入口提供300秒协作式预算，覆盖扫描、投影、确认和失败退避。原有每项目120秒保留，以免因本轮改动缩短大项目快照预算。批次超时抛出 TimeoutError，不把部分完成写成整批成功；外部 CancelledError 原样传播。已确认的项保持完成，未确认 token/删除凭证仍由下次周期扫描。

两个 beat 配置新增 expires=60，旧周期消息超过一分钟不再开始执行；这只限制排队消息，不会终止已经运行的任务，也不删除数据库待办。

## 验证

- 后端65项通过，包括新增13项边界验证：两个入口的扫描/投影/退避超时，外部取消，部分项目完成后超时，档案确认超时，周期过期配置，以及公共投影在快照/提交阶段取消后的会话退出与不确认。
- 相关5文件AST与 git diff --check 通过。
- 代码冻结后按 shadow-mind 无可靠只读隔离回退做本地两类复核：取消/事务/重放语义，以及任务调度/完成声明。外层时限触发的 CancelledError 不被内层 except Exception 吞掉；公共投影会退出会话，PG提交结果不确定时依赖已有清理日志及幂等重放。

## 限制与后续

这是 asyncio 协作式取消预算，不是操作系统硬时限。同步阻塞代码、不响应取消的驱动和事务清理可能延长实际耗时；任务桥接的引擎销毁也不属于恢复协程预算。离线替身仅证明取消传播与调用顺序，不证明真实PG回滚、连接池释放或Celery消息过期行为。

真实双库故障/取消、worker负载与多进程重叠、待办索引/分页/公平性和大型作品快照性能仍待验收。本批未部署，不涉及模型路由、提示词或小说文学质量结论。
