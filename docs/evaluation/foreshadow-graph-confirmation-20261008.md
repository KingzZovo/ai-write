# 图谱来源的伏笔建议确认与恢复（2026-10-08）

## 用户流程

图谱来源且读取时副本一致的建议现在可以提交确认。接口先在同一SQL事务保存作者请求与 confirming 状态，提交成功后返回202；界面切到“确认同步”，轮询执行进度。同步完成才成为 accepted；失败可重试，来源冲突且回执确认未执行时可以放弃。来源不明的旧记录仍不能直接确认。

## 持久性与来源边界

- 新表 foreshadow_confirmation_jobs（迁移a1001940，父a1001939），以建议ID为唯一命令ID，保存首次请求账号/时间、执行次数、令牌及结果。重复请求不替换原作者意图。
- 图谱写入前以唯一约束+回执节点写锁串行化同一命令，再锁定目标伏笔读取真实属性。正文锁定核验和图谱属性比对均通过才修改兑现状态；模型不参与确认执行。
- 状态变更与 applied/rejected 回执同属一个Neo4j事务。回执独立于伏笔节点：删除目标后仍能识别先前是否执行。拒绝回执也阻止迟到任务重新应用旧请求。
- SQL提交失败或图谱提交响应丢失后，恢复先读取原回执，不重放修改。投影使用图谱当前值，并在既有作品物化互斥锁内读取/写入，避免用旧回执的结果覆盖后续作者修改。
- 任务与建议完成状态在SQL同一事务保存；原快照和证据继续保留。请求时刻存于任务，实际图谱决定时刻与请求账号写入建议处理记录。图谱来源在历史页最多报告副本一致，不把副本比对当成图谱长期一致保证。
- Celery任务soft120/hard150秒，内部90秒操作上限；Beat每60秒恢复，10分钟过期租约、每周期最多3次，手动重试保留同一命令及首次请求信息。内部错误只保存异常类型。
- 降级若仍有未处理任务或 confirming 建议则阻止删除恢复表。迁移文件静态检查显示唯一head为a1001940。
