# 章节细纲的事实、篇幅与收束（2026-10-07）

检查确认两条路径行为不同：异步任务使用 chapter_outline_expander，已经读取完整书纲和前章当前近文，但没有传正文预算；流式 OutlineGenerator 则只保留书纲 title/main_plot，而本次书纲实际使用 raw_text/structured/volume_plan，这会丢掉事实约束。两个模板都要求固定 300–500 字细纲和章末钩子；流式 schema 还固定示例为正文 4000 字。

## 修改

- 流式生成保留完整书纲；API 通过项目、卷身份和章号查有效预算，稳定卷 ID 优先。同卷重复章号在模型前返回 409。
- 异步扩写按现有预算解析器处理章预算、旧 50000 字默认值与项目设置；提示词明确正文预算不是细纲长度，保存的 word_count_target 以有效预算为准，不接受模型擅自扩大。
- 共用篇幅和收束指令只在分卷计划连续完整、当前卷为最后卷、章号到达卷章数且不与书纲预估章数冲突时明确标为全书终章。不会把数据库里最后创建的一章直接判为结尾；计划不足时按既定安排区分收束。
- 取消固定细纲字数及关键事件条数，替换会诱导新角色与悬案的婚礼示例。无高压行动或关键推断时可填“无”；终章交接字段明确完结，不为填写字段创造续篇。
- 新建注册表默认提示同步去掉强制章末钩子；既有自定义注册提示保留，扩写系统要求仍明确终章收束。

## 验证

56 项针对性通过：两种生成模式保留完整书纲与 1800 字预算；不将非终卷、普通章、空/不完整计划和章数冲突判成终章；真实 PG 扩写既有目标/历史默认目标均正确传入并保存 1800，模型报 9000 不改变预算，原正文保留；重复章号在调用前拒绝。首次新测试缺少临时 schema 的 outlines 表，随后模型替身参数签名不符，均修正测试装配后重跑通过。

补重复章号检查前全量 2040 passed、4 项既有 warnings、326.75 秒；最终 56 项针对性覆盖新增 409 行为及本轮功能。按 shadow-mind 无可信只读隔离条款本地独立复核，发现预算查询可能在重复章号中任取一条并修正。隔离四服务已部署 8e9b247，234 个 Python 源文件一致。真实 ARM ASGI 请求在进程内替换生成函数后，验证完整书纲与 1800 字预算进入终章入口；模型调用为零、无生成文字，该探针不证明真实模型文学质量。生产未更新。旧流式细纲保存的原子性、上游编辑期间的上下文有效性及整书正文仍需后续审查，不把本轮提示词和预算修复视作完整工作流合格。


## 三章真实细纲及编辑复核

使用已编辑并确认的卷纲版本 2，三个异步任务分别请求一次，均完成并保存细纲。轮询观测耗时依次 92.61、95.19、65.15 秒；成功模型调用延迟为 56.613、63.994、34.504 秒，三次均 Claude 路由失败后 Luna 返回，不是 Gemini 的产出表现。调用记录中三章均有 1800 字预算，只有第三章带明确终章指令；第二章的实际提示保留第一章的编辑新句、排除了旧错误句。

按编辑标准审读，而不是模型评分：

- 第一章清点、说开顾虑、优先兑现家谱期限的安排基本成立，但 summary 写成菜谱是林禾“自己的旧物”。只改该处为母亲的旧物，保留原模型输出。
- 第二章只交还家谱一次，无凭空找副本或猜补缺文。但开场状态仍复述上一日，time_delta 写“夜间或次日上午”，与梗概次日上午开场不一致。局部修订 summary 起句、start_state 起句和 time_delta，统一为隔一夜后、退租前一天上午开场，中午前交付、随后检查旧书。
- 第三章明确全书完结，物品搬离暂存、社区工作台安排和给母亲的电话均落实。power_resource_map 又将菜谱说成林禾所有，仅改成由她保管母亲的菜谱。

三章共 5 个字段/片段做编辑修订；PUT 后重新 GET 全部章节，逐字段验证与候选一致，数据库章预算和细纲 word_count_target 都为 1800，正文仍为空。模型原输出与任务结果均保留。这不是模型自动纠错，也不应把三章细纲生成成功视为小说已经合格。

剩余文学问题：细纲多处重复规则、修补过程仍泛化；同一物品的归属在不同字段反复漂移，需继续检查事实传递和正文表现。下一步以这份编辑候选试写，审查关键场面、语言和连续阅读；同时继续旧流式保存安全、浏览器全流程及生产发布验收。
