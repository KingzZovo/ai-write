# 作者认知任务与历史补提取（2026-10-08）

本批完成代码、离线验证和本地冻结复核，尚未部署。目标是让作者能处理认知提取缺失/失败，并防止后台旧消息、改稿及重排让后章使用错误材料；本批不判定实际小说产出已合格。

## 作者可见的变化

- 桌面“记忆中心 → 人物认知”与移动“工具 → 人物认知”共用面板，分页查看当前完成保存稿的提取状态、执行次数和完整原文依据。
- 缺失、失败、失效和结果损坏可单章提取或重试。有效完成结果与活动任务复用；普通后台消息不能重置失败预算。
- “补提取历史完成章”持久保存本次全部章节 ID，每批至多 100 章，保留游标与统计；新增章节在下一次安排中纳入。处理时重新核对当前保存稿，只安排缺失项，保留有效结果和已知失败。
- 面板明确区分“安排已结束”与“提取完成”。模型返回的有效空数组表示没有提取出明确变化，不表示人物一无所知；“当时仍不知”保留历史时间，不升为当前未知。
- 连接断开或响应缺失时保留固定请求及原来源版本，作者可确认原提交；切项目、分页或原章删除后，迟到响应不会改写新界面。

## 实现合同

`ChapterCognition.cycle_id`隔离每轮执行。迁移把既有行的初始周期设为行 ID，新作者重试与 obsolete 来源重新交接会换周期、清空执行令牌和次数。新任务携带周期，认领、模型调用前检查和写回都受周期/令牌/当前来源约束；旧三参数消息仅兼容记录的原始周期。`delivery_id`仍把失败后的剩余尝试绑定到原 Celery 请求，每轮最多 4 次执行，每次至多一次格式修复。

`cognition_requests`在同一事务内预约请求、绑定内容签名并写入受理结果。来源 hash 和原记录版本必须匹配；重复请求返回原回执，即使原章已删除也不创建新任务。请求和补提取任务随作品永久删除清理；受理记录不随单章删除而丢失。父作品锁先于章节/任务锁，模型调用与队列发布不持作者事务。

`cognition_backfills`只保存章节清单、游标和统计，不复制小说事实。每次推进与认知入队同事务提交，中断时共同回滚；现有`cognition.replay_pending`每分钟入口先推进一批，再恢复/派发提取。只读列表使用批量来源核对，没有每章两次来源查询。

`load_ledger`从前章清单检查覆盖，未提取的完成章不再被视为空账本。来源/空结果/完整原句共同校验；读取结束前分批复核完整来源，并比较前章集合、章序和目标边界，避免读取期间的改稿或重排形成混合材料。依赖材料不可用时停止生成/评审，提示到人物认知入口处理。

API 都在现有登录中间件下，根路径为`/api/projects/{project_id}/cognition`：

| 方法与相对路径 | 用途 |
| --- | --- |
| `GET /chapters?limit=20&offset=0` | 当前章节状态分页（最多 100 章） |
| `GET /chapters/{chapter_id}` | 完整认知条目和逐字依据 |
| `POST /chapters/{chapter_id}/retry` | 携固定 request_id、source_hash、version 受理当前保存稿 |
| `GET /backfills` | 最近 5 次安排的进度与统计 |
| `POST /backfills` | 携固定 request_id 安排历史补提取，复用正在安排的清单 |

## 中文质量、Gemini 与剩余工作

按[中文小说编辑标准](CHINESE_FICTION_EDITORIAL_STANDARD.md)，逐字引文用于定位，不能证明模型正确理解了人物是否相信、误解或真正获知。本批没有将模型评分或测试数量作为小说合格依据，也没有切换默认模型。

既有[CPA 路由记录](cpa-gemini-routes-20261006/REVIEW.md)包含`gemini-3.1-pro`，同名模型曾经过不同上游；此前[正文对照](context-guidance-20261007/REVIEW.md)仍发现限知视角越界与自动评审高分不符。当前没有新的 CPA 调用。需要固定实际线路，用相同资料比较完整及连续章节，再按人物口吻、场面、信息边界、承接、关键动作与编辑修改量决定是否采用 Gemini。

后续仍需完成认知条目的作者修订/驳回和整书语义召回。当前上下文仍读取全体历史正文并两次核对，1005 章交接样例不是 500 万字真实服务容量或费用验收。

前端组件执行、真实浏览器、PostgreSQL/worker 联调、累积迁移和部署均未完成。源码新增`a1001947`，最后记录的隔离运行版本仍是`c4b4a4b`。上线前需协调停止旧 API/worker 写入、完成迁移和隔离验证，再启动支持执行周期的新版本；不能把旧消息格式兼容当成旧二进制可混跑的证明。
