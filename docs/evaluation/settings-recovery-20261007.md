# 书纲设定提取：持久结果与恢复

状态：代码及离线验证完成，数据库迁移、双库验收、浏览器验收和部署未完成。

## 修复内容

原流程在模型返回后直接写图并同步 PostgreSQL；同步失败时结果没有持久记录，再次点击会重新调用模型，可能产生不同设定。页面刷新也无法知道先前提取是否完成。

- `OutlineSettingsExtraction` / `a1001931` 保存项目、书纲来源摘要、完整已校验结果、状态、尝试次数、重试时间及最终同步计数；同书纲同来源唯一。
- `outline_settings_delivery.save_receipt` 锁内核对来源并提交结果，再执行 Neo4j 写入和严格 PostgreSQL 投影。已有同源结果优先，模型调用期间不持有读事务。
- `deliver_receipt` 按项目 → 书纲 → 结果记录顺序锁定，来源变化标为 stale，完成记录直接复用。普通同步失败保留结果并安排退避；连接、提交、取消异常依靠事务回滚保留之前已提交的记录。
- 每分钟 `entities.replay_outline_settings` 扫描最多 20 条到期 pending/failed，每条最多 120 秒。后台不调用模型，并在获得锁后再次检查重试时间；手动重试可提前进行。
- GET `.../outlines/{id}/extract-settings` 只返回当前来源的状态和计数，不返回结果正文。前端刷新读取，待恢复时每 5 秒轮询；切换项目/书纲/稿件后丢弃迟到响应。读取状态不会发起模型生成。
- 新文件：`backend/app/services/outline_settings_delivery.py`、迁移 `a1001931_outline_settings_receipts.py`、离线与 PG 专项测试。
