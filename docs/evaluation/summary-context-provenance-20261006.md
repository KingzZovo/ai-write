# 写作上下文的摘要来源校验

## 实现范围

`summary_provenance.current_summary_sql()` 在 PostgreSQL 内计算与 Python 一致的标题/正文/摘要指纹，来源匹配且正文/摘要非空才返回摘要。旧来源、改稿或摘要被另一写入路径替换，返回 NULL。校验需读取数据库中的正文，但邻章和卷摘要查询不把完整正文传回应用。

- ContextPack 前情改为最近五个实际章节，不再跳过摘要缺失的邻章寻找更旧摘要。来源失效明确显示缺口；未完成章节标为待审稿参考，不提升为既定事实。未来细纲继续从 outline_json 读取。
- 时间锚点只使用来源有效、状态 completed、持久化全书章号严格早于当前章的摘要。
- 评审前后邻章摘要采用同一校验；来源失效时仍提供当前正文首尾节选，保持真实相邻章和后文独立边界。
- 旧 HierarchicalMemory 的卷内前情使用校验后的摘要并标明缺口、草稿身份。新生成卷摘要必须所有现存章节均 completed 且摘要来源有效，不能跳过缺章摘要拼出虚假完整性；已有卷摘要的来源追溯不在此项完成范围。
- 剧情线分析、完结准备度、确定性相关章回读改用来源校验后的摘要。相关章回读不再拿章节标题冒充摘要，未完成章节不返回历史摘要。
- 大纲生成的上一章摘要只取 completed 且来源有效的稿件；扩写没有细纲时不再取未经核实的章节摘要作为规划梗概。
