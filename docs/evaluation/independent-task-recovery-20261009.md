# 独立任务中断核查与有限恢复

2026-10-09，分支 `fix/2026-10-06-pipeline-safety`。本批完成源码与离线验证，未部署。

独立任务中断后，现在先核对原请求、已交付内容及目标来源，再决定是否继续。已有正文、候选或作者修改时保留并转为待审；只有没有交付且来源一致的新版任务才允许恢复。心跳过期本身不授予执行权。

## 实现与行为

- 首次认领在作品物理锁内记录执行来源，与原参数、执行 UUID 和第一次尝试同事务提交，确认后才进入模型链。完整参数副本和尝试摘要不因恢复重建。
- `generation_task_sources` 记录作品设置、目标章稿/细纲及分卷、书纲/目标卷纲、显式或作品指定的风格/结构参考行。参考书纲还记录实际骨架摘要。分卷和大纲按 64 行分页核对，不限制整书总长度；持久来源为有界摘要。
- `generation_task_recovery` 仅处理有版本、UUID 和过期心跳的活动独立任务。90 秒过期只作候选；必须实际取得与其他生成/作者写入共用的作品锁，验证原物理连接，再按 Project→Task 重读。取消、归属变化、活动整书任务及新心跳均不能被旧扫描结果绕过。
- 全请求最多 **3 次执行（首次加两次恢复）**。恢复直接提交新 UUID、下一次 running 和追加历史，没有重置 pending 的窗口。历史绑定前后 UUID、原参数摘要和尝试次数；坏记录或预算耗尽转为待审，原记录不清空。
- 已保存正文证明、返回结果、润色稿或候选片段均保留待审，不自动重写。保存证明在隔离后仍指向原交付 UUID；它是历史证明，不能因当前隔离 UUID 不同而误报正文丢失。
- 进度写入明确区分实际候选与两个已知操作提示。未知旧文字、空 candidate 标记和异常字数保守待审。空字符串、纯空白和无正文的流式心跳不写入候选，也不清除已有候选。
- pending 的历史候选保留待审；不完整的旧执行参数、来源、心跳或尝试记录不能被当作新任务覆盖。缺少首次来源的旧活动任务不现场补猜。
- `generation_task_dispatch` 每轮默认 32、最多 100 个任务，仅扫描元信息，跳过回收站、批次/整书子任务及被锁定任务；按 Project→Task 再核对后提交派发时间，确认提交后才发布原任务 ID。派发时间不修改 `updated_at`，broker 失败或回应不明不重建任务、不重置预算。
- Beat 每 30 秒投递到 `pipeline-control` 的发现任务，再调用明确的 `tasks.recover_async_generation`。普通 HTTP/消息重复仍只读已认领任务；没有新增 HTTP 隐式恢复。

首次来源只保护所记录的目标和材料，**不是全部前文、人物图谱、提示词、风格派生材料或路由的冻结副本**。各次执行仍重建当前上下文。没有落盘的模型输出无法被当作已保存交付；恢复可能再调用模型，不能承诺模型请求恰好一次。

## 长书读取

1005 章、5,220,810 字符的 SQLite 用例中，提交、首次认领和恢复各读取目标章正文一次；另外 1004 章正文没有被恢复核查读取。当前章来源表示小于 180 字符。

130 卷的用例覆盖三页，末卷修改能阻止恢复。参考书用例包含 5,226,000 字符，骨架查询只取剧情卡和章序字段，不再顺带读取切片原文；保留原有至多 400 行、覆盖首末章节的采样，末条骨架变化或损坏进入待审。这里没有将 400 行骨架当作完整小说质量验收。
