# 弧规划固定请求与持久恢复

2026-10-09，基于 `d0a81dc`，仓库 `/root/ai-write`。本批完成源码、离线验证及两轮冻结本地复核，尚未部署；没有调用 CPA 或切换默认模型。

## 问题与结果

此前弧规划在 HTTP 调用内连续生成元信息和每批五章。中断后没有持久阶段记录，重试可能重做已成功的规划，也无法可靠判断创建分卷是否已经提交。首次弧还把卷号写死为 1，下一弧按前弧卷号追加，可能与实际目录冲突。

现在作者先读取本书当前来源，以固定 UUID 提交完整创作材料和原目标章数。后台按阶段保存输入、尝试、失败原输出和已接受章纲；恢复沿用这些记录，只继续未完成阶段。全部规划完成后，分卷、全部空正文章草稿、完整大纲和创建回执在同一事务提交，卷号按实际最后卷号追加。HTTP 受理不再冒充规划已完成。

## 执行和来源合同

独立 `ArcPlanningRequest` 没有扩展既有五类 `GenerationTask`。请求绑定本书、作者原话、章数、分卷顺序及前弧当前规划/正式作者进度；同编号改变任一材料返回冲突，普通重放只读原记录。前弧文字修订仍优先，完整保留卷 ID 等身份元信息，不混回旧结构剧情。

后台复用 `generation_execution_session` 的作品 PG 会话锁、原物理连接检查和清理合同，短事务按 Project→Request 顺序核对执行 UUID 与取消状态。每次模型调用前确认阶段原输入、注册提示/逻辑路由和尝试预占；阶段最多两次逻辑调用，规划执行最多三轮。预占后中断仍消耗尝试，不补造历史、不重置预算；第三轮之后若只差保存完整规划，仍可重试最终事务而不再调用模型。

已接受阶段不会重新生成。两次调用均中断时允许作者发起一次锁内核查，核查转为待审并停止，不会发出第三次调用。来源变化、损坏记录和预算耗尽均保留原材料与已取得内容。作者停止后，迟到结果不能写入；已完成或已停止的请求只读。删除成果保留回执，重放不能复建；永久删除作品才级联清理请求。

系统提示、模型名、端点 ID、tier、温度和预算按阶段保存，不含凭据。这个快照冻结逻辑路由，不能证明底层端点配置、实际 CPA 上游或 Worker 内部型号固定。阶段次数也不等于 Provider 内部 HTTP 请求恰好两次。

Beat 每 30 秒有界补投 pending 或 300 秒无检查点的 running 原请求；每个模型阶段上限 240 秒。过期只作发现条件，实际作品锁取得后才核查和接管。最终保存回应丢失时不另开会话写失败，先读原回执。

## 作者入口与接口

桌面、移动弧面板均可填写创作材料、创建章草稿、恢复/停止原任务、查看全部已接受章纲及失败原输出、下载完整记录。发送前在 sessionStorage 暂存完整原请求；POST 成功后还要读取持久详情，逐字段核对原材料才清除待确认状态。后来编辑的草稿不被旧回执覆盖；未知结果保留原 UUID，损坏暂存不被覆盖。

5 秒轮询仅读轻量状态；原作者材料、来源和阶段全文按需加载。完成回执只附简短标题/进度，避免轮询反复传输长设定。历史使用稳定游标，处理同一时间戳的多条请求。

新前缀 `/api/projects/{project_id}/arc-plans` 提供来源、提交、状态、分页历史、完整详情、resume 和 cancel。原 `/api/arc/{project_id}/start` 与 `next-arc` 转入同一持久服务，返回 202；缺固定请求或来源返回 428。旧外部调用者须升级，不再等待一次 HTTP 返回完整弧。
