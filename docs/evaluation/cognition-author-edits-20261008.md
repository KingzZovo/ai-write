## 中文编辑依据与变化

旧结构只有“得知”和“仍不知”。“沈青以为父亲已经读了信，却又怀疑回信是陈川代写的”无法分别保存误信和怀疑，历史提示也把它们显示为普通认知。这会让写作模型误把人物的认识当作故事事实。

现在分别保存 `learns`、`still_unknown`、`believes`、`suspects`，每条只有一种认知类型和连续逐字依据。提示显示“当时确信（可能误信）”“当时怀疑”；读者记录只允许正文明确提供的信息，不推测真实读者心理。

使用[此前保存的两章 CPA 样例](cognition-history-20261007/samples.json)离线回放，由 Codex 按[中文编辑标准](CHINESE_FICTION_EDITORIAL_STANDARD.md)明确补入第一章沈青的怀疑：

| 原文建立的状态 | 本轮处理 |
| --- | --- |
| 陈川说车坏了，沈青觉得他在找借口，却没有证据 | 为沈青补 `suspects`，不把车坏或陈川撒谎定为事实 |
| 第一章父亲已收到通知，沈青尚不知道 | 保留当章未知及读者信息差 |
| 第二章沈青看到签收日期，知道通知早到了 | 保留后章得知，不用旧未知否定新认识 |
| 车究竟坏没坏，她仍拿不准 | 保留不确定性，不因车灯亮就推断车况 |

回放走实际保存、作者校订、历史读取和提示渲染函数，保留全部原句与章节顺序，没有擅自指认是谁把通知放进抽屉。判断沿用已读《阿Ｑ正傳》中人物自我解释与客观真相的区分，出处和阅读范围见中文编辑标准；没有新增互联网检索，也没有套用经典小说的措辞。这是 Codex 的编辑式核对，不是真人作者盲评；它证明材料按决定传递，不能证明新小说写得更好。

## 工作流与数据合同

- 桌面记忆中心与移动工具共用校订器，可增改删条目；保存空校订明确表示本章不记录认知变化。完整保存稿用于选择原句。
- `cognition_revisions` 在应用层只追加作者决定、完整校订、旧模型快照、前一决定、来源凭据、原版本及已验证登录账号。原模型 `changes_json` 保留供对照。
- 校订和恢复自动均沿用 `cognition_requests` 的固定请求。作品、请求、章节来源及当前记录按既有锁序核对，同一事务提交；重放返回原回执，不同请求不能越过原版本。
- 保存决定换执行周期并清除旧令牌。作者模式不被入队、周期恢复、历史补提取或普通重试撤销；迟到成功、异常与格式修复不能覆盖校订。
- 恢复自动是明确作者操作：有效原模型结果可复用，包括 `[]`；否则换新周期进入已有持久任务。历史保留。
- 有效认知统一验证决定、项目/章节/记录归属、完整来源和逐字原句。坏决定不回退模型；同稿读取期间发生校订，也须重建上下文。
- 浏览器按作品和章节保留草稿、原版本及未知请求；回执仅清理与原提交完全一致的草稿，后来输入保留。来源变化后须对照当前记录再采用旧草稿；本地存储失败时提示复制页面内输入。
- 删章保留历史和回执，永久删作品级联清理。已删章历史可按原章节 ID 从 API 读取，当前列表尚无已删章历史浏览入口。

API 根路径为 `/api/projects/{project_id}/cognition`：

| 入口 | 行为 |
| --- | --- |
| `GET /chapters/{id}?include_source=true` | 按需返回完整保存稿、当前认知及原模型结果 |
| `POST /chapters/{id}/edit` | `request_id/source_hash/version/changes`，保存完整校订 |
| `POST /chapters/{id}/restore-auto` | `request_id/source_hash/version`，明确恢复自动 |
| `GET /chapters/{id}/revisions` | 分页历史、模型快照、账号、时间及当前来源匹配状态 |

迁移仅更新 prompt 和 schema 都精确等于旧默认的认知资产，自定义内容与路由保留；带类型读取后比较 JSON，避免 PostgreSQL `json` 普通等号问题。有作者历史时降级迁移拒绝丢弃历史。SQLite 验证了迁移语义和删除级联，真实 PG 仍未验证。
