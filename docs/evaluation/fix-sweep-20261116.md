# 收口批次:停整本书的软失败、角色位置四处失败、数字约束贴身化(2026-11-16)

这一批只做三件事:**不再让一次软失败停住整本书**、**把 HEAD 自带的 4 项失败测试全修掉**、
**把大纲已定的金额从系统提示挪到生成旁边**。

## 1. 认知提取软失败不再停整本书

### 问题

实测三次(11-14 / 11-16):某章认知提取连续 3 次判"依据无法在正文逐字定位"
→ 该章 `cognition` 落成 `skipped` → `cognition_reader` 判定上一章未就绪
→ **之后每一章都被 `character_cognition_not_ready` 拦住**,补跑提取也没用。
代价:整本书停在一次纯软失败上,而下一章的上下文里本来就有上一章完整正文。

### 做法

新增开关 `ALLOW_COGNITION_DEGRADED_CONTINUATION`,**默认 False(维持现状:未就绪即阻断)**。
打开后([cognition_reader.py](/root/ai-write/backend/app/services/cognition_reader.py:96)):

- 记录缺失、或状态不是 `completed` → 该章按"无认知变化"计入,并 `warning` 记录章节与原因;
- **只降级这一类**:凭据不符、作者决定被改这类真实损坏仍然照旧抛错
  (条件里要求 `status != 'completed'` 才走降级通道)。

长链探针显式打开它(产品默认不变),否则任何一次提取软失败都会让测量作废。

新增 [tests/test_cognition_degraded_continuation.py](/root/ai-write/backend/tests/test_cognition_degraded_continuation.py:1) 8 项:
默认阻断(缺失 / 未完成)、打开后降级、`completed` 不受影响、
**凭据不符即使打开也必须抛错**。

## 2. HEAD 自带的 4 项失败测试全修

`tests/test_character_location_context.py` 这 4 项从 HEAD `854f9b9` 起就一直红着。
逐项诊断后的真实原因:

| 测试 | 真实原因 | 处置 |
|---|---|---|
| `..._pg_and_graph_places_remain_observations_not_a_store_choice` | 同章两个地点(PG 一个、图谱一个)会被挑一个写进 `card.location` | 把折叠出的 `location_state_records` **接进人物卡**(原先只接了 `apply_locations`) |
| `..._multiple_state_rows_preserve_all_same_chapter_places[graph]` | 同上:图谱两条同章状态只保留第一条 | 同上 |
| `..._multiple_state_rows_preserve_all_same_chapter_places[pg]` | `character_states` 上有 `UniqueConstraint(project_id, character_id, chapter_start)`,**同章第二行直接 IntegrityError** | 唯一键改为"**来源 + 内容摘要**"去重;新增迁移 `a1001959`;投影侧写入 `status_digest` |
| `..._same_named_pg_people_with_only_state_positions_require_identity_check` | 同名两张卡、只有状态位置时**不报错**,会按名字把状态分配给两张卡 | 装配时对同名多卡直接查状态:带位置即抛 `ambiguous_character_location_owner` → 对外是 `character_graph_context_unavailable` |

### 为什么唯一键要换成内容摘要

旧键假定"一个角色一章只有一条状态"。实测这站不住:同一章可以有两处位置(先船舱后甲板),
PG 与图谱还可能各给一条。新键
`(project_id, character_id, source_chapter_id, status_digest)`:
同一来源重放仍然幂等(摘要不变即命中),同章两条不同观测可以共存;
历史行 `status_digest` 为空,不受约束(PostgreSQL 允许多个 NULL)。

迁移 [a1001959](/root/ai-write/backend/alembic/versions/a1001959_character_states_multi_observation.py:1)
(`down_revision = a1001956`,当前**单一 head**)。降级会先删掉同章重复行再恢复旧键,
避免降级时因数据冲突失败。

投影侧([entity_tasks.py](/root/ai-write/backend/app/tasks/entity_tasks.py:1087))改为写入
`status_digest = sha256(规范化 status_json)`,冲突目标同步改名。

**注意**:这四处改动**没有改任何既有迁移文件**;`a1001959` 尚未在任何真实库执行。

## 3. 大纲已定的金额挪到生成旁边

上一批的证据:同一个数字放进约 1 万字的系统提示里,模型会无视(第 7 章自造 840、
第 8 章却按大纲收 820);而"拆段 + 续写"之所以有效,机制是把约束**重新送到眼前**。

所以这次把 `numeric_pins` 的清单**同时**注入写手的 user content
([scene_orchestrator.py](/root/ai-write/backend/app/services/scene_orchestrator.py:444)):

```
【本章写到的金额必须与大纲一致】
[CH-8] 校服交了,周芸收下八百二
写到这些名目时只能用上面的数;不要自己另算一套总数,也不要把它们改成别的数目。
```

没有可注入金额时,这块不出现(user content 与改动前逐字一致)。
新增 2 项测试:`test_numeric_pins.py` 里验证注入存在与缺失时的行为。

## 5. 24 章验证链

`--chapters 24 --limit 24`,`gemini-3.1-pro`,默认配置(1 场/章 + 篇幅兜底)。

| 指标 | 结果 |
|---|---|
| 章节 `status: ok` | **24/24** |
| 错误章 | **0** |
| 质检门 | passed 21 / blocked 3 |
| 认知记录 | completed **21** / skipped **3** |
| 实体投影 | ok 2 / missing 22 —— **见下** |

### 5.1 关键验证:降级放行确实让整本书走完了

3 章认知提取软失败(`skipped`),**链条没有停**——这正是本批第 1 项要的结果。
换成改动前,第一次 `skipped` 就会让第 2 章起全部 `character_cognition_not_ready`,
24 章根本写不完。日志里 164 条 `cognition_degraded_continuation` 记录可以逐章追溯。
**代价**:那 3 章的人物认知变化没有进入后续上下文;后续章节的上下文里仍有上一章完整正文,
但再往后的历史会缺这一层。所以这是"用一层台账换整本书能写完",不是无损修复。

### 5.2 22 章投影缺失是**环境不一致**,不是逻辑错误

```
entity_error: ProgrammingError: UndefinedColumnError:
  column "status_digest" of relation "character_states" does not exist
```

评估库是 `Base.metadata.create_all` 直接建的,**没有走迁移**,所以缺 `a1001959` 新加的列;
投影侧已经按新口径写 `status_digest`,于是整批插入失败。
这反过来证明迁移是必需的、而且接线是对的(库里没列就立刻报错,不会静默写错)。

已把 `a1001959` 的 DDL 手工应用到**评估库**(不碰任何用户库),并在
`verify-20261116b`(10 章)复跑验证:

| 指标 | 结果 |
|---|---|
| 章节 `status` | ok **7** / truncated 2 / refusal 1(后两类是质量门按设计拦下的坏输出) |
| **实体投影(仅看写成的章)** | **7/7 ok** |
| 认知记录 | 7/7 completed(与写成章一一对应) |

也就是说:22 章缺投影确实只是"库里少了新列",补上 DDL 后投影逐章恢复。
`truncated` / `refusal` 那 3 章没有投影是正确的——它们本来就没被当成成品落库。
