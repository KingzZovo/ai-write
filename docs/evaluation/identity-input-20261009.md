# 人物身份输入与称谓观察（2026-10-09）

本批修复当前作者书纲被旧姓名结构覆盖，以及把相同称谓下的不同姓名直接当作人物替换的行为。只完成源码与离线核对；没有调用 CPA、连接运行服务、应用迁移、部署或更换默认模型。

## 实际行为

- `fact_contract` 在提取姓名之前应用 `outline_for_generation`。当前作者文字优先，旧结构仍完整存储；同一称谓的多个姓名全部保留，不按字段顺序选出唯一人物。
- 只读取当前确认书纲，保持确认、版本、创建时间与 ID 的既有选择规则。无确认书纲与已保存行中的 SQL/JSON null 分开处理；坏类型、解析失败、不可用标记、空当前文字及元数据壳明确停止，不读旧确认稿补救。
- 当前确认书纲存在时，人物档案不再补造书纲没有明确的角色槽位。这也覆盖作者直接以纯文字或新结构替换原书纲、没有 `_author_text_revision` 的情况。已登记姓名完整保留；没有确认书纲时，唯一且明确的档案标签仍作为带来源的提示。
- 书纲及人物读取采用列值与 `autoflush=False`，不提交待保存内容，也不通过 ORM 刷新丢掉同一会话中的未保存修改。报告保留所选书纲 ID、版本、完整原载荷摘要和角色声明来源。
- 正文中的称谓/姓名差异作为需要上下文核对的 `warning`。保留旧 `role_name_drift` 代码和 `canonical/observed` 字段以兼容历史报告，增加 `identity_established=false`、正文摘要和 `editorial_status=needs_author_review`。没有发现字面差异也不表示人物或文学质量合格。
- 实际后台任务继续把报告与完整正文版本同事务保存；源读取失败仍停止或保存待审稿。没有改写或删除原稿，也没有撤销书纲结构检查器的独立合同。
- 共用 `has_meaningful_outline_content` 原先会把空白字符串落入后面的非空值分支；现在明确排除空白，仍允许后续字段提供有效内容。

## 作者场景核对

“主角：林禾”不能被旧 `entity_registry` 中的林照覆盖。作者删除师承安排后，旧导师档案不能自行恢复该安排。正文写到沈听澜和另一位导师陈川，或者写到不同人物各自的父亲，字面检测没有证明它们指向同一个人，因此不能据此硬拦稿件。

这些观察仍需回到人物关系、叙述视角和具体原句判断。遵循既有[中文小说编辑标准](CHINESE_FICTION_EDITORIAL_STANDARD.md)：人物的选择和前后承接不能由一个名称表或模型评分代替。本轮没有新模型稿、联网参照或真人盲评；既有 Gemini 实稿未通过中文编辑验收的结论保持。
