# 移动端正文保存与后台任务交接

日期：2026-10-09。代码与离线检查完成；未部署。全项目目标仍未完成。

## 问题与改动

移动端原来已经发送 `expected_content_text`，并非完全没有旧稿比较；缺口在于使用旧章节更新返回值、未保存稿依赖单个组件，以及后台任务的 `progress_text/result_text` 直接回填当前编辑区。后端进度里包含操作说明，任务完成也不能证明当前章保存了同样的正文。

- 编辑器复用 `useChapterDraft`、`ChapterDraftSession`、`ChapterSaveStatus` 与完整 `/content` 回执。切章保留未确认稿；请求期间可继续输入；失败后全文核对。浏览器暂存失败可下载备份，暂存不等于服务端保存。
- 删除移动端独立 PUT 和任务结果回填。候选全文、操作进度、润色候选分别展示；完成后对任务原章节调用保存稿读取。当前作者输入由会话保留，必要时显示全文对照。
- 新观察器一次只读一个任务快照，收到响应后再安排下一轮。切换任务/作品或卸载使旧响应失效；`completed/needs_review/needs_repair/failed/cancelled` 停止轮询，未知状态或读取失败保留提示并等待明确重读。
- 项目、任务列表、大纲就绪和提交响应均核对来源。提交未获完整回执时先刷新任务，不自动重提；同一组件中的重复点击被同步令牌拦截。这不等于后端提供持久幂等请求。
- 书纲生成不再依赖某章正文已加载。分卷候选传递所选章节所在卷号；仅有一卷时可明确选定，多卷未选择时禁用。已有大纲的查看按钮返回目录并展开。`GeneratePanel` 接收调用者忙碌、正文和卷目标状态。
- 首轮复核确认异步 `outline_volume` 本来就不保存正式卷纲。界面现明确候选性质，保留全文查看、复制和下载；本批没有增加正式采用卷纲的流程。

## 后端返回合同

`POST /api/generate/async`、任务详情和作品任务列表统一提供：

```json
{
  "task_id": "任务ID",
  "project_id": "作品ID",
  "task_type": "chapter",
  "chapter_id": "原请求章节ID或null",
  "volume_idx": null,
  "status": "pending"
}
```

`chapter_id` 和 `volume_idx` 来自持久任务参数；未知或损坏的值保留为 null，不补猜。卷号只表示任务记录的请求目标，不是对执行时大纲内容或章序的来源证明。详情仍返回完整候选和进度，列表不返回任意参数或正文候选。

作品列表新增 `active_only=true`。活动任务不受最近完成历史的窗口遮挡；取消标记按有效状态过滤。筛选查询按时间/ID游标每批最多128条，覆盖同时间戳与无日期历史；SQL只返回末尾200字符的进度，不读取完整候选。真实 PG 的查询成本、并发与索引效果仍需验证。

这批前端需要同批后端返回新增字段；不支持拿缺少来源字段的旧响应假定为有效回执。旧 `/chapters/{id}` 兼容写接口仍保留可选前提，不能宣称所有历史正文写入口已统一。
