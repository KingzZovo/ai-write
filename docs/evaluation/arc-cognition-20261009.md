# 人物认知进入弧规划（2026-10-09）

本批把有正文来源的人物认知接入弧规划的实际调用、修复和持久恢复。完成源码及离线验证；没有运行服务、调用 CPA、切换默认模型或部署。

## 实际变化

- 新规划来源 `version=5`，保留 `book_context=2`、`character_context=1`，增加 `cognition_context=1`。按真实全书末尾边界读取全部已完成章，保存完整认知历史及每章来源、决定和原句证明摘要。有效空决定也有覆盖凭据；缺提取、坏作者指针或失效正文不能变成空账本。
- 新 journal `version=2` 保留基础原输入，并记录认知来源与召回查询基础。每个模型尝试各自保存所选完整原句、逻辑嵌入空间、排名事件及实际输入；恢复保留已接受阶段及原尝试，不补造旧来源。
- 查询使用完整作者任务、前弧、已接受规划及本轮失败原稿；参考人物目录仍进入基础材料，但不会让所有目录人物都成为本轮必须召回的人物。短历史完整传递，长历史沿用现有事务外语义召回和事件分组。
- 单次认知材料预算为 12,000 字符，以完整事实及原句为单位。必要记录超出容量时，在嵌入和模型调用前停止；保留完整原件供核对。旧未知与最新同人物记录同行，提示保留误信、怀疑和读者认知的区别，不能把当年的未知直接当作现在未知。
- 检索前结束读取事务；选择返回后，重新在短事务内核对执行者、取消、来源及原阶段，再提交选择和尝试预占。每阶段最多两次、规划执行最多三轮；检索失败不增加模型尝试，也不能买到第四轮执行。
- 前端增加完整认知原件及逐次实际输入的展开审阅，长文展开后才挂载；进度和历史列表不附认知全文或阶段全文。坏记录仍能下载完整原件。
- 旧来源 v1–v4、旧 journal v1 继续按原材料审阅；执行时与当前新版来源不一致即停止，不给旧请求补造认知依据。

新增模块分别拥有来源读取、持久材料校验/投影和事务外选择。共享写作/修订/评审的字符串检索接口保持兼容；`CognitionLedger.snapshot_hash` 的计算内容不变，新增可审阅的完整 `snapshot`。

## 具体问题与修复

初始实际路径复现两项缺口：认知未进入弧规划 Prompt、已完成章缺认知提取却仍可规划。接线过程中又复现 SQLite UUID 绑定、来源预览触发未保存编辑 autoflush、第三轮检索失败仍提示可恢复的问题，均补了回归用例。

补查发现，损坏记录中的超长认知选择可能在详情/恢复校验时抛出 `RequiredContextUnavailable`，使原件无法正常读取。先复现失败，再将无法复现的持久选择归为记录损坏：详情仍返回完整原件，执行进入待核对且不新增模型调用或重置预算。

## 500 万字规模与耗时

实际走预览、提交及 11 章的 4 个规划阶段。样例包含 **1006 章、5,386,409 正文字符、5032 条认知变化**，另有 200 个无关参考人物。

| 检查 | 结果 |
|---|---|
| 首次完整正文核对 | 6 批，每批最多 200 章 |
| 后续提交及全部规划阶段 | 0 正文字符回读 |
| 四次历史事件嵌入数量 | 5032、0、0、0 |
| 早期未知与后章获知 | 每个实际阶段均保留完整原句 |
| 无关参考人物 | 进入基础材料，不进入认知召回查询 |
| 优化后预览 / 提交及规划 | 1.86 / 53.47 秒 |
| 四次选择耗时 | 5.07、4.88、4.64、7.86 秒 |

初次未剖析测量的规划为 69.31 秒。针对这个实际疑问做一次 cProfile，定位到本地 Qdrant 的 ID 过滤及重复解析同一完整认知原件；剖析自身增加耗时，该次 162.83 秒不能与普通运行直接比较。

本批仅复用一次同步 journal 校验中的不可变观察值，并消除已核对凭据的重复解析；每个执行边界仍重新读取和校验当前材料，没有跨请求缓存可变认知载荷。修改后普通规模运行约 53.47 秒。这是单次本机 SQLite、本地 Qdrant、确定性假向量测量，不代表线上 PG/Qdrant 性能，也不证明中文语义召回准确。
