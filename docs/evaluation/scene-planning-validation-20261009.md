## 工程修复

`scene_plan_contract.py`独立负责数据合同，编排继续兼容导出原 SceneBrief。文字字段拒绝布尔/数组/对象冒充，brief必须非空；无标题只补位置标签，不编场景内容。台账允许完整JSON对象/数组，保留数值、未知值与嵌套内容；单独布尔或全空容器不能当已填写。time_delta保留旧数值表达，不自行添加单位。旧别名保留，存在相互不一致的多份内容须修复，不随意择一。

七类条件字段均在有内容时传给writer：action_budget、inference_ledger、evidence_strength、npc_disclosure_budget、actor_boundary、foreshadow_seed、register_guard。静场仍可省略。校验只查可用的数据形状，不判断某个动机是否可信，也不自动证实规划新增的事实。

每场target_words必须为1–6000的JSON整数，缺失/错误不补1000或夹值。全章声明预算在原目标85%–115%内。例如3000字目标下，8×900不能直接放行，重规划后可保留八次事件并各分375字；30,000字可以20×1500。超过现有20×6000单章技术容量在调用前失败，不降低请求目标；单书设计下限仍是500万字以上。这不保证模型实际生成长度，也不以字数证明剧情完整。

编排拥有最多两轮逻辑调用，Registry内层重试关闭；每轮均使用配置超时与硬上限的较小值，修复轮不再擅自扩大为240秒。修复携带原作者要求、完整背景、完整旧输出及具体缺陷，允许合并场数或重新分配详略，要求保留原定中间事件，同时纠正旧规划擅改的事实。已有无效规划即使后一次请求失败也不能改成模板成功；未取得可用交付才保留原显式应急开关。

所有Registry结构化调用先拒绝显式length/max_tokens/filter/tool等结束，沿用原一次修复上限；分场额外使用严格JSON，拒绝截断、重复键、NaN/无限数和指数溢出，不让json_repair补成“完整规划”。其他任务仍保持旧本地JSON修复默认。缺finish_reason沿用未知兼容，不能当明确正常结束证明。失败回执新增validation_stage，防止错误标记在task validator前被拒绝后丢掉已知规划状态。逻辑两轮不等于两个HTTP请求，Provider原重试/降级仍存在。

附带修复旧弧大纲的失败合同：generate_arc_outline收到parse_error/_parse_error时返回不可用，start与next-arc不再继续保存空弧纲。本批未声称解决全部弧纲字段/章数完整性问题。
