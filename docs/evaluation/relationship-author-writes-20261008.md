# 作者关系写入、历史与重试修复

2026-10-08，基于 `364fb7f`，分支 `fix/2026-10-06-pipeline-safety`。本轮修改本地源码、测试和文档，没有连接运行服务、调用CPA模型、执行真实迁移或部署。

## 问题与修复范围

旧关系编辑写入图谱的标签、备注和情感倾向没有进入PG投影；作者改过类型的边仍带原正文来源，会被误当成未改过的抽取。章节重建又可能覆盖或恢复这些修改、删除。旧请求没有内容绑定和版本校验，重试可覆盖后来的作者决定。类型改名重建PG行还会丢失稳定ID及分卷演变记录。

最初两个API用例分别复现了来源误标和旧请求覆盖，均先失败，日志：`/tmp/aiwrite-relationship-author-20261008-before.log`。随后升级API测试夹具，使用真实SQLite提交与事务式图谱替身；不恢复旧的无版本写入协议来通过测试。

## 当前行为

1. **版本和固定请求。** 新增`GET /api/projects/{project_id}/neo4j-settings/relationships/record`，返回完整图谱组、版本、字段及混合值提示。POST需要`Idempotency-Key`；PUT/DELETE还需要`If-Match`。修改请求不能为空，未知字段拒绝。版本变化、目标关系冲突、请求编号重用均明确拒绝。
2. **作者设定独立。** 作者修改后标记`origin=author`，移除正文/大纲抽取来源字段，保留原依据；完整类型、标签、备注及情感进入“作者关系设定”，不会被标成某章已发生事实。完整来源记录和未编辑的混合字段继续保留，不用PG规范关系词替换原图谱说明。
3. **旧抽取不会撤销作者决定。** `RelationshipSuppression`绑定项目、人物方向、来源ID、来源版本及原始关系类型，正文和大纲重放均核对。后续章节或新的大纲版本仍可登记新的关系变化。无来源的旧写入遇到已归属关系/抑制记录时拒绝；旧去重只处理无来源、非作者记录。
4. **历史和稳定ID。** 改类型沿用`projection_id`与PG行，保留`evolution_json`、卷范围、创建时间。图谱回执保存原边及完整PG原记录，删除前也保存分卷历史。历史已有持久留存，尚未新增操作历史浏览界面；`author_id`在此是关系登记标识，不是登录账号审计。
5. **提交确认与恢复。** 图谱决定和回执同事务提交，PG确认提交后才返回`status=saved`及原请求编号。PG失败、响应丢失和确认丢失保留回执，60秒周期任务在总预算内恢复当前图谱值；不执行历史patch。图谱已提交后出现PG冲突仍返回待同步，不能当作明确拒绝让界面丢掉原请求。
6. **共用锁与人物删除。** 作者关系、正文投影/失效、大纲提取、旧关系写入和人物删除共用项目图谱锁。人物删除尚待清理时暂停相关关系写入/投影，避免把旧PG身份及关系历史挂到重新出现的人物上。PG物化锁继续覆盖读取与提交。
7. **界面保留作者输入。** 编辑器展示完整来源，未核对正文的抽取仅称登记记录。未知结果固定原操作、内容、版本和请求编号，切换编辑/删除仍先确认原操作；同一关系的两个面板共用草稿。切换作品、较慢读取及迟到保存响应不会清掉较新输入；确认完成后不再用迟到来源重建旧草稿。
8. **批量同步成本。** 复用分批锁定的ID/关系键完成所有权及占用核对，仅类型实际变化时UPDATE。1005条未变化的作者关系，从3021次SQL执行降到6次；标签等更新不会被统计为新增关系。此为SQLite执行次数验证，不是500万字作品的实际延迟或吞吐验收。

已有路由前缀和导入名保留，但写入协议增加必需请求头，前后端需要配套发布。首次使用时初始化三个Neo4j唯一约束：`relationship_project_guard`、`relationship_write_id`、`relationship_suppression_key`。本轮没有新增SQL迁移。

## 对中文小说连续性的意义

测试中，作者将“同伴”改为“敌对（仍需共同查案）”，并补充“不能再把二人的配合写成亲密无间”。这份设定现在完整进入写作材料，且与已核对的前文事实分开。

按[中文作者/编辑标准](CHINESE_FICTION_EDITORIAL_STANDARD.md)，下一场应从人物为什么还要合作、愿意交出什么信息、如何回避对方等具体行动和对白上承接关系。不能把关系标签在正文复述一遍就认定连贯；也不能凭新增备注编造一段前文从未写出的翻脸经历。这里是对测试材料的编辑说明，不是新的模型样稿或文学验收结果。

本机CPA已有`gemini-3.1-pro`的核查记录。本轮没有切换默认模型。此前同题样稿中，Gemini出现限知视角越界而自动评审给满分；另一模型的候选也存在动作目的与交接路径含混。具体证据见[完整章节对照](context-guidance-20261007/REVIEW.md)和[CPA上游诊断](cpa-gemini-routes-20261006/REVIEW.md)。后续需在固定实际线路、相同资料和约束下比较完整及连续章节，用正文证据、人物口吻、关键场面、节奏、衔接和编辑修改量判断，不能由模型自评分代替。
