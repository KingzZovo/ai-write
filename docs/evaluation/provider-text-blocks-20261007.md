# 供应商多内容块正文完整提取

## 实际问题与修复

AnthropicProvider.generate 原先只读取 resp.content[0].text。思考块在前会取不到文本，多个正文块则只返回第一块，尽管结束原因可能是正常完成。后续长度或标点检查不能发现所有这种提取丢失。

现按响应顺序拼接全部明确type=text块，保持块内换行、空格和字符，不额外添加分隔符。思考、隐藏思考、工具及无类型块不进入正文，即使它们带有text属性。空文本块允许；明确正文块的text不是字符串时抛固定invalid_provider_text_block，不将前面的部分正文返回为成功，也不把异常对象字符串化。usage和finish_reason继续保留。

只改Anthropic普通响应提取；流式接口继续使用SDK的text_stream。OpenAI/CPA模型选择与配置未改变。

- 新增8项覆盖思考在前、多个正文块精确拼接、工具块带text排除、空/无类型/无正文、坏正文块拒绝部分成功、空块后的正文和截断元数据保留。
