# 500万字实体读取与物化基准（2026-10-06）

## 实测发现与修复

使用独立测试schema和独立Neo4j作品ID生成2000章，每章2500个合成汉字，总计500万字。先测每章1条状态，再测每章5条状态（20名人物、10000条状态变化）。调用实际 `verified_character_states`、`verified_world_snapshot` 和严格PG物化函数，不调用模型。合成字符不是小说质量样本。

加密样本确认长篇故障：旧物化一次拼接所有状态参数，超过asyncpg的32767参数限制，抛 `InterfaceError`。此时读取能成功，但历史记忆重建会失败。

- 新 `entity_bulk.upsert_projection_rows` 将关系、地点、组织、伏笔、组织成员、人物位置、人物状态的写入限制在最多500行/批，并按表列数保留参数余量；调用方仍统一提交事务，批次不自行commit。
- 冲突更新只在字段确实变化时执行。JSON用JSONB语义比较，避免相同内容或仅键顺序差异的重复写入；null使用 `IS DISTINCT FROM` 正确比较。
- 位置/状态/成员查询去重名称参数，伏笔删除也按500个ID分批，防止重复/历史数量放大参数列表。
- 计数反映实际写入行；重复重建不再更新所有相同状态，减少不必要的WAL和行版本。

最后修改最新章正文，不运行后台清理，再核对两个读取路径都排除该章旧来源；其余有效字段与预先计算的逐章状态完全一致。

原始数据：`entity-context-5m-baseline-20261006.json`、`entity-context-5m-dense-before-20261006.json`、`entity-context-5m-dense-after-20261006.json`。最终脚本额外验证空读模型恢复和重复写入；修复前脚本测量时PG已预置状态，因此写入前后RSS/耗时不是严格单变量比较，不据此宣称固定百分比加速。

## 复现与测试

脚本 `backend/scripts/benchmark_entity_context.py` 只接受显式localhost测试库和测试Neo4j端口，使用独立随机schema/作品ID，在finally中清理；不接触生产。脚本参数为 `--chapters 2000 --chars 2500 --characters 20 --states-per-chapter 5 --materialize --output <结果文件>`；需提供 `PIPELINE_TEST_DATABASE_URL` 和 `ENTITY_TEST_NEO4J_URI`，以及 `PYTHONPATH=.`。结束后测试库 `entity_bench_%` schema计数为0。

47项相关测试通过。新4项真实PG测试覆盖5000行写入、更新来源/结束章号、重复和JSON键顺序变化不写入、后续批次FK失败时整体回滚、跨批冲突DO NOTHING、伏笔主键更新。最后补JSON键顺序断言随全量运行；4文件AST通过。

按shadow-mind的无可信只读隔离回退规则，专项后冻结实现，分别做本地正确性与架构复核。核对批次不自行提交、JSON/null比较、旧冲突更新字段保持、失败仍由严格worker重放；基准脚本清理失败时仍尝试释放连接和删除测试schema。

最终后端全量 **1781 passed, 4 warnings, 264.64秒，无跳过**；日志 `/tmp/aiwrite-entity-bulk-full.log`。4项warnings为既有JWT短密钥2项、Qdrant版本探测2项。全量通过后仅更新文档，未改实现。

## 限制与后续

- 仅本机单进程、单作品、有限字段变化的合成基准；没有模拟多用户并发、复杂人物关系、生产磁盘/网络或中文小说实际语义。不能据此保证生产SLA。
- 物化仍读取作品级图快照；零更新降低写入量，但重复扫描仍约5秒。受影响实体的增量物化仍是优化方向。
- 字段来源与大数据参数限制已实测，不代表无来源生产历史记忆已重建，也不代表正文、细纲、提示词或Gemini达到文学验收标准。
- 本批未部署，生产备份恢复、迁移、真实工作流和中文小说样稿仍待验收。
