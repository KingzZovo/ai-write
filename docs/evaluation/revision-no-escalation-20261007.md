# 定点改写失败不再自动扩大为整章重写

## 行为

原流式和后台自动评审链在定点调用抛错、无定位结果、空/退化输出时均进入完整章节重写。一次定位或供应商故障不能证明应该重写整章，尤其会放大未经证实的评审意见。

现在默认定点模式遇到上述情况即跳出修订循环，保留本轮当前候选与已有评审，不增加整章重写调用；成功局部修订继续原有重新评审流程。SSE发出 revise_skipped / targeted_revision_unapplied，后台任务params_json持久记录同名停止原因。最终是否通过继续由绑定确切正文的ChapterAcceptance判断，停止不等于合格。

前端对应显示“局部修订未完成，已保留当前候选”及审阅提示，未知停止原因改为中性提示。只有明确score_above_threshold才显示评分达标。

显式配置 TARGETED_REVISION_ENABLED=0 的完整重写模式保留；本批没有声称该模式已经完成全部证据门槛审计。无引文的全章结构问题/缺失事件仍保留评审意见，由后续规划或作者审阅处理，不直接丢掉。

## 验证

- 后端改写相关72项加验收22项，共94 passed。
- 新增10项从当前生产模块AST提取实际定点分支执行，分别覆盖SSE/worker的无定位、无有效替换、抛错、成功和显式关闭。模型调用使用替身，验证失败不落入整章调用分支、后台原因提交及SSE事件。
- 这些是生产分支执行测试，不是完整ASGI/Celery/数据库集成。完整运行仍需真实环境验收。
- 前端generationEvents 19项通过、tsc --noEmit通过；4文件AST、git diff --check通过。
- 按shadow-mind无可靠只读隔离回退，冻结代码后本地核对循环break/continue、保存与验收、事件显示和显式全章模式。复核发现前端默认把未知停止原因映射为评分达标，已修正并补测。

## 剩余边界

本批只阻止定点失败导致的自动范围升级。既有质量门禁、最终候选保存、其他后处理和作者主动重写仍有独立路径；未声称所有后处理均停止或未经运行验证即可保证最终数据库字节不变。后台停止原因目前在任务元数据，独立恢复/手动处理界面仍需完善。

未进行新的真实模型实写、长篇中文编辑审读、完整浏览器或迁移部署。模型低分不等于文学不合格，高分也不证明可交付；实际文学判断继续依照CHINESE_FICTION_EDITORIAL_STANDARD.md并保留具体原文证据。
