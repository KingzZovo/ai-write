# 作者弧材料直达实际写作输入

2026-10-09，基于 `f954ffd`，仓库 `/root/ai-write`。本批补齐作者原始弧材料到实际写作器的传递链，尚未部署，没有通过CPA生成新的样稿；附有明确标注的离线编辑示范。

## 触发问题与文学意义

上一批已保留原始开场材料，并将作者进展/下一步方向接入 ContextPack。继续检查后发现，实际写作器没有读取 `_arc.input_material`；这些原话只在专用 `chapter-brief` 接口中出现。常规章节生成依赖整理后的章纲，模型若改写或漏掉原要求，写作阶段未必还能看到作者原话。

这与[既有 Gemini 实稿审读](editorial-planning-20261006/REVIEW.md)中的数额漂移、缝纫被改成发薪等问题直接相关。测试以“欠三千、交两千、余一千”等合成作者材料复现输入遗漏；这不是新生成稿，也不证明补齐输入就能让 Gemini 稳定写对。继续遵守[中文小说编辑标准](CHINESE_FICTION_EDITORIAL_STANDARD.md)，人物选择、道具交接、关键动作和篇章兑现仍须从连续正文核对。

## 最终实现

新增纯投影 `arc_author_material.render_arc_author_source`。实际写作上下文和 API 的当前章 brief 共用它，完整传递作者创作意图、背景、设定及补充材料；不再只依赖模型章纲转述。原存储对象不变，额外描述字段保留为完整 JSON 材料，不补造缺少的背景。

原开场绑定 `_arc.chapter_order` 的原目标 ID，仅进入这一章；章节重排后不会给占用旧编号的章重演开场。已有开场但没有可核对身份时明确停止，要求作者在当前大纲中修订，不按现章号猜配。当前进度的显式方向和前文说明继续使用上一批的身份/时间边界。

作者后来的文字改稿由既有 `outline_for_generation` 决定权威。当前全文替代旧作者材料和旧结构，完整进入必需预算块；`arc_replaces_volume_outline` 避免在可选卷纲块重复注入同一全文。正文提示和 API brief 均验证只出现一次。当前文字稿为空时停止，不能自动启用旧材料。

原始材料字段类型错误不再静默遗漏；有效的当前文字修订也不会重新读入已经损坏的旧材料。必需内容放不下时返回明确预算不足，不截断作者设定或把开场变成可选输入。原始材料以创作意图/设定标注，计划不作为已发生正文事实，作者摘要也不替代正文核查。

`load_arc_writing_context` 返回完整文字及去重标记，`load_arc_writing_material` 保留文字调用兼容。ContextPackBuilder 继续先核对当前卷纲、进度和目标章；新增投影是纯函数，不增加数据库写入或额外历史查询，沿用本弧最多 40 章的读取边界，单书设计下限仍为 500 万字以上。
