# 世界规则的当前来源与作者编辑

2026-10-09，基于 `b9a3c83`，仓库 `/root/ai-write`。本批完成实现、重点检查、两轮冻结本地复核和全目录离线回归；未连接运行服务、调用CPA、切换默认模型或部署。

## 问题与结果

世界规则原本从Neo4j写入，再尽力同步到PostgreSQL；规划、写作和列表却使用PG副本。同步失败后，作者刚修改或删除的规则可能继续进入实际Prompt。PG同步还会按文字重合度覆盖规则，足以把“不得”改成“可以”，或丢掉新增例外。

当前图谱读取和完整投影已由共用服务拥有。弧规划全部阶段、ContextPack实际写作采集、规则列表共用当前值；图谱不可读时明确失败，不回退PG旧值。旧副本不自动清理。`HierarchicalMemory`兼容入口也已接线，但未发现实际外部调用者，不据此增加主链验收范围。

取消按文字相似度覆盖规则，只去掉分类和全文完全相同的重复登记。当前规则的中段、否定、例外和换行完整保留；2101条相近规则用例核对全部条目，必需材料依旧受明确预算保护，不靠截断宣称完整。单书设计下限保持500万字以上。

## 出处与规划恢复

| 来源状态 | 使用与作者工作流 |
|---|---|
| `author` | 作者当前登记的设定；保留节点上的旧提取字段仅作历史参考 |
| `current_outline` | 原提取依据与当前所选完整书纲一致；仍为创作设定，不是正文事件 |
| `registered` | 无可核对提取出处的历史登记，明确标注未知出处，不补造来源 |
| `needs_review` | 已知提取书纲变化、替换、删除、不可用或无法核对；列表保留，自动规划/写作停止，作者核对后可保存为当前设定 |

新提取保存当前书纲完整文字及实际结构投影的材料摘要，避免无关Project计数变动使新记录失效。旧提取仍核对原始摘要，不补造新材料摘要；旧摘要覆盖整个Project/Outline，因此无关项目字段变化也可能使旧记录待核对。坏当前书纲标记不会被文字修订分支掩盖。

新规划 `source_json.version=3` 内嵌 `book_context.version=2`，保存实际完整图谱来源。有效旧version=1/2保持原件与原提示投影；旧请求执行时不补造新出处，也不重置预算。图谱变化后保留原请求待审；暂时读取失败503后可恢复原请求，保留已接受阶段和原尝试计数。

实际ASGI合同已更新到前端fixture，SHA-256：`25c32d3c7d456f199f6796ab8a20fe796662384e8d10d1bf3a909dd1024f8c45`。轻量状态与历史仍不附完整长文本。

## 编辑与并发边界

正式作者创建、编辑和删除先取得Project FOR NO KEY UPDATE锁，既阻挡弧规划最后来源核对的FOR UPDATE，也允许独立PG投影的外键KEY SHARE检查。标准书纲提取已有相同Project锁；规划仍锁全部书纲候选ID及所选全文。旧维护ETL和任意直接图谱改动不在这个互斥保证中。

编辑/删除必须提供原规则版本；缺失428、过期409、原键消失404、无效编号/输入422、图谱写入未确认503。原版本包含真实节点ID，防止删除后同文重建被旧页面写入。原键逐字匹配，支持旧空分类及首尾空白。创建同文规则返回实际ID，重复坏键拒绝；修改、显式合并与删除在单个managed graph transaction内核对实际影响数量。

图谱确认提交与旧PG投影分开：使用同一图谱driver刷新兼容副本，副本失败不会把已确认图谱写入报成失败。当前列表只读取图谱；不能据此声称PG历史已完全清理或跨库恰好一次。

前端编辑稿独立于当前列表，来源冲突或原行消失仍保留全文。重读显示完整当前文字，只有“采用读取版本，保留编辑稿”才更新保存基准；后创建的同文节点不能自动替代旧身份。新增/修改缺完整回执时不关闭输入，重复点击只发送一次；删除结束重新读取实际列表，未确认时不乐观移除。

本批没有新增固定作者写请求、完整编辑历史或关闭/切换标签/刷新后的规则草稿持久化。显式合并沿用旧功能：删除原节点并采用目标节点，因此不能宣称保留了全部历史节点。写作采集当前规则，也不等于整个正文生成运行已冻结全部上游来源。
