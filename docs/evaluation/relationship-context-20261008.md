# 人物关系进入写作上下文的完整性修复

2026-10-08，基于 `53bdd38`，分支 `fix/2026-10-06-pipeline-safety`。本轮修改本地源码、测试和文档，没有访问运行服务、执行真实迁移、部署或调用CPA模型。

## 已确认的问题

旧代码只在人物状态循环中附加关系，因此只有关系、没有状态记录的人物会丢失关系。关系字典以对方姓名为键，把“同事＋朋友”压成一项；档案中的旧关系又可能通过 `setdefault` 挡住正文中的新记录。卡片只选中关系的目标人物时，入向关系也不会保留。

图谱关系查询先按派生的 `chapter_end` 排除早章记录，再核对来源。如果关闭关系的后章已经改稿、删除或不再有效，早章关系仍被排除。查询还存在全局2000条上限。图谱读取失败时，主生成会继续使用旧档案；分层记忆把有向关系显示为双向。

以上8项用例均先失败。冻结复核另发现：关系使用档案别名时会新增假的独立人物卡，选中正式姓名后又丢掉别名关系；别名与另一位人物的正式姓名相同还会误选人物。随后补充的5项用例也先失败。

## 最终行为与边界

- 新增 `relationship_context.py`，在 `filter_current_entity_rows` 核对来源之后重建有效关系。保存章节ID、来源摘要、全书章号、事件类别及完整关系描述。
- 依照现有图谱写入契约，`new` 的不同类型并存，重复同类型保留较晚来源；`change` 替换同一有向人物对的较早类型，同章记录并存，反向记录独立。不会再因失效后章留下的派生结束日期隐藏有效早章关系。
- `ContextPack.relationship_records` 独立于人物状态及档案关系字典。关系双方没有状态也能进入候选；卡片选择后保留与任一选中人物相关的记录，并将另一端姓名纳入名册。
- 档案关系标为“档案关系参考”。正文关系保留方向和完整限定语，不把“他信任她”改成互相信任，不把暂时合作改成亲密同盟。
- 档案别名仅用于召回：保留全部登记候选，正式姓名优先，不按第一个登记者猜身份。关系端点保留原称呼；只因关系使用别名而产生的假人物卡不再新增。共享称呼的全部候选以“档案称呼核对”进入同一必要预算块。
- 关系及称呼核对说明不可拆分；预算不足时明确失败。关系查询移除2000条上限，状态/位置等其他查询不能据此宣称全部无上限。
- 主生成的图谱读取失败抛出 `RequiredContextUnavailable('character_graph_context_unavailable')`，沿用公开的 `context_unavailable` 提示，不继续只用旧档案生成。组装先暂存在副本中，失败不发布半份卡片和关系；成功的空历史仍可使用。
- 分层记忆复用有方向和来源章的渲染器。`ChapterGenerator` 的 `pack.to_messages()` 与 `SceneOrchestrator` 的 `pack.to_system_prompt()` 使用的是实际组装结果。

没有改用PG原始抽取缓存替代图谱关系：那会绕过作者已经在图谱中做的修改和删除。作者图谱编辑的独立来源与重放保护仍需后续修复。

## 对中文小说验收的意义

下面仅为固定测试输入对应的上下文示意，不是模型新生成的小说：

```text
[CH-900] 老陈 → 阿青：暂时合作（仍各自提防，尚未互相信任）
档案称呼：老陈对应陈川；阿青对应沈青。
```

按[中文作者/编辑标准](CHINESE_FICTION_EDITORIAL_STANDARD.md)，下一场可以让二人配合行动，同时在交付证物、分担风险、说话分寸上保留戒心。若直接写成彼此毫无保留，不能因为“合作”一词已经出现就判为连贯。人物无需在正文复述关系标签；动作、对话和选择能承接前场，才说明材料被有效使用。

“同事”和“朋友”可以并存；一方的信任不证明另一方也信任；多人共用“老陈”也不证明他们是同一人。这些差异现在不会在上下文组装时被直接抹掉。

既有 `change` 契约仍会替换此前同向各类型。这只是现有写入语义，不能据此断言“敌对”必然解除“同事”或“亲兄弟”。正确的语义关联和作者修订仍待验收。来源摘要匹配也只证明版本一致，不能证明抽取模型解释正确。本轮没有新的互联网阅读、模型样稿或文学合格结论。
