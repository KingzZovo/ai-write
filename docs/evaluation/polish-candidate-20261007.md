# 完整上下文润色候选

旧后台可选enable_polish每2000字符截段，各自要求加口语、打破对称句，再无分隔拼接，并用正则删正文标记。硬切可能截断对话/场景，统一风格指令也不符合按作者与人物区别判断的要求。异常后polished_text复制原稿，会把未润色内容显示为润色版。

## 改动

新增polish_candidate服务，一次提供完整原稿与现有章节作者要求。提示词只修病句、歧义和无意重复，保留人物声音、段落、事实、视角与结尾；大纲保持层级。删除统一口语化指令及输出正则改文。结果单独存polished_text，原评审结果、章节正文与result_text不因润色候选改变。

共享结束原因校验拒绝明确截断；空响应报错、逐字未变不产生新候选。成功候选标needs_review并保存原稿SHA256；空稿/超过24000提示字符记录skipped，不截原稿。300秒协作式等待，输出预算16384 token；来源长并不保证回复够长，因此仍检查结束原因。失败仅记录类型并清空候选，不伪造成功。通过既有polishing路由调用并补项目/章节日志归属。

移动端默认显示原稿，切换标签改为“润色候选（待复核）”，不默认展示未经复核的第二稿。
