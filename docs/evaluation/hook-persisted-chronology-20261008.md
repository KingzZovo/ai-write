# 生成钩子的持久化章号（2026-10-08）

此前 HookManager._resolve_global_idx 用“之前各卷章数+卷内章号”重新计算，失败返回卷内章号。删除/调整章节后，算术位置可能不同于已有 Chapter.global_idx；查询失败还会让第二卷第3章被当成全书第3章，误导人物状态检查和新伏笔记录。

现在复用 resolve_history_boundary，按作品+卷+卷内章号查询已保存的 global_idx，仅接受正整数，未知/重复/异常不再回退。生成前人物检查与伏笔提示收到同一个持久化位置；查询失败或超过30秒时返回 can_proceed=false 和固定中文提示，不继续读取错误时间位置。现有 BatchGenerator 在 can_proceed=false 时不会创建生成任务。

生成后摘要与实体处理先按原有作品/卷/章作用域运行，再用30秒上限读取全书位置；定位失败只跳过依赖全书章号的兑现核查与新伏笔登记，不影响此前独立步骤。成功时两处伏笔调用均使用持久化位置。
