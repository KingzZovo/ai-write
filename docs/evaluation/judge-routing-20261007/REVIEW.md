## 实际结果

测试稿为上一批真实 ARM 生成的 1524 字车站交接章；对照稿为既有 396 字控制样本。请求使用当前完整章节评审提示与作者要求。以下分数仅记录模型返回，不能当作文学验收。

| 请求 | 耗时 | 模型返回 | 按原文复核 |
|---|---:|---|---|
| Gemini 3.1 Pro，非流式 | 4.33 秒 | 10 分，零问题 | 漏八点→八点半、限知视角越界 |
| Gemini 3.1 Pro，内部流式 | 3.64 秒 | 10 分，零问题 | 同样漏报；未证明改传输能解决评审问题 |
| Grok 4.5，有错稿 | 121.36 秒 | 请求超时 | 没有可评价的诊断；停止后续控制请求 |
| Grok chat fast，有错稿 | 3.81 秒 | 9.6 分，一个完成度问题 | 误判，并漏时间和视角问题 |
| Grok chat fast，对照稿 | 2.66 秒 | 10 分，零问题 | 本例未见误报，不证明泛化可靠 |

快模型认为陈川必须在站长明早八点半回来前完成封存并盖戳。作者实际要求“今晚没有完成正式封存”“陈川答应明早与站长共同核对后再封存”，并明确陈川无权代站长批准。模型把未来约定改成当前到期义务，还增加了不成立的截止时间。该问题没有 quote，原文也不支持诊断。

真正需要修的原文是：“我爸明早八点，在县医院有复诊的号”随后变成“预约的是八点半的专家号”；跟随沈青的限知视角中出现“在他眼里”陈川的内心判断，以及“冰凉的铜钥匙硌在手心”陈川的触觉。另有“交接薄”“洅出”用字问题。逐本登记、钥匙交付与明早封存安排基本已表达，不应要求今晚提前封存，也不应把正常上车省略判成缺失。

因此本轮不将快模型替换为默认评审，也不强制 Gemini 内部流式。T2 的旧 DeepSeek 默认模型已确认下线，且 12 项空 model_name 的任务继承它；替代模型的任务能力仍需验证，失效配置尚未解决。Embedding 配置未改。

## 代码修复

- `api/model_config.py`：创建、修改、删除端点提交成功后才重置路由；提交失败不发布失效。只改 default_model 时保留加密凭据。
- `services/model_router.py`：异步加载持有局部候选，加载期间若被重置则重新读取当前路由，避免访问 None 或返回失效候选。
- 新测试覆盖真实 PostgreSQL 独立连接的 CRUD 可见性、提交失败、加载途中重置（有/无第二个读取者）。测试不请求付费模型。

17 项针对性测试通过；全量后端 1857 passed、4 项既有 warnings，269.87 秒。Python AST、归档 JSON、git diff --check 通过；隔离运行时健康接口返回 ok，但该运行时尚未装入本批代码。全量日志位于本机 `/tmp/aiwrite-router-full.log`。

## 独立复核与范围

依 shadow-mind 的隔离要求，使用本地独立复核回退，没有启动共享可写目录的影子代理。正确性复核检查提交边界、失败传播、重置发生在 await 前后及新读取者先完成的交错；架构复核确认沿用既有 API 事务与单例，不增加新的路由配置来源。`expire_on_commit=False` 保证提交后响应字段可读；请求依赖最终空提交与现有 Prompt CRUD 做法一致。

残余风险：失效仍仅当前进程有效；其他长期存活进程的路由单例没有 TTL，Prompt 的 TTL 不能替代路由刷新。Celery 常规任务入口会重置单例，但不能据此宣称所有 Worker 已即时更新。已在执行的调用继续使用此前取得的路由。本批尚未构建 ARM 镜像或部署；上一批运行时仍在使用旧代码。闲置事务与 prompt UPDATE 归因、事实评审可靠性、后续完整工作流和生产上线均待续。

请求、返回、解析结果及 SHA256 见同目录文件；认证信息与原始驱动日志仅存私有目录，没有归档进仓库。
