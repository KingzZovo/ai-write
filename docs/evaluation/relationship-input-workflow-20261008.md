# 长书关系输入与断点恢复

2026-10-08。本批代码和离线验证已完成，未部署。章节事实提取改为先读完整本章，再按实际关系变化涉及的人物对核查前文；所有相关记录都保留，失败后复用已完成的提取和批次。

## 修复的问题

旧流程每章都把全项目有效关系发送给模型。一章只涉及陈川、沈青两个人时，300组支线人物也进入输入；作品越长，输入越膨胀。修改前的失败证据在`/tmp/aiwrite-rel-input-20261008-red.log`。

只按姓名在正文中的子串筛选，会漏掉称呼和指代。本次让模型先从完整正文提取变化，程序再按返回的原方向人物对读取旧记录；没有加入按词语猜身份、自动合并别名或裁掉旧关系的规则。

## 当前流程

1. `chapter_entities`提取完整本章的五类变化，初次不返回`replaces`。提示词明确区分新成立关系与已有关系的转变、解除、撤销或替代，不能因没有前文清单就一律当作新关系。逐字证据与全部数组通过校验后立即保存。
2. 按`changed_relationships`中的原方向人物对读取图谱，每次查询最多200对，结果没有全局记录上限。完整历史先核对来源，再折叠到有效旧记录；不提前相信派生结束日期，不把作者设定当自动结束目标。
3. 在调用范围模型前构建并保存全部批次。每批至多16条候选，保留完整类型、限定语、旧引文及完整本章。48,000字符预算包含实际注册的系统提示，并预留512字符供格式修复；单条材料仍放不下时明确失败。
4. 独立`relationship_scope`任务逐条返回`ended`和本章证据。每个ID恰好一次，false也必须回应；缺项、重复、未知ID、伪布尔、无法定位的引文及显式截断不能进入完成结果。格式问题最多修复一次，继续携带全部原材料。
5. 每完成一批即保存，恢复只处理未完成批次，使用冻结的候选。全部完成后合成原有五数组及`replaces`；变化证据和结束证据合并为正文中真实连续的一段，不拼成伪引文。随后才执行原图谱、PG事实和记忆卡投影。

没有变化或没有旧候选时，不调用范围模型；对应变化明确保留`replaces=[]`。旧完整缓存继续按原摘要重放，不为了升级而重新调用模型或猜结束对象。前章重写后，新同名关系不会成为冻结旧引用的替代对象，无法对应的旧引用继续标为待核对。

## 持久化与恢复

迁移`a1001945`向`chapter_entity_extractions`增加三列：

| 字段 | 职责 |
| --- | --- |
| `payload_stage` | 旧记录默认`complete`；初次结果尚待范围核查时为`scope_pending` |
| `scope_json` | 完整批次输入和逐批结果；全部完成后清为SQL NULL |
| `delivery_id` | 实际Celery任务编号，约束已知模型失败的重试归属 |

部分结果的摘要绑定来源、阶段、初次结果和全部批次；完整结果保留原`digest([source_hash,payload])`身份。损坏缓存保留供诊断、清除可重放摘要，不静默以新模型结果替换。降级迁移遇到未完成范围材料会拒绝丢弃。

每个检查点在短事务中核对本章来源与投影token；模型调用不持作者行锁。中途改稿或删章结束旧任务，旧token不能更新新任务的记录。图谱或PG投影失败时保留完整结果，恢复无需模型。

范围失败标为`scope_failed`，不进入每分钟自动模型重试循环；崩溃遗留的`running`仍可按原10分钟规则恢复。冻结复核进一步发现：仅过滤周期查询无法阻止此前已排队的重复调用。现在记录真实Celery request.id，原任务可继续最多3次Celery重试，新周期任务不能重新开始已知模型失败的调用。新的明确任务仍可继续未完成批次。

新Prompt资产初始化时继承已有`chapter_entities`路由，保留作者已配置的资产。不存在或未绑定时明确失败，不回退到五数组提示词。热路径继续使用Prompt缓存和统一调用入口。

## 输入规模实测

以下是离线合成工作流，模型被替身替代；字符数是实际传给调用入口的`user_content`长度，不是供应商token。

| 无关关系数量 | 初次提取输入字符 | 范围核查输入字符 |
| --- | ---: | ---: |
| 0 | 679 | 1094 |
| 300 | 679 | 1094 |
| 5000，均与主角有关、但对方不是本章变化对象 | 679 | 1094 |

另给同一人物对5000条确需核查的旧记录：全部保留为313批，每批都含完整本章；包含系统提示和修复预留的最大批次为15,821字符。建计划加校验耗时0.426977秒。证据在最终重点日志中。

这是输入选择和纯函数测量。大量相关记录仍需要相应的模型调用；完整计划随检查点保存，也会增加SQL写量。未测真实PG/Neo4j、模型费用、供应商token上限或500万字全链路延迟，不能把这张表称为整书容量验收。

## 中文作者/编辑标准

构造用例中，“陈川和沈青绝交了，公事照办”不能被程序扩展成两人已经离职；之前的同事身份应保留，私人交情的变化另记。后续正文是否合格，还要看双方如何回应、回避、交换信息，旧情绪怎样进入下一场，而非仅复述正确标签。

这些用例验证材料传递和工作流，不能证明模型正确读懂了反讽、失言、指代或复合关系。仍沿用[中文小说编辑式验收标准](CHINESE_FICTION_EDITORIAL_STANDARD.md)中已记录的《阿Ｑ正傳》《水滸傳》阅读范围，本轮没有新增互联网取样或生成正文。

CPA既有核查包含`gemini-3.1-pro`。此前Gemini完整候选存在限知视角越界，而自动评审给出满分；另一模型也有动作目的和交接问题，见[完整章节对照](context-guidance-20261007/REVIEW.md)及[CPA路由核查](cpa-gemini-routes-20261006/REVIEW.md)。本批未调用CPA、未切换默认模型，不能据此声称Gemini或新版Prompt已达到中文小说交付标准。
