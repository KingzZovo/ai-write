# 人物后台恢复的状态确认

状态：前后端代码及离线验证完成，真实浏览器/数据库验收和部署未完成。

## 修改

作者保存遇到同步失败时，后台已有持久 token，但编辑器只显示一次错误，不能知道恢复是否完成。本轮增加只读状态和候选稿绑定的确认流程。

- POST 人物保存仅在确定图稿已写入、PG 同步/确认未完成时返回 `character_projection_pending` 错误码。未知图写入结果、版本冲突不冒充后台恢复。
- `apiFetch` 的 `ApiError` 保留 HTTP 状态和可选业务码，仍继承 Error 并保持现有 message，避免前端靠中文字符串猜测状态。
- 新增 GET `/neo4j-settings/characters/profile?name=...`，返回当前图档案及 pending 布尔值，不写入、不调用模型、不暴露内部同步 token；不存在/坏档案分别返回 404/409。
- 编辑器收到明确 pending 后，将提交稿与当前草稿分别保存到 sessionStorage。每 5 秒只读核对图档案：仍待办则等待；图档案已被其他作者改动则停止并保留旧稿；待办清除后还要 GET 页面档案并逐项一致，才报告完成。
- 完成时推进已确认基线，保留等待期间继续输入的新内容。关闭/刷新后恢复未完成确认；后台已完成导致服务器基线变化时，不把同一已提交稿误判为旧草稿冲突。
- 项目/人物变化取消旧查询并隔离迟到响应；4xx 终止轮询，瞬时读取错误允许重试。等待确认期间不再发出保存请求，避免拿旧基线写入新的草稿。
- 发现新稿后，“载入当前档案”使用刚读取的权威图档案；不会重新装入旧基线。界面明确要求先复制保留的旧草稿再核对。
