# 卷纲采用、作者编辑与保存历史（2026-10-09）

本批完成源码、后端离线验证和本地冻结复核，未部署。桌面与移动端现在能把后台生成的卷纲候选放入编辑稿，核对后明确保存；空卷也可以直接编写第一份卷纲。作者正文、独立编辑的章节细纲和被替换的完整卷纲得到保留。

## 保存与候选合同

新入口为 `/api/projects/{project_id}/volume-outlines/{volume_id}`。读取按稳定分卷 ID 定位，以确认状态、版本、创建时间和 ID 选择当前卷纲；来源同时包含所有竞争卷纲的摘要，避免只比较一行而忽略新的确认记录。无效或重复卷号停止操作。

保存要求固定请求 UUID 和作者核对过的完整来源，文字与结构对象二选一。作品生成、资料和结构锁内重新比较来源，修改前完整稿、竞争卷纲快照、采用结果和请求摘要同事务保存。先确认提交，再返回成功；提交不明保留原请求。重试优先读取原回执，后续改稿或删卷不会让旧请求重新执行。相同编号不能用于另一份请求。

文字保存以作者 `raw_text` 为后续生成的权威材料。结构模式沿用既有的未编辑摘要同步，仅更新能够用原始 stub 证明未被作者改动的章节摘要；正文与独立细纲保持原样。新决定不继承旧稿的模型质量判定。结构模式不能同时绑定模型候选，界面说明已有作者文字与结构安排的关系。

异步卷纲提交绑定当时实际分卷 ID 和卷号。Worker 在共用作品执行锁内核对来源并认领，模型调用使用核对通过的卷号；交付时记录完整候选文本摘要。预览和采用要求任务完成、未取消、稳定目标及全文仍一致。客户端不能伪造候选回执。卷纲 JSON 保留叙事字段中的星号、反引号等原始字符。

候选回执只证明**任务、目标分卷和完整候选文本的关联**。它不证明整个书纲、风格、人物图谱等全部生成上下文，也不证明剧情安排或中文表达合格。

保存历史每页默认 20 条、最多 100 条，按创建时间及 ID 游标分页；列表不读取全文，点击记录才读取修改前后内容。原始下载包含全部历史 JSON 和竞争卷纲快照。删除分卷后保留历史及原回执；永久删除作品才级联清理。

旧 `/outlines` 卷纲创建、更新、确认和删除接入共用结构锁及提交确认；更新、确认、删除必须携带完整 `expected_content_json`，可以额外比较版本和确认状态。旧接口仍保留原结构同步能力，但**没有新入口的固定请求和完整保存历史合同**。书纲兼容流程保留。

分卷上移、下移改为 `/volumes/{volume_id}/move` 单次事务，明确相邻分卷 ID 和双方原卷号，交换后维护全书章序及大纲关联。桌面不再连续发送三次临时卷号更新。

## 作者使用流程

- 桌面中央编辑区、向导卷纲卡、空卷目录入口和移动端共用卷纲编辑会话；任务候选根据已记录的目标打开，不借用当前选中分卷。
- 候选全文先展示，作者明确放入后才改变编辑稿，点击保存才正式采用。可以恢复替换前稿；重复放入同一未修改候选不会覆盖原作者备份。
- 发送前暂存完整请求和编辑稿，未知结果重试原 UUID 和 JSON。保存过程中继续输入、切换分卷或恢复旧回执均保留后续稿；已知新远端稿冲突不会被旧回执清除。
- 损坏或无法写入的浏览器暂存阻止新覆盖，提供全文下载和离页提醒。浏览器暂存是恢复辅助，不承诺容量、跨设备同步或服务器持久化。
- 保存后刷新目录与历史，不强制切走作者当前视图；历史刷新取消详情读取时清除加载状态。两端按同一规则展示当前卷纲及完整叙事内容。

第二轮复核未发现新增具体问题，40 个代码/测试文件与冻结清单逐项一致。清单 `files` 对象按 `json.dumps(..., sort_keys=True)` 编码后的 SHA-256 为 `375e555445f52587aed2089f9cbae4af0587e6248bcb8e3fc9d2043959957b4f`。
