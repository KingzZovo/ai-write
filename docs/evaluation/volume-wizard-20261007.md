# 桌面分卷向导原子创建验收

## 问题与修改

桌面向导通过 `/api/generate/outline` 生成分卷时，后端先存卷纲、再另行创建卷章；前端又创建同一套卷章，可能出现重复卷号及默认20万字卷预算。空规划卷被当成已完成跳过，流中断或保存失败后仍可能进入下一步。

新增 `volume_creation.py`：生成前核实本项目已确认书纲及空卷状态，记录源快照；完整结构校验后在项目/书纲/卷行锁下比较快照，同事务保存卷纲、卷和所有章节。已有章节或卷纲拒绝覆盖。默认预算按全书计划章数分配，保留整数余数；显式非默认自定义卷预算保留。生成期间作者改书纲、项目、空卷或新增章节，保存拒绝覆盖。

桌面向导由 `volumeWizard.ts` 统一执行：只在明确收到 saved ID 和 completed 后读取服务端结果，并核实卷章数量及顺序。前端不再重复 POST 卷章或 PUT 卷纲，不自动重试；已完整卷章保留，空规划卷继续生成，失败停留当前步骤。

## 本地独立复核

按 shadow-mind 技能使用本地复核（当前子代理没有可信只读隔离）。分别检查持久化/并发及界面成功边界。发现旧 detached save 在连接取消后可能越过项目锁存活：分卷改为直接等待保存任务，取消时清理会话并回滚，完成后再释放项目互斥。增加真实 PostgreSQL 取消提交用例。

## 范围与后续

本批修复分卷首次创建与桌面向导。不会清理已有重复数据；历史不完整卷章需检查后走已有再生成入口。预算值恰好为20万仍按历史默认值处理，现有模型没有区分用户显式设置与默认来源。独立细纲/整书流式保存仍需后续审计。此次不包含新的模型中文正文质量结论；生产尚未发布。
