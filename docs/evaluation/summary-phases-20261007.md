# 摘要自管会话拆分

## 问题与修复

上一轮 ARM 完整章节探针在摘要期间观察到闲置事务停在 prompt_assets 读取。SSE 保存正文的会话被直接传给摘要服务，源读取与 Registry 请求会跨越模型等待。

summarize_and_save_chapter 现在允许 db=None：以短会话读取源正文、摘要及完整位置/版本快照，关闭后调用模型；再开短会话按原有完整来源 CAS 写回。自管路径在模型期间没有源读取事务，向量/正文块投影前写入已提交并关闭。空输出不建写会话，取消正常向上传播。借用会话保持原有事务所有权与脏对象保护，不擅自关闭调用方会话。

SSE 保存入口在摘要前完成自己的 dispatch 读取事务，再调用自管摘要。章节正文与版本已先提交，来源 CAS 仍防止等待模型期间的改稿、删章及改后恢复写入旧摘要。摘要不推进正文 updated_at 的既有规则保持。
