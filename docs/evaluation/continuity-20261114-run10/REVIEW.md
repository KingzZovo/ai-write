## 跨章确定性检查(12 处,全部可复核)

```
{"chapters": 10, "violations": 12}
{'word_below_target': 9, 'remainder_conflict': 1, 'prop_missing': 2}
```

### 1. 字数系统性偏低:9/10 章低于目标的 85%

比值 0.48–0.77,只有终章 ch10 冲到 1.33。这不是偶发方差,而是**稳定写不够**:
目标 1200 字、场景预算区间 1020–1380 的前提下,模型交出的中位数只有 0.62。
这一项上一轮(3 章)已经看到,现在在 10 章上得到确认。

### 2. 第 1 章章内数字自相矛盾(硬伤)

同一章里同一笔账出现四个数:

- 「一共两千,我妈那儿垫的三千,眼下就凑出来这些」→ 已还 2000 / 欠 3000
- 「周芸数到**一千八百**块时停了停」→ 手里明明只有两千,却数到 1800 停手
- 「**剩下那八张十块**的攥在手心」→ 80 元
- 「**剩下的八百**,我跟铺子里的刘老板说好了」→ 缺口变成 800(设定是 1000)

`remainder_conflict` 抓到了其中「一千/八百」这一对;点钞数到 1800 这一步需要人读才能发现,
说明**"数字自洽"还没有被完整机器化**。

### 3. 大纲里的道具没有落地

`顶针`、`铁盒` 全篇一次都没出现(第 2、7 章的大纲围绕它们展开)。`信封` 出现了,
但方向与大纲相反:大纲是"周芸把信封压在碗下给弟弟",正文是"周航把信封递给周芸"。

## 编辑式审读(读了 ch01 全文与 ch10 结尾)

- ch01 的场景质感比上一轮好:渡口凉风、军绿挎包、拆下来的电饭锅内胆挂在车后架、
  数钱时"每一张都带着常年贴身存放的温热"——这些是有具体来源的细节,不是通用氛围。
- 但人物关系与钱的关系被写糊了:姐弟谁欠谁、信封里到底多少钱、缺口是多少,读者要回头数两遍。
  这是本场最需要修的地方。
- ch10(终章)反而把篇幅写足了(1598 字),说明"写不够"不是能力问题,而是**预算没有被执行**。
- 判定:**需局部修订**(数字与道具是硬问题,语言本身可用)。

## 本轮修掉的三个真缺陷(都在生产代码里)

1. **`entity_context.py` 缺 `UUID` 导入** → 有角色的项目整章写不出来(P0,已修 + 回归)。
2. **NVIDIA embeddings 批量请求 400** → `modality` 必须与 `input` 等长,而 provider 永远只发
   `["text"]`,于是批量向量化全挂、语义召回不可用,第 4 章起阻断。已改为按输入条数展开
   (`nvidia_embedding_payload`,5 项回归;直接对官方端点验证过 2 条输入的行为)。
3. **认知提取的逐字依据失败后无定向修复** → 模型把 evidence 改写成自己的话(实测 5 条里 3 条
   在正文中找不到),连报 3 次即中止,整条链停住。现在:系统提示明确"直接复制连续片段,
   不改写、不加省略号、不拼接",并且失败时把**具体哪几条找不到**回给模型重试。
   修后本轮 10/10 一次通过。
