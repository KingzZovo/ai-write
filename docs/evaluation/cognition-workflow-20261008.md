# 人物认知提取与上下文修复

2026-10-08，基于`1e22e20`。仅修改本地分支，未执行服务连接、CPA调用、真实数据库迁移或部署。

## 问题与修复

离线复现发现：带截断/过滤结束标记的有效JSON数组可被保存为完成结果；默认注册提示与调用附加提示重复；已知模型失败会每5分钟重新派发。认知读取在验证原句后丢弃原句，固定1200字预算又由全书较新条目争抢，可能挤掉本章人物的关键获知过程。手动和后台评审在认知读取失败后仍可评分。后来补充复现了已知pending/running/failed等当前来源被当成空知识的路径。

- 提取使用完整正文与实际注册Prompt，移除重复附加系统提示。明确异常结束直接失败，普通结构错误最多修复一次；保持180秒总预算和现有路由预算。
- `ChapterCognition`增加`delivery_id`和`attempt_count`。每个执行周期最多4次提取尝试（初次加3次重试），每次至多两次格式调用；底层供应商既有重试预算没有放大。重复原消息也不能重置次数。周期任务只恢复未确认的pending/过期queued/running；已知失败只允许原任务剩余次数或明确新尝试继续。
- 入队、认领、格式修复前和落库核对来源，每次调用模型前再核对租约。作者改稿、删章或新令牌会停止旧结果；取消保持取消语义。来源/回执读写会话在模型调用前关闭，不让作者行锁跨模型I/O。
- 先验证当前来源，再校验整个结果的回执、摘要、结构和原句。旧版本来源失效时排除；当前来源未完成或损坏时明确阻断。完整原句与来源章号保留到最终Prompt。
- `load_prompt_context`统一ContextPack、后台评审、手动评审、后台生成修订和SSE修订。原标签匹配仅用于召回，不改写身份或合并同义事实。所选人物和本章标签、读者的最新记录先保留，余量按人物轮流挑选完整条目；缺省上限仍为1200字符，最低节选放不下明确报错，总数和节选数可见。
- 较早“当时未知”和后来获知继续按章保留；转述、怀疑和误解的限定不被程序移除。未知条目缺失不等于人物知道，知识条目缺失也不等于人物不知道。

## 中文作者视角

样例中的“陈川不知道信已送到”与后来的“沈青把回执交给他，他才明白父亲已经收信”属于两个时刻。写下一章时，应能核对他通过什么行动获知消息，而非只有一条无来源的结论。获知事实以后，人物是否信服、如何回应、是否隐瞒，仍需结合场面和人物动机判断。

这批使用原创诊断材料核对传递边界，没有生成新小说，也没有用模型分数验收文学质量。继续遵守[中文小说编辑式标准](CHINESE_FICTION_EDITORIAL_STANDARD.md)以及既有《阿Q正传》《水浒传》原文参照。逐字引文只保证可定位，不能证明提取语义正确，更不能证明人物、语言、节奏和全章完整性已合格。

本轮未调整Gemini路由或默认模型。既有[CPA诊断](cpa-gemini-routes-20261006/REVIEW.md)及[认知对照](cognition-history-20261007/REVIEW.md)仍是历史证据；新比较须固定健康上游，以同材料的完整连续章和编辑修改量验收。

## 冻结复核

按`shadow-mind`的无可信只读隔离回退规则，本地分别做正确性/性能与归属/完成性复核；没有启动子代理。首轮冻结26个文件并核对未变，记录为`/tmp/aiwrite-cognition-workflow-20261008-review-v1.md`。发现两处具体问题：认领提交时失去租约仍可调用一次模型，以及轮流选择记录会扫描“最长历史长度×人物数”的空位。

结束首轮复核后，新增离线复现确认前者会多调用模型一次；增加调用前租约检查后通过。后者改用未耗尽迭代器队列，避免反复检查空历史。在5000个人物、9999条偏斜记录、100万字符探针预算下，完整输出同为578366字符，实测1.305609秒降至0.037003秒。该预算用于测试完整保留与算法开销，不是生产模型上下文设置。两项修复验证见`/tmp/aiwrite-cognition-workflow-20261008-review-red.log`和`/tmp/aiwrite-cognition-workflow-20261008-review-green.log`。

修复后再跑重点和全目录回归，最终冻结清单为`/tmp/aiwrite-cognition-workflow-20261008-freeze-final.json`，两视角最终核对记录为`/tmp/aiwrite-cognition-workflow-20261008-review-final.md`。没有把SQLite或纯函数探针扩展为真实服务、整书容量或文学质量结论。
