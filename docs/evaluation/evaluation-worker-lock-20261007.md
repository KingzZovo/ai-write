# 重复评审消息的worker互斥

新增evaluation_worker_lock，按任务UUID生成独立PG advisory命名空间，与项目生成/资料投影锁分离。调用pg_try_advisory_lock失败即返回already_running，不读取任务或调用模型。

EvaluationLease的会话绑定持锁的同一物理连接，避免丢锁后通过另一池连接写入旧结果。模型前提交并关闭读取会话，模型等待期间不保留事务；读取前、模型前、错误/结果写回前检查锁连接。上下文错误rollback后也检查连接再重读，避免无意识重连继续写。

退出始终invalidate专用连接，包括取消、查询/提交失败导致获取锁结果不明确的情况，防止会话锁返回连接池。代价是每个活动评审占用一条连接，且完成后需新建物理连接；容量需按真实worker并发验收。评审异常存储改为固定evaluation_call_failed，不将供应商异常原文写入任务。

验证：31项离线回归通过；新增6项锁命名空间、正常/忙/取消/提交失败连接清理与同连接session绑定、busy不执行核心函数，以及1项模型后丢锁不写结果。现有后台函数测试改用明确的lease替身。5文件AST和git diff --check通过。

新增1项真实PG门禁（仅收集、未运行）：同时投递同任务只调用模型一次，并在模型等待时检查持锁连接没有开放事务，最后验证结果保存。

按shadow-mind无可靠只读隔离回退，冻结后本地复核连接所有权、事务边界、丢锁/回滚/取消路径及池清理。复核将结果读写绑定锁连接，并扩大获取锁异常时的清理范围；对应测试已通过。

未完成：真实PG断连/终止后恢复、连接池容量、Celery重复消息与进程退出验收。pending消息重投递尚未实现，不能把互斥当作恢复完成。模型调用结果与提交之间进程崩溃仍可能导致后来重复调用模型；本轮不承诺外部API恰好一次计费。现有生产与迁移未更新，整体目标继续。
