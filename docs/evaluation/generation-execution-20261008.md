# 旧生成运行器的执行互斥与失效保护

2026-10-08启动，2026-10-09完成本批代码和离线回归。未部署，未访问运行服务或CPA，未切换默认模型。单书设计下限继续是500万字+；本批没有进行整书性能或文学验收。

## 问题与行为

旧`generation-runs/start`先创建Run再执行，同书的重复恢复也没有跨worker执行权保护。只把Session绑定某个SQLAlchemy Connection仍不够：连接失效后允许重连，旧任务的晚到结果或异常收尾可能覆盖新任务检查点。

现在`start_run`在作品锁内核对目标后创建并执行，返回已保存快照。`execute_run`先用独立短会话读归属，再取得执行权并重新读取状态；其他执行者已经完成时直接返回当前结果。API不再在借入会话上刷新旧Run实例，服务也不提交调用者的待提交事务。

| 情况 | 当前行为 |
| --- | --- |
| 本书已有执行者或活动整书任务 | 409；不创建额外Run、不改旧检查点、不调用模型 |
| 新建缺少章节或传null | 422；章节是必填目标 |
| 作品/章节不存在、回收站或跨作品章节 | 404；已保存稿保持原状 |
| 新建或恢复正常结束 | 返回执行会话内读取的已保存状态；仍是`needs_author_review` |
| 取得执行权之前已有其他执行者完成 | 锁内重读并返回新结果，不再生成 |
| 已完成记录被再次恢复 | 允许只读返回，不要求取得作品执行权 |
| 数据库提交或执行权未获确认 | 固定503，不伪造已保存的失败状态；尽可能返回`run_id`供读取核对 |

活动整书状态沿用`production.control.ACTIVE_STATES`：queued、generating、pausing。新建服务的返回形状由ORM对象改为快照，仓库内实际API调用方及文档示例已经同步。

## 执行与写入边界

`generation_execution.py`使用与整书、单章及作者写入命令相同的`project_lock_key`。独立PG物理连接持有会话锁，Run、检查点、CriticReport、候选及错误状态通过绑定这条连接的Session写入。

`PhysicalConnectionGuard`记录原DBAPI对象，在普通SQL、driver SQL、事务开始及提交前核对连接身份；已知失效或发现替换后永久撤销旧执行权。`GenerationExecutionSession.commit`在提交异常或取消时同样撤销执行权，禁止旧任务靠重新读取、重写failed来覆盖未确认结果。

退出先撤销业务执行权，再关闭Session、丢弃物理连接，最后移除监听。清理任务受到shield保护并排空，连续取消不能让外层连接先退出。取得锁、锁确认失败、忙碌、模型异常与取消均经过清理。已提交完成后的进度通知失败不再降级已保存的done状态。

评审、截断交付、候选保存/恢复及改写预算合同继续有效：审稿阶段取消后沿用已提交正文；硬伤未解决且预算耗尽仍停在needs_review。只承诺此前提交的文本得到保留，断库时尚未提交的模型输出不能声称已保存。
