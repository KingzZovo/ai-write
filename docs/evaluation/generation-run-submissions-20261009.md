# 旧生成运行器：固定请求与章稿来源

日期：2026-10-09。分支：`fix/2026-10-06-pipeline-safety`。当前为本地源码与离线验证，尚未部署。

## 问题与处理

旧 `/api/generation-runs/start` 每次产生随机编号，也不要求作者提交所看到的完整保存稿。请求已执行而响应丢失后，重复 POST 会产生第二次模型执行；旧断点恢复也无法证明当前章稿仍是原请求的来源。

新增 `generation_run_submissions` 独立表：客户端请求 UUID 同时作为 Run ID，原请求摘要、原改写上限、章稿及分卷位置来源与初始 Run 同事务提交。提交获确认后才进入原生成核心。模型、评审、候选仍走原有路径；本批不替换 Chapter 正文，不将候选状态或评审完成当作文学合格。

重复 POST 首先读取原回执。完全相同的请求只返回原检查点，running、failed、needs_review 与 done 均不重新执行；参数不同返回冲突。并发提交恰好发生在首次回执读取与运行读取之间时，会再次核对回执，避免误把刚受理的请求判为旧编号冲突。取得执行锁后再次读取，锁忙时也允许观察已提交的原请求。

## 接口合同与兼容

`POST /api/generation-runs/start`：

| 字段 | 合同 |
| --- | --- |
| `request_id` | 必需的客户端 UUID；发送前保存，重试必须复用；响应 `id` 等于它 |
| `project_id` / `chapter_id` | 必需的稳定目标 UUID |
| `expected_content_text` | 必需的完整保存稿，逐字比较；未写章节显式传 `""`；不能用未保存编辑稿替代 |
| `max_rewrite_count` | 0–8 的整数，默认 2；属于固定请求，不接受字符串或布尔值 |

未知字段拒绝，避免调用者以为设置已生效。没有找到 `frontend/src` 的旧 Run 调用方，因此本批没有前端源码变更。仍使用此接口的外部客户端须同步升级；不能让新旧请求合同混用。

| 状态 | 含义 |
| --- | --- |
| 428 | 缺固定请求编号或完整原稿前提；尚未创建运行 |
| 409 | 编号绑定其他请求、原稿/来源变化、来源证明不全或作品正被其他执行占用 |
| 404 | 尚未观察到此运行，或作品/章节不可用、作品已永久删除 |
| 410 `generation_run_gone` | 原请求已受理，但 Run 或章节已删除；旧编号不能重新生成 |
| 422 | 参数、UUID、改写上限或正文编码无效 |
| 503 | 数据库执行/提交结果未确认；保留原 `run_id`，先 GET 核对 |

`GET /api/generation-runs/{id}` 只读，旧候选仍可查看；缺失 Run 而后见到回执时再次读取，区分刚提交与实际删除，后者返回 410。永久删除作品后连同回执清理，此后返回 404。

初始事务已提交但确认丢失时，重试 POST 可能读到 `planning/running`。这代表记录已受理，不能据此宣称模型已经执行或正文已经保存。继续生成仍须显式调用原 `/resume`；普通 POST 重试不代替恢复操作。

## 原稿、恢复和删除边界

- 原稿比较不截断、不去空白；请求摘要涵盖全部公开输入。持久来源只保存有界指纹，完整正文不复制进回执表。
- 复用 `chapter_submission_source`，覆盖正文、标题、细纲、卷/章/全书位置、状态、摘要及其来源、目标字数和作者版本时间；另保留分卷 ID、作品归属和卷号。改文后恢复原文也不能绕过版本比较。摘要来源发生变化同样需要核对，不能宣称只检查正文。
- 新建和恢复沿用专用物理连接上的作品执行锁。捕获/核对来源时按 Project → Volume → Chapter 取短行锁；Project 使用 KEY SHARE 保护删除，Volume/Chapter 使用 SHARE 保护来源。来源事务在模型工作前结束，作品执行锁继续保留。
- 显式恢复在作品锁内检查回执、Run 归属、原改写上限及计数、当前章稿和分卷来源；不重建旧回执、不改写原请求、不清零计数。缺证明或来源不同的历史运行保留原候选，停止自动续写；已完成运行仍可只读返回。
- 回执只对 Project 设置级联外键。删除 Run、章节或分卷不会释放已受理的请求编号；即使重新创建同 UUID 的章节，旧请求也不可重放。永久删书才清理回执。回执不是候选全文备份，删章时原有候选/报告的级联行为未改变。
- 来源证明只覆盖本次记录的章稿和位置，不能证明整部作品的书纲、所有前章、人物、提示词版本和模型线路均被冻结；恢复时上下文仍经原准备/核查链重新读取。
