# 普通正文与整章改写重试完整性

## 问题

ChapterGenerator.generate收到GenerationResult后直接返回text，没有使用供应商finish_reason，带句号的截断回复也能进入后续候选处理。后台整章改写场景循环失败后有两次尝试，共用regen_chunks；第一次已生成文字后异常，第二次继续append，会把两份稿件拼接。

## 改动

普通正文生成返回前调用共享require_normal_finish，拒绝length/max_tokens/content_filter/tool_calls等明确非正常结束。底层内部流汇总成GenerationResult也适用。不以句号判断完成，缺失结束元数据仍保留旧兼容行为，完整性未知。

后台整章改写收到任意非空片段后失败，保留last_regen_err并退出重试循环，进入既有needs_repair分支，不把regen_chunks赋给current_text。零文字失败仍允许原有第二次尝试。定点模式未改动。

## 验证

80项相关离线测试通过：普通正文真实生成器调用（上下文/端点替身）、直接流、结束原因、定点不升级、风格信号链。新增AST分支测试执行生产代码的整章重试循环，验证部分交付后只调用一次、无文字失败仍可重试成功；这不是完整Celery/数据库测试。

按shadow-mind本地两轮复核：正确性检查确认结束校验在返回text和人物检查前，部分输出错误保留在last_regen_err；调用链检查确认错误分支break先于current_text替换。平台无可靠只读子代理隔离，未启动子代理。

## 未完成验收

真实端点、完整任务持久化/界面恢复尚未实跑；needs_repair的现有错误提示仍偏向场景规划故障，供应商截断的分类反馈需要继续完善。后续质量门禁对保留候选的处理、非本入口的普通文本调用、整章改写事实与作者声音保留仍待检查。正常结束不代表文学完整，也不证明写作质量提升。未新增迁移、未部署，累计迁移头a1001934尚未执行。
