# 生成上下文的实体来源核对（2026-10-06）

## 本批实现

后台失效清理是最终一致，作者提交改稿到清理任务完成之间仍可能读取旧状态。本批在生成读取边界核对每条记录的直接正文来源。

- `filter_current_entity_rows` 共用批量来源校验：按章节ID查当前作品、卷、正文、标题、状态、持久化章序，重算实体来源哈希；拒绝未知来源、非completed、重复全书章号和当前/未来章。每批最多200个不同来源，用列查询且禁用autoflush，避免ORM旧缓存。记忆卡另外核对摘录确实逐字存在于该版本完整正文。
- `a1001927` 为PG人物状态、位置读模型增加章节ID和来源哈希；物化从Neo4j保留来源并与别名归一化同步。旧行不伪造来源。两个本机测试库已应用DDL，生产未迁移。
- `verified_world_snapshot` 在同一Neo4j读取事务取状态/关系/位置候选，再回查PG来源；当前章重写仅用其之前的事实。每类查询有2000条候选上限。没有来源的旧图节点/组织边不自动进入该章派生事实通道。
- ContextPack的图谱补充、PG状态/位置覆盖、“旧人重现”记忆卡，和旧HierarchicalMemory的实体层改用来源核对。直接来源失效时，不能通过另一个旧读模型绕回来。
- 生成前人物死亡检查同时核对PG/Neo4j来源；死亡判断使用明确字段值，不再把“濒临死亡”“避免死亡”中的子串当作人物已死。
- 登场统计只作触发提示的候选条件；记忆卡标题用最近通过来源核验的片段章号，标“最近核实片段”，不把旧统计里的章号冒充最后出场事实。

## 尚未完成

1. **继承字段的来源混淆**：`EntityTimelineService.apply_entity_changes` 会读取前态并把前章字段合并到本章新状态。前章字段可能失效，但合并后的整行使用本章来源哈希。直接来源校验不能证明每个继承字段成立。下一步须将逐章状态变化与累计状态分开，逐字段保留来源或按有效逐章变化重建，验证前章编辑后后章不携带旧字段。
2. **其它事实/统计路径**：人物基础profile、登场统计、认知、关联章节诊断、非本章五类实体及管理API仍有独立读取路径，不应把本批主生成入口收敛描述为所有数据入口已治理。
3. **旧数据重建**：旧图、旧读模型没有凭据时会被排除；需可恢复重建流程填补记忆缺口，不能假设缺数据就是没有事实。旧已completed投影的读模型刷新也需明确版本策略。
4. **规模与并发边界**：目前为有界候选批量回查，未做500万字基准；校验代表读取时看到的来源，不锁住作者直到模型生成结束。生成结果仍须已有来源版本/CAS写回保护。
5. **文学、端到端、上线**：模型提取准确性、中文长篇连续性、浏览器全流程、备份恢复和生产部署仍未验收。本批没有真实模型调用。
