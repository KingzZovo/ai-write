# 人物保存的条件写与可重试同步

状态：代码及离线验证完成，真实 Neo4j/PG 并发验收与部署未完成。

## 行为

新增 `character_profile_write.write_character_profile`，在 Neo4j 单个写事务内先对人物节点执行依赖原值的计数更新，取得写锁，再读取和比较档案。内容比较按 JSON 键排序，区分布尔和数字，不依赖序列化键顺序。

- 编辑请求必须携带原档案 `expected_profile_json`；当前内容既不等于原稿、也不等于待保存稿时返回 409，不覆盖。
- 当前内容已经等于待保存稿，作为幂等重试允许再次严格同步。图已写入、PG 同步或响应失败后，重试相同请求不必先覆盖其他版本。
- `expected_profile_json: null` 表示仅创建；同名不同档案拒绝。同名同内容可重试。编辑使用 MATCH，人物已删除时不重新创建。
- 完整 `profile_json` 和旧稿字段均为必填。清空必须明确发送 `{}`；缺字段/null 不推断为清空。姓名去除两端空格并拒绝空姓名。
- 作者来源仍写入 `author_edit`。图错误/同步错误返回脱敏的 503；同步使用本次图驱动及 `strict=True`，不把失败伪装为 accepted。
- 编辑器提交最后一次已核对基线，失败不推进基线；添加表单提交 create-only，增加重复提交保护和错误提示，失败保留输入。

## 接口兼容与部署

此接口契约收紧：旧客户端不带 `expected_profile_json` 或 `profile_json` 会得到 422。仓库内全部官方人物写入调用已更新；发布时需成套更新前后端。没有放任旧调用绕过比较的后门。

Neo4j 使用动态节点属性 `profile_write_lock`，无新增 PostgreSQL 迁移。本轮未修改实际运行服务或生产配置。

## 本地独立复核

依 shadow-mind 无可靠只读隔离的回退流程，分别检查事务/失败行为与接口/用户流程。复核修正了缺完整档案时被默认空对象清空的问题，并确认创建和编辑分支分离，失败比较回滚整个事务。前端确认失败后保留原基线与草稿，不以重复点击强制覆盖新版本。

## 未完成事项

- 内容快照并非独立版本序号。同名人物删除重建且内容相同的情况，以及内容改变后又恢复的情况，无法仅凭本次快照识别。
- 后台 materializer 仍可能使用更旧的作者图快照覆盖较新的 PG 投影；本轮保证图端条件写，不声明跨库版本排序已经完成。
- 作者保存仍无持久化自动恢复回执。503 后可重试相同稿；若图/PG 原本不一致或失败后又改了草稿，需要核对当前权威版本，不能强行重试覆盖。
- 真实 Neo4j 约束、节点锁、PG 同步故障注入、浏览器并发与整体部署仍须验证。历史 PG/图人物档案分歧未自动迁移。
