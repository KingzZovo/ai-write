# 独立后台任务：执行归属与正文交付证明

日期：2026-10-09。分支：`fix/2026-10-06-pipeline-safety`。本批完成本地源码和离线验证，尚未部署。

## 问题与处理

独立正文任务此前只有 pending → running 认领，没有持久执行 UUID、心跳、首次执行参数和独立正文保存证明。部分大纲任务没有经过作品执行锁；正常保存和异常补存使用不同数据库连接，不能仅凭任务仍显示 running 就确认旧执行者还有写入权。

现在五类独立任务（正文、书纲、卷纲、章纲、参考小说书纲）共用既有作品执行锁。首次认领核对来源并提交执行记录后，才进入模型流程。正文、任务状态、大纲、版本及评审的规范写入绑定持锁物理连接；新保存会话只更换对象缓存，不更换连接。只读认知材料继续使用独立会话。

正文保存时在同一事务写入交付证明。进程在保存成功后、更新任务完成状态前退出，不再只能靠进度文字猜测是否已保存。仅有保存证明而执行没有完整结束时，明确进入 needs_review；这不代表小说已经通过中文编辑验收。

## 执行与保存合同

| 环节 | 行为 |
| --- | --- |
| 认领 | 作品锁内核对作品、原提交证明、正文原稿或分卷来源；首次记录执行版本 1、UUID、原参数副本、尝试次数与开始时间 |
| 重复投递 | 非 pending 请求只读返回；已有执行记录不能通过重置 pending 重新认领 |
| 执行归属 | 批次子任务必须来自所属批次；整书子任务由 production/chapter_executor 执行，单独投递只读跳过；HTTP 拒绝伪造 pipeline_id |
| 写入 | Project → Task 行锁核对执行 UUID、版本和取消标记；规范 ORM/Core DML 必须使用持锁连接，旧连接失效后不能用新连接补写 |
| 会话 | 禁止未结束事务上的重叠保存会话；规范写入不支持保存点，避免回滚保存点后误复用行锁校验证明 |
| 心跳 | 15 秒一次，独立连接按执行 UUID/版本更新；不修改进度排序时间。已知写连接失效、取消或执行凭证变化时收束工作 |
| 取消清理 | 监督者只向工作协程发送一次取消，并排空工作、心跳、每个保存会话关闭及外层物理连接清理，之后才释放作品锁 |
| 来源拒绝 | 失败回写重新取得 Project → Task 锁；不能覆盖已经接受的取消，也不能修改其他作品、批次或整书的任务 |

`saved_manuscript_json` 绑定执行 UUID、任务 ID、原提交摘要、完整正文 SHA-256、状态、实际字符数和保存稿来源。复用批次保存证明的材料规则：正文、标题、细纲、位置、作者版本等仍参与核对，派生摘要及其摘要来源不伪装正文改动。证明写入失败时正文也回滚；提交确认丢失时保留数据库的实际结果，旧执行者不得补写 failed 来覆盖它。

所有保存分支仍调用原生成核心。新增实际核心入口测试覆盖正常完成、质量待审、质量服务错误、事实检查待审/错误、评审异常补存、流式中断，以及四类大纲的保存或候选处理。测试使用真实 SQLite 事务，替代模型、派生服务和 PG 传输；测试片段用于验证交付行为，不用于文学评分。

## 数据与兼容性

新增迁移 `a1001955`，父迁移 `a1001954`，源码保持单头。`generation_tasks` 增加七列：`execution_version`、`execution_id`、`heartbeat_at`、`execution_params_json`、`attempt_count`、`attempts_json`、`saved_manuscript_json`。

旧行保留版本 0，不补造历史执行或交付证明。PG 降级先取得表锁，再核对是否已有新版执行；有证明时拒绝直接删除这些列。SQLite 用例验证旧请求、状态、候选保留及降级保护。迁移尚未在真实 PostgreSQL 应用，上线前仍须核对累计迁移和所有 worker 版本。

卷纲来源错误继续返回既有 `StaleChapterWrite` 合同。卷纲任务只产候选，正式采用仍走既有作者保存入口。批次和整书的执行合同保持独立，本批不把它们迁入新执行器。
