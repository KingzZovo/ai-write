## 1. 这一轮要回答什么

前一轮 `continuity-20261114-run10` 的检查器报了 `time_missing` 8/10、`place_missing` 1/10,
读正文后看着像"第 2 章起整章脱离大纲、时间地点视角全错"。

但在写结论前我先去查了**大纲到底有没有送进生成链**,结果发现那是**我这套测量装置自己的缺陷**,
不是产品行为。这一轮把装置修好,重跑同样的 10 章。

## 2. 根因:大纲在提示投影里被静默截断

`context_pack._render_chapter_outline_block()` 只认识生产 schema 的字段
(`summary` / `key_events` / `prev_chapter_threads` / `state_changes` / `foreshadows_*` /
`next_chapter_hook` / 合同字段 / `scene_beats`)。

而探针原来写的是:

```python
{"title": ..., "brief": ..., "pov": ..., "location": ..., "time_cue": ..., "key_action": ...}
```

一个都不在渲染器认识的范围里。渲染器末尾的降级分支是"没有任何能识别的字段就 dump 整份 dict",
判据是 `if not parts:` —— 但标题行已经让 `parts` 非空,于是**整章大纲只剩一行标题**,
`brief`/视角/地点/时间全部丢掉。

后果:第 1 章还能从书名/卷纲起步;第 2 章起模型手里只有"上一章正文 + 本章标题",
于是natural 地顺着上一章往下写。run10 里看到的"时间/地点/视角漂移"就是这么来的。

**两个缺陷,一真一假:**

| | 性质 | 说明 |
|---|---|---|
| 探针用非生产字段名 | 测量装置缺陷(我的) | 使测量结果无效,必须修 |
| 渲染器把非 schema 字段静默丢成一行标题 | 产品缺陷(真实,但触发面窄) | 生产路径(`chapter_outline_expander`、弧规划)都强制 `summary`+`key_events`,所以真实用户走正常路径不会触发;但作者/导入/旧大纲一旦用别的字段名,就会静默丢失,正是本仓库反复治理的那类"静默失败" |

## 3. 修复

1. **探针改用生产 schema**(`scripts/quality_eval/continuity_probe.py`):写入
   `chapter_idx/title/summary/key_events`,其中 `summary` 以
   `时间:<time>;地点:<place>;视角:<pov>。<brief>` 开头,`key_events` 由 brief 的
   "本场需完成" 拆出。这样这些信息走的是渲染器真正会渲染的字段。
2. **渲染器不再静默截断**(`app/services/context_pack.py`):记录标题行数 `header_lines`,
   若标题之外一个字段都没渲染到,则把剩余字段补出来(跳过已渲染字段与顺序元数据)。
   这是恢复该函数注释里写明的作者意图,不是新增功能。
3. 新增检查 `pov_missing`(声明视角人物是否出现在开头 300 字内)。
4. 修探针续跑分支的字数单位:原为文件字节数,与新建分支的字符数不同单位,续跑章节会显得是三倍长。
5. 回归测试:`tests/test_outline_prompt_integrity.py` 增 2 项
   (非 schema 字段不被丢弃 / 生产字段不重复渲染)。

## 5. 人工核验(不只看计数)

- `time_missing` ch07:正文写"前几天凑出来的三百块已经交给了弟弟",
  与声明"三天后"**不矛盾但不精确**,属弱命中;不是漂移。
- `number_conflict` key="在我这":误报。检查器取数字后 3 个汉字当名目,
  "在我这账本上"  这种介词短语被当成名目。该检查的 detail 本身已写明"需人工核对"。
- **一处真实缺陷**:ch07 写"四十套,每套二十二块,加起来是八百八十块",
  ch08 写"总共是八百二十元。这笔钱是四十套校服的工钱"。40×22=880 ≠ 820,
  跨章数字自相矛盾。成因:ch07 的大纲只要求"她算出这批活能挣多少",没有给数;
  ch08 的大纲钉死了"收八百二"。模型在 ch07 自行编了一个数,到 ch08 必须服从大纲,于是对不上。

## 6. 仍然存在的问题

1. **跨章数字台账缺失**。产品侧 `fact_contract` 只校验称谓(`role_name_drift`),
   没有任何跨章金额/数量台账,第 5 节那类矛盾不会被任何机制拦下。
   探针这边的 `BOOK_FACTS`/`number_conflict` 也拦不住(名目不同)。
   这是"能否稳定产出可验收长篇"的下一个真缺口;补它需要产品级改动,本批未做。
2. 跨章时间**单调性**仍未实现:只校验"本章是否出现可定位时间的说法",
   不校验"第 7 章的时间不早于第 6 章"。需要认知账本 + 语义判断。
3. `number_conflict` 的名目抽取过粗,会误报,当前只能当提示用。
