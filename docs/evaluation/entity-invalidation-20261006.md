# 章节失效传播与旧事实清理（2026-10-06）

## 修复内容

此前正文来源检查能阻止草稿或已删除章节继续提取，但不能清除已经写进图谱的事实。删除章节还会级联删除提取记录，导致恢复任务看不到需要清理的对象。

- 新迁移 `a1001926` 建立 `entity_invalidations`。项目/章节 ID 不设指向作者数据的 FK，章节、卷、项目删除后待办仍然存在。章节来源更新/删除的 BEFORE 触发器保存旧作品归属；卷删除或卷序/归属更新在子章节变化前保存旧作品中的章节身份。和作者修改同事务，回滚不产生清理。
- 每个作品/章节只保留最新 revision，失败轮转后重试；Beat 每30秒处理至多50条。没有模型调用，也不依赖首次 broker 投递来创建待办。
- 清理和提取共用作品会话租约。既存章节/卷在核对来源及清理时加行锁；如果新图谱已经对应当前有效来源，保留新事实。图谱 marker 保留递增 token，阻止迟到的旧写入重新复活被删事实。
- 单个 Neo4j 事务删除该章节拥有的状态节点、关系及位置边，重算受影响人物时间区间。手工/未知来源的旧事实不批量删除，后章状态保留。
- 图谱提交后总会重试严格 PG 物化。此前关系清理分支吞掉异常，本批严格路径改为抛出，让任务保留待办。PG 失败不误确认；下一次从已清理图谱恢复，不重新调用模型。
- 新记忆卡写入 `source_chapter_id` 和 `source_hash`。重新编号后写卡会清掉本章旧编号卡；清理按章节身份和来源删旧卡，不按旧全书章号猜测归属。已经匹配当前正文的卡保留。
- 释放作者行锁后才按 revision 确认待办；期间作者再次修改会生成新 revision，旧清理不能确认新变化。外部取消传播并释放租约，保留可重试待办。
