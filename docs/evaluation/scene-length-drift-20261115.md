# 漂移怎么处理:召回不行,控制单次输出长度行(2026-11-15)

回应三个问题:**向量库能不能用、召回能不能治漂移、控制单次输出长度**。

## 1. 召回治不了这个漂移,原因是具体的

"漂移"这里指的不是"忘了上下文",而是**违反了某条已定事实**。举一个我实测到三次的实例:

| 章 | 正文 | 大纲 |
|---|---|---|
| ch07 | "三十套校服,每套二十八块,总共是**八百四十块钱**" | 只要求"算出这批活能挣多少",**没有给数** |
| ch08 | "当场点出**八百二十元**工钱" | 钉死"收下八百二" |

- 向量库召回的是**相关旧文**,不是**约束**。而且这个数是 ch07 现场编出来的,
  写 ch07 时它**还不存在于任何地方**可召回。
- 唯一能提供约束的是大纲(ch08 的 820)。**它当时就在提示里**——
  我重放过运行时的 `ContextPack`,ch07 的提示里确实有"第 8 章 收下八百二",模型照样没听。
- 那就"加个事后检查"行不行?我把这条路也验了:从 24 章大纲**自动抽"名目-数额"**当 pin,
  再逐章比对正文。结果:**漏掉这一处**,却报出 3 条误报(名目被抽成"把装着""的货款";
  "九百块的铺租 vs 八百块的铺租"这种正常涨价也被算成矛盾)。

```
ch03 「的货款」大纲={'七百'} 正文=七百块   ← 后缀差异误报
ch16 「的铺租」大纲={'八百元'} 正文=八百块 / 九百块   ← 涨租误报
命中 3 条,真实矛盾 0 条
```

所以:**召回不是校验;而"自动校验"需要能识别名目,纯正则做不到**(我删掉的正是这类检查)。
这条捷径不成立,别再往那个方向加正则了。

## 2. 控制单次输出长度:机制早就在,只是没被用上

平台**本来就实现了**分段生成:`SceneOrchestrator` 逐场写,每场都会重新注入
**完整系统提示 + 本场合同 + 本章此前已写正文**,还带一句明确的
"核对前文已经说出的时间、数量、人物知情和物件去向;它们不能随规划措辞重新变化"。

但**一章只写一场**:`_scene_count_for_target = round(target/1000)`,1200 字目标 → 1 场;
`MAX_SCENE_WORDS = 6000`,`MIN = 1`。规划提示还写着"简单章节可只写一场"。
于是**整章就是一次生成**,分段重注入这套机制一次都没生效。

我实测的每一轮都是这样:`plan.scenes` = **1 场 × 1200 字**。

### 改了什么

新增可配置的**单场输出上限** `SCENE_MAX_OUTPUT_WORDS`:

- 它决定推荐场数(`ceil(章目标 / 上限)`),并写进规划提示与校验口径;
- **默认 6000 = 维持现状**(整章一场),不改任何既有行为;
- 调小它(例如 600),1200 字章 → 2 场 × 600 字,每场重新注入约束与已写正文。

代码:[config.py](/root/ai-write/backend/app/config.py:95)、
[`recommended_scene_count`](/root/ai-write/backend/app/services/scene_plan_contract.py:51)、
[规划提示](/root/ai-write/backend/app/services/scene_orchestrator.py:219)。

### A/B(同大纲、同模型、10 章)

| | 1 场/章(对照) | 2 场 × 600(本臂) |
|---|---|---|
| 实际场数 | 1 × 1200 | **2 × 600** |
| **ch07 写下的工钱** | **880**(40 套 × 22 元) | **820** |
| **ch08 写下的工钱** | 820 | 820 |
| **是否矛盾** | **是** | **否** |
| 字数中位比 | 0.94 | **0.78** |
| 不足目标 85% 的章数 | 1/10 | **6/10** |
| `time_progress_missing` | 0 | 2 |

读 ch07 正文可以看到差别:一次生成 1200 字时,模型自己搭了一套
"四十套 × 每套二十二块"的算术并把总数写成 880;拆成 600 字的段之后,
它的写法变成"**按件数折算下来,这批校服做完能挣八百二十块钱**"——
直接采用计划里的数,不再自己推。

**一个实例,不是统计结论。** 对照侧的 880/820 我在三次独立运行里都复现过;
本臂目前 n=1,第二个 seed 的结果见文末。

### 代价:字数掉下来了

拆段本身不解决"每段写不够"。600 字目标下,模型每段只写 330–500 字,
两个 seed 的整章中位比是 0.78 与 0.89(对照 0.94)。所以这个开关现在的形态是
**用篇幅换约束遵守**,两个 seed 都还不能直接把默认值翻成 600。

## 3. 建议的下一步(按价值)

1. **先把每段的篇幅写足**(这是既有问题,不是本次引入):每段目标要真的落实,
   现在一段 600 字只写 350。补上之后 600 上限才有意义。
2. 再做**多 seed 复测**:确认"拆段 → 数字不再自造"是不是稳定效应
   (至少 3 个 seed,对照侧已有 3/3 的基线)。
3. 稳定之后再谈把 `SCENE_MAX_OUTPUT_WORDS` 默认调小;在 1 完成前不要动默认值。
4. 顺带:召回/嵌入服务**不能是写一章的硬前提**(见 ch19 的
   `character_cognition_retrieval_unavailable`)——这段材料在窗口里放得下,
   不该因为第三方超时卡住整本书。

## 4. 本轮改动的边界

- 默认行为**未变**(`SCENE_MAX_OUTPUT_WORDS=6000`),既有 110 项场景测试全绿;
- 新增 2 项回归(场数换算 / 上限必须写进规划提示);
- 没有引入新的模型调用,没有改大纲、没有改既有迁移。

## 5. 第二个 seed

同一命令重跑一遍(新项目 = 新提示):

| | seed 1 | seed 2 | 对照侧(3 次独立运行) |
|---|---|---|---|
| 场数 | 2 × 600 | 2 × 600 | 1 × 1200 |
| **ch07 / ch08 的工钱** | 820 / 820 | 820 / 820 | **880 或 840 / 820** |
| 是否矛盾 | 否 | 否 | **3/3 都矛盾** |
| 字数中位比 | 0.78 | 0.89 | 0.94 |

seed 2 的 ch07 写法:"做下来能挣九百块……**刨去这些零碎开销,真正能揣进兜里的工钱
大约在八百二十块上下**;八百二十块交了今天到期的八百块铺租,只剩二十块钱垫底。"
—— 毛利九百、净得八百二十、交租八百、余二十,内部自洽,和 ch08 的"八百二十元"一致。

**汇总:对照侧 3/3 自造冲突数字,拆段侧 0/2。** 方向一致且机理清楚,但样本仍小
(2 vs 3),不当成统计结论;要定论需要按 seed 成对复测。
