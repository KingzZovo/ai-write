# 桌面正文保存与生成交接（2026-10-09）

本批完成代码与可执行的离线验证，未部署。桌面编辑器现在按作品和章节保留稿件；保存比较完整原稿并等待提交确认。切章、后台刷新和旧生成事件不会直接替换另一章的编辑区。质量失败稿由作者核对，前端不再自行强行写回。

## 保存合同

- 新 `GET/PUT /api/projects/{project_id}/chapters/{chapter_id}/content`。读取实际保存正文，核对作品归属和回收站；写入要求完整 `expected_content_text`，沿用作品生成→资料→作品→章节锁。
- 缺前提428、改稿/占用冲突409、未确认提交503。返回保存的完整正文、实际字数、章节身份、状态和备份ID；明确提交后才派发提取。
- 只在作者明确允许清空/大幅缩短时使用 `force`，同时完整保留 `author_edit_backup`；force仍比较原稿。普通自动保存不每次创建全文版本，同稿不重复备份或提取，并纠正历史错误字数。
- 可明确将待保存候选保留为 `draft` 或 `needs_review`；该入口不允许直接传 `completed` 作为模型验收结论。已有完成章的普通作者修改沿用其原状态。

## 桌面流程

`chapterManuscripts.ts` 校验真实正文/回执，Unicode字数与后端一致。`chapterDraftSession` 每章只有一个保存序列；请求期间继续输入会保留新内容，下一次以已确认稿作为基准。冲突或未知结果停止自动重试，读取完整保存稿后由作者明确选择。

未保存稿和完整基准按章写入当前标签页的 `sessionStorage`，切章、组件卸载和刷新时可以恢复并核对。存储异常保留内存稿并明确提示下载；页面离开前刷新暂存。干净且不再使用的章节从会话目录释放，不因逐章浏览而长期保留整书正文。浏览器暂存有容量和生命周期限制，关闭标签页前仍需完成保存或下载；本批没有把浏览器存储当作500万字作品的数据库。

`ChapterSaveStatus` 提供实际保存状态、完整保存稿对照、作者选择和编辑稿下载。只读刷新保留未保存输入；明确“使用保存稿”才替换编辑区。正文响应、项目切换及大纲就绪检查都有来源隔离，未加载正文时不能误编辑空白稿。

`chapterGeneration` 持有本次生成对应的章节会话；取消、切章和结束后令旧事件失效。生成时暂停自动保存，`saved` 等事件只作为处理提示，结束后再读取真实保存稿核对；未确认或不同的候选保留供作者处理。移除旧 `quality_failed` 回调的前端PUT，不用模型检查结果或技术保存状态宣称小说已合格。
