# 设定提取状态与显式重试

2026-10-07。前端代码未部署，真实浏览器/API联调待网络恢复。

此前桌面确认书纲后以fire-and-forget调用extract-settings，只在控制台打印结果。失败不会告诉作者，界面也没有重试入口。

新增 `SettingsExtractionStatus.tsx` 的状态组件和请求hook，接入DesktopWorkspace：

- 确认书纲成功后自动发起原有提取，展示提取中、完成数量、失败和重试按钮；完成数使用API返回的三个非负整数，缺字段或非法计数视为未完成。
- 提取失败不撤销书纲确认，也不阻止作者核对已保存稿。只在作者点击重试时再次请求；已完成也可显式重新提取。
- 项目、书纲ID或书纲内容变更时中止旧浏览器请求并忽略迟到结果；同一请求运行期间同步重复点击不重复发送。
- 状态显示在工作区，切换视图仍可见；仅当前确认书纲对应当前加载记录时展示。刷新加载不自动调用模型，已有确认书纲可手动提取。
- 中止浏览器请求不等于撤销后端已提交数据。状态仅当前会话有效，不冒充后台持久任务；后端源核验和写入保护仍负责数据安全。

验证：前端18文件 **157 passed**（11.60秒），新增11项测试覆盖无自动加载调用、成功计数、失败重试、同步去重、项目/ID/内容变化、坏成功响应、合法零结果和卸载中止。TypeScript及diff检查通过。日志 `/tmp/aiwrite-settings-ui-tests.log`、`/tmp/aiwrite-settings-ui-tsc.log`。
