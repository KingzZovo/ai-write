# 实体提取版本、原子图谱写入与恢复（2026-10-06）

## 本批实现

旧ExtractionMarker按全书章号永久completed，正文改稿不触发新提取，甚至会混用旧图谱与新正文记忆卡。本批任务不再依据该标记跳过，改由来源绑定的PostgreSQL提取记录驱动。

- `entity_sources.py`：读取唯一章节身份与持久化正全书章号；无ID只能接受唯一匹配，不再取最高卷或计算章号。completed、非空正文、全书章号不重复才进入事实提取。来源收据覆盖作品/章节/卷身份、标题、局部与全书顺序、状态、正文哈希。
- `ChapterEntityExtraction` / 迁移a1001924：保存来源收据、已校验payload及其哈希、状态、错误类别、时间和投影token。原文不重复整章存储。相同正文/元数据版本可复用结果；正文改回旧版也使用新token写图。
- `entity_projection.py`：同作品使用独立PostgreSQL会话级advisory锁；连接租约在关键阶段核对，取消时释放物理连接。模型期间无章节行锁；模型后重新核对来源，先提交payload。写图/物化期间锁定来源章节及卷，避免作者正文在投影过程中变化。
- `entity_graph_projection.py`：完整payload在一个Neo4j事务中替换该章节拥有的状态/关系/位置，并提交source/payload收据。递增token阻止迟到任务覆盖新投影。失败回滚整个图事务；已有相同投影不重写。
- 只重算受影响人物的时间线。前章改稿不会错误关闭后章状态；新关系的并存角色（同事+朋友）保留，明确关系变化才结束原关系；作者明确的旧终止时间保留。旧无来源事实不批量删除。
- 严格物化调用复用同一Neo4j driver，内层PG提交失败也传播，不再吞错。状态读模型保存JSON对象、冲突更新状态与结束章号，位置更新结束章号；清理当前图快照已不存在的状态/位置键。每批最多500个删除ID。ORM补齐已存在于旧迁移中的6个唯一约束，与生产迁移语义对齐。
- 同一全书章号的记忆卡在重写前清除旧集合，包含正文删除的人名，不再只覆盖仍出现的人物卡片。
- `entities.replay_pending` 每60秒检查最多50条待办/已保留payload的失败记录/超过10分钟的running记录。图谱或物化失败可无模型重放；已经耗尽且没有payload的模型失败不无限重叫模型。回收发现新来源时先持久化替代待办，再淘汰旧待办，消息发送失败仍保留新待办。

## 本地独立复核

按shadow-mind的无可信只读隔离回退规则，完成实现及针对性测试后冻结代码，分别检查正确性和架构。

- 正确性复核发现：并存关系不能按单一关系轴相互关闭；手工终止日期不能被重算打开；过期回收记录须淘汰并保留替代待办；物化内层提交错误不可被吞掉。已修复并增加真实测试。
- 架构：来源解析、payload存储/恢复、图事务分开；模型结果可以独立重放，图写以章节ID拥有事实而非依赖局部章号，PG仅保存投影与控制记录，Neo4j仍是事实图谱。完整全量通过后未再改实现。

## 尚未完成的边界

1. **首次投递仍不是保存事务内的outbox**：记录在实体任务开始时建立；若保存后首次broker发送就失败、任务从未开始，当前回收器看不到它。须接入所有保存入口的事务待办。
2. **删除/草稿/跨作品移动还缺失效传播**：来源不再可用会停止新提取，但不会自动抹除既有图谱事实。章节FK级联还会删除历史提取记录，需独立tombstone/删除队列。
3. **读取来源校验尚未贯穿图谱、PG人物状态及记忆卡**：改稿提交至新投影完成之间仍有旧事实窗口。不能把本批原子写图描述成全文系统强一致。
4. **旧无来源事实仍保留**：已部署历史ExtractionMarker和图节点未清理，旧图迁移/隔离/重建须另行验证，不用今天正文给旧事实伪造来源。
5. **重新编号的旧记忆卡、人物首次出现记录/孤立人物身份、其它非本章五类实体投影**仍需治理。普通同章号重写已清理旧卡，不等于所有版本化卡片完成。
6. PG物化仍读取作品级图快照并处理投影键；受影响时间线虽有界到人物，500万字的规模时延尚未实测。未来宜以受影响实体增量投影，不以当前测试证明规模完成。
7. Neo4j与PG之间不是分布式事务；恢复依赖保留payload/收据。备份恢复须一并考虑token序列和图谱最大token，不能单独回退序列后继续写。
8. 模型输出语义真实性、中文长篇连续性、浏览器全流程及生产部署均未验收，目标继续保持未完成。
