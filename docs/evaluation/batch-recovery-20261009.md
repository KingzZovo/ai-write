## 修复的问题

上一批已经固定批次请求及每章来源，但进程可能在正文提交后、任务完成或批次进度提交前退出。把所有 running 任务重置为 pending 会重新生成已交付稿；只依据心跳超时接管，也不能证明旧进程已停止写入。

本批为新版执行增加独立 PostgreSQL 会话锁、执行版本、15 秒心跳、每次接管的 worker UUID、逐章尝试和正文保存证明。心跳过期 90 秒只是恢复候选，实际接管还须取得批次锁及共用作品命令锁，重新读取持久状态。原锁连接失效后不得悄悄重连；旧执行在 ORM 写入、显式行锁、Core DML 和异常 failed 更新中均须通过当前凭证。

正文保存证明与 Chapter 在同一事务提交，包含任务/执行身份、全文 SHA-256、字数、状态和稿件来源。稿件来源核对正文、标题、细纲、位置、目标篇幅及作者修改版本；派生摘要通过独立 CAS 更新，不改变正文交付证明。原始提交来源仍保留完整字段，未重建或放宽原请求。

## 恢复行为

| 持久记录 | 后续动作 |
| --- | --- |
| 子项已记录终态 | 保留当时观察，不重写正文或再次调用本章模型 |
| 任务完成、结果与保存证明一致，批次进度尚未提交 | 补记完成，继续原请求中可执行的后续章节 |
| 正文已保存，但任务未完成或结果不一致 | 保留正文和候选，进入待审，停止后续自动生成 |
| 存在进度、结果、润色候选或已输出字符，但没有完整保存证明 | 保留材料，待作者核对，不清空后重试 |
| 原稿/位置变化、任务来源缺失或尝试记录损坏 | 保留现有材料，待审，不补猜来源 |
| 没有交付，原稿完整来源仍一致，记录有效 | 复用原子任务和请求，最多 3 次尝试；恢复后再次退出但尚未开始本章不消耗新的模型尝试 |
| 已有待审、失败或取消章节 | 恢复时停止剩余章节，不自动越过问题继续写 |
| 清单缺项 | 不重建清单或任务；父批次待审，可证实属于该请求的游离活动子任务也停止等待 |
| 历史执行版本、缺失心跳、未过期、仍持实际锁 | 不自动接管 |
| 已记录 interrupted/cancelled | 不因周期扫描复活 |

核查历史逐次追加，保留原任务状态、错误及处理时间。GET 仍只读原批次；重复 POST 不主动接管运行中批次。新增 Beat 任务每 30 秒扫描一次，默认最多派发 32 个请求（上限 100），控制扫描使用既有 `pipeline-control` 队列，实际章节执行使用普通 worker。提交、派发或结果未确认时继续保留原编号；周期派发不改写正文，也不把 broker 回执当作生成完成。
