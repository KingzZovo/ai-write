# 旧兼容正文保存与组合更新

日期：2026-10-09。代码与离线检查完成；未部署。全项目目标仍未完成。

## 问题和改动

旧 PUT /api/projects/{project_id}/chapters/{chapter_id} 已有可选原稿检查和空稿/骤缩保护，但不强制客户端提供原稿，且在事务提交前通知实体提取。同一请求还支持正文、标题、细纲、摘要及章号，不能简单拆成两次保存而留下部分成功。

- 新 author_manuscripts.prepare_author_manuscript 统一获取生成互斥、资料锁、作品和章节锁，在锁内重读完整保存稿并比较。缺前提返回428，过期稿返回409；force仅放行明确缩短/清空。
- /content 与旧章节PUT共用准备服务和 author_manuscript_write 提交上下文。prepare只校验并暂存完整备份，不改正文、不提交、不通知；两个入口各自应用允许字段后一次提交。
- force明确替换且正文变化时保存完整旧稿、原标题与状态；正文不变只纠正字数，不新增备份或通知。
- 旧接口保留ChapterResponse，并在正文更新成功时增加完整 manuscript_receipt，含status=saved、保存稿、changed和backup_version_id。读取/纯元信息更新的该字段为null。旧客户端必须先读取完整保存稿，再发送expected_content_text；服务器不会补猜客户端原稿。
- 细纲版本或章号冲突、备份写入失败会撤销整个组合修改。提交异常统一返回chapter_save_unconfirmed（503）；已提交但回执丢失仍不能当作未保存，客户端应保留输入并重新读取核对。
- 只有显式提交成功后才通知实体提取。派发失败不反过来声称正文未保存；通知本身不代替数据库来源任务的恢复保证。
