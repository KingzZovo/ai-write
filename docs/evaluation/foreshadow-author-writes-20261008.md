# 作者编辑伏笔的版本保护与同步恢复（2026-10-08）

## 问题与结果

旧直接编辑接口先修改图谱，再调用默认不严格报错的全作品投影；投影失败时可能返回旧 PG 记录。更新也没有原版本比较，创建响应丢失后重试会产生新 ID。前端会吞掉创建错误、把读取失败显示成空列表，刷新或迟到响应可能丢掉编辑输入。

现在作者创建、编辑、手动兑现和删除都使用明确的操作身份。更新/兑现/删除核对原记录，已执行请求只读取处理结果与当前记录，不再重放旧修改；失败时保留输入并区分“尚未获得完成确认”和“已写图谱、列表待同步”。PG 自有记录可在图谱驱动未初始化时编辑。

## 接口契约与发布依赖

- 列表与写入响应新增 source、version。version 沿用伏笔来源摘要，覆盖类型、描述、登记章号、条件、计划、状态、兑现章号和来源；旧接近度不参与版本比较。
- 四个直接写入端点都要求 Idempotency-Key（UUID）。PUT、DELETE、POST /{id}/resolve 另要求 If-Match（响应中的 64 位小写 version）。缺失/格式错误为 422，内容或来源冲突为 409。当前前端已携带这些字段；其他调用方须同步更新。
- 创建的伏笔 ID 固定为该次请求 ID；同一编号重试保持相同的作品、对象、操作、原版本和输入内容。明确拒绝后，新的作者意图使用新编号。
- API 显式等待 SQL 提交后才返回 201/200/204；错误仅返回固定代码和中文说明。图谱成功但投影未完成为 foreshadow_sync_pending，无法确认完成为 foreshadow_write_unconfirmed；二者均为 503。
- 章号上限与 PG Integer 列一致，超出 32 位非负范围在请求校验阶段拒绝，避免先写图谱再因 SQL 溢出长期无法同步。
- 新表 foreshadow_write_receipts，迁移 a1001941（父 a1001940）。只存请求身份、内容摘要、来源与处理结果；伏笔删除后保留，作品永久删除时级联清理。非空时拒绝降级删除回执表，避免旧重试重新生效。静态迁移图唯一 head 为 a1001941。

## 写入、互斥和恢复

1. 直接写入先取得既有作品物化互斥，再锁定作品共享行，核对作品仍存在且未移入回收站。来源读取使用标量列及禁用 autoflush，避免用 ORM 缓存代替当前记录。
2. lifecycle 来源在伏笔行锁中比较原版本，修改和最终回执同一 SQL 事务提交。重复已处理请求不再修改事实；已拒绝请求即使原文后来恢复也保持拒绝。
3. neo4j 来源先提交 pending SQL 请求绑定，再重新取得物化锁/作品锁并复查处理状态，随后才允许图谱操作。此绑定防止图谱成功而 SQL 后续失败时，同一编号被改用于另一条本地伏笔。
4. 图谱以唯一请求回执写锁串行化重复调用，再锁目标节点比较实际来源摘要；创建、编辑、兑现或删除与 applied/rejected 图谱回执同一事务提交。回执独立于目标节点，删除后仍能识别原操作。
5. 投影读取当前图谱值，不用旧请求的目标值覆盖后续修改。投影和 pending→最终 SQL 回执同事务提交；发现另一来源或跨作品 ID 冲突时停止，不强行覆盖。建议确认 worker 复用同一单条投影实现。
6. 已应用图谱回执保留 sync_pending，SQL 成功后再确认。Beat 每 60 秒调用 foreshadows.replay_writes，恢复只读取并投影当前图谱值，不重新执行作者修改。失败指数退避至最多一小时；整批 300 秒、单条 60 秒，Celery soft330/hard360 秒。
7. 若 SQL 请求已绑定但尚未触达图谱，后台没有原操作正文可执行，也不自动代替作者重试；界面保留同一请求和输入供显式重试。这种情况没有成功响应。SQL 绑定不等于图谱修改已经发生。

## 编辑界面

- 编辑器独立于列表分组和刷新状态，刷新失败保留已有卡片与草稿，跨作品旧响应被丢弃。已发生变化的记录展示当前内容，作者核对后才能用新版本继续提交自己的草稿。
- 保存期间保留提交稿；迟到成功仅清理仍与原提交一致的草稿，不清空重新打开后输入的新稿。
- 创建尚未确认时保留原输入与请求编号，不改成另一次创建。重新打开的窗口持有原请求编号，即使旧窗口随后成功清理缓存，重试也不会产生新身份。
- 草稿和请求保存在当前浏览器会话的 sessionStorage；存储不可用时降为本页内存。清理浏览器存储或切换设备后，不宣称仍能恢复原草稿/请求。服务端已应用的图谱同步仍可继续恢复。
- 只改描述时，未修改的复杂条件记录原样保留，不把对象结构悄悄改成文本数组。类型、描述和条件都有明确标签；错误可见且输入保留。

## 验证与本地复核

最终 162 项后端测试通过：34 项新增作者写入测试、11 项更新后的生命周期入口测试，以及请求校验、图谱确认、建议保存/留存和证据入口回归。覆盖真实 SQLite SQL 与迁移、丢失 SQL/图谱提交确认、后续作者修改、删除后重试、请求跨对象误用、图谱两个旧版本竞争、来源改变、实际 ASGI 响应及无图谱驱动的本地写入。

前端完整 29 文件、266 项测试通过；本功能相关 42 项。新用例覆盖保稿、刷新失败、跨作品慢响应、明确核对新版、创建重试/重新打开、旧窗口迟到成功、兑现与删除重试、结构化条件保真。Webpack 生产构建通过，包含 TypeScript、20 页静态生成及构建追踪。

按 shadow-mind 在主实现与重点测试后冻结代码，分别进行本地正确性和完成度复核；平台没有可信的只读子代理隔离，因此未委派。复核发现并先用失败用例复现了“图谱不确定成功的编号可被改用于本地伏笔”，随后增加提前持久绑定并重跑回归。还核对了图谱缺席时的 HTTP 依赖、迟到创建确认、完整条件保留、代码实际接线和发布前置条件。最终实现指纹：62efbed986ac1e89ce58633c0658bd21243c3e57831311ad3902be3c8aab8a61。

## 尚未验收及下一步

代码未部署，a1001941 及前置迁移未执行。真实 PostgreSQL 行锁/唯一键竞争、Neo4j 唯一约束与锁行为、进程中断、Beat/Worker 恢复和真实浏览器交互仍未联调；SQLite 与事务替身不能替代这些验证。全量后端回归也未完成。发布须同时更新前端、后端、worker 和 schema；图谱历史重复 ID 须先核查，不能自动合并。

本轮只覆盖作者直接 CRUD 及共用单条投影。HookManager 的自动伏笔注册仍调用 ForeshadowManager.register_from_text/create，尚未接入本轮回执链；其正文完整性、来源版本与重复登记仍需核查。历史误标、混用章号、图谱/PG 旧差异、作品永久删除时的图谱节点与回执清理继续保留在计划中。

没有新增 CPA 模型输出或中文小说对照，也没有切换默认模型。真实 Gemini/其他端点的连续章评审、剧情完整性和文学质量验收仍未完成，不能据本轮工程测试认定中文产出已合格。
