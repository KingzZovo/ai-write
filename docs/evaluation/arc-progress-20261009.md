# 作者弧进度与具体保存稿确认

2026-10-09，基于 `c50f806`，仓库 `/root/ai-write`。本批把作者进度接到具体保存稿和实际章节身份，并接入桌面、移动端。源码与离线验证完成，尚未部署。作者点击确认、系统状态和测试通过都不替代中文小说编辑式验收。

## 问题与结果

旧 `chapter-written` 只收摘要，重复请求会继续增加计数；它没有说明作者确认了哪章、哪份保存稿。章序改变后，计数还可能指向另一章。旧“下一步方向”也没有章节身份，不能据此决定它应进入哪一章。

现在作者先读取完整标题和正文，再明确确认这份保存稿。正式进度由 `arc_progress_writes` 的追加回执拥有，不再写回旧 `Outline._arc` 计数。相同请求只返回原回执；稿件或安排改变须核对，旧确认、旧稿、作者说明和旧报告均保留。

这项改变支持中文作者实际关心的问题：哪一章已写到结果、人物和物件交接是否已落在正文、下章承接哪份稿。它不会用“模型分数高”或“章节数够了”判小说合格。继续采用[中文小说编辑标准](CHINESE_FICTION_EDITORIAL_STANDARD.md)和[已有 Gemini 实稿审读](editorial-planning-20261006/REVIEW.md)；本批没有生成新小说样稿。

## 最终合同

- 作者操作绑定作品、稳定卷章 UUID、当前完整大纲来源、章序及上次回执；确认稿件另逐字比较完整标题和正文。空稿拒绝，`draft`、`needs_review`、`completed` 均允许作者审读确认，不修改正文或章节系统状态。
- `acknowledge/retract/reconcile/direction/finish/reopen` 共用作品结构锁。回执、完整稿件快照、操作前来源和正式进度同事务保存；API 确认提交后才返回成功。提交不明返回 503，保留原请求，不能以新 UUID 重算。
- 改稿或改标题显示“待重核”；移出/删除已确认章须明确撤销，随后采用当前安排。首次核对前删掉部分原章节也不能自动缩短原计划。结束决定绑定当时的计划和章序，结束后改安排不能沿用原结束状态开下一弧。
- 方向绑定具体 `direction_chapter_id`。提前确认后章，不会把后章说明注入前章；章节重排不会把既有方向借给占用旧章号的章节。旧无身份方向只在首次完整历史中保留，作者明确指定后才重新使用。新建弧保留开场原材料，不再复制到旧方向字段。
- 当前读取最多处理本弧 40 章，选择当前完整卷纲；有有效写时正文指纹时无需回读正文，未知指纹只回读相关已确认章。列表不加载历史原稿。历史按稳定卷 ID 分页，删章/删卷仍可查，永久删书才由 Project 外键清理。
- 旧 `chapter-written/next-direction/complete` 返回 428，不能旁路新合同。`current/chapter-brief/next-arc` 使用正式进度，下一弧在规划前及保存锁内重验前弧来源。实际 `ContextPackBuilder` 已接线，作者前文说明和目标章方向作为完整必需材料预算，放不下明确停止。

新迁移 `a1001957 -> a1001956` 创建独立进度历史表；有历史时拒绝直接 destructive downgrade。SQLite 迁移/留存验证通过，真实 PostgreSQL 迁移没有执行。

## 作者界面与恢复

桌面写作栏与移动工具栏新增“弧进度”，可选择分卷、审读完整保存稿、确认/撤销、核对新安排、保存方向、提前结束或继续，并按实际章 ID 回到编辑器。历史弧目录包含已删除卷，历史详情支持全文下载。

界面复用现有按章草稿会话：有未保存稿、保存中、生成中或标题未核对时不能确认。用户勾选已读后，提交的是展示的那份完整保存稿。切卷/切章隔离迟到读取。

提交前把完整原请求暂存到当前标签页；断线保留 UUID、原来源、原正文和作者后来输入。POST 后再读取持久历史详情，逐字核对原稿、来源、说明及回执。旧回执只作为历史，不覆盖当前进度；当前读取不得早于已知序号。只有明确拒绝的请求才能由作者释放后重新核对；存储失败不发送，损坏暂存原件保留下载。

浏览器暂存并非服务器备份，容量也有限。前端行为入口仍未确认，41 项新增行为用例保留但未执行；类型检查和构建不能代替这些行为测试。
