# 章节移动后的大纲归属与前章衔接

当前阶段：本地实现、离线验证和冻结复核完成。基线提交 `cf30cf5`，本轮无新迁移；累计迁移头 `a1001943` 尚未执行，未部署。本轮未连接运行服务、PostgreSQL、Neo4j 或 CPA。

## 已核实的问题

- 章节顺序已能原子保存，但章纲、卷纲章节摘要和计划伏笔仍带旧章号，下一次生成可能串章。
- 细纲扩写存在数组下标回退；流式细纲保存上下文以章号减一寻找前章，遗漏稀疏编号和跨卷承接。
- 卷纲就绪检查、重新生成和编辑同步的归属判断不一致，部分仍只认旧卷号。
- 伏笔计划读取没有遵守作者原文修订淘汰旧结构的规则，旧计划可能重新进入生成上下文。

## 已完成

新增 `services/outline_order.py`，在结构操作原事务内维护章纲、卷纲摘要及计划伏笔的所属与当前位置。机器字段随稳定章节 ID 更新，正文、作者剧情文字、原始响应不改写。只读取章节位置和大纲；旧 stub 的完整内容先建摘要索引，再逐字比较，避免逐条扫描整书正文。位置版本时间保持递增。

新生成或作者明确指定的结构计划由保存端建立关联，不信任模型/客户端提供的内部 ID。旧摘要只在稳定关联或完整保存 stub 逐字一致时补关联；无法核实的条目原样留存并标记不可用。已失效的 ID 不回退到占用旧编号的新章节。无卷 ID 的旧卷纲按明确且唯一的卷号解析，卷移动时使用移动前的卷号；有可核实 stub 时优先据此确定所属卷。这不是对历史裸数字含义的全面修复。

卷纲就绪、扩写、正文上下文和重新生成统一优先稳定卷 ID，并使用一致的版本选择顺序。新版空计划不会借用旧版内容。细纲扩写和章摘要拆解移除数组下标回退；流式细纲优先当前章纲，并以同一份上下文快照读取、重验实际紧邻前章，覆盖稀疏编号与跨卷承接。

伏笔计划读取遵守 `_author_text_revision`，作者修订淘汰的旧结构不能重新进入提示词。已绑定的有效结构不再夹带原始模型响应中的旧编号或失效条目；纯文字计划及带空结构占位的文字仍完整保留。内部关联字段从提示与编辑文本中隐藏，保存时仍使用完整原版本核对。

卷纲编辑仍只同步“完整等于原 stub、正文为空、状态 draft”的章节。独立编辑的细纲和已有正文保留。不可用旧条目的原章号可以与新位置重复，保留这些历史条目不会阻止编辑当前有效章节；作者明确改定章号后可重新关联。界面提示暂不用于生成的旧计划，不将其删除或冒充已发生正文事实。
