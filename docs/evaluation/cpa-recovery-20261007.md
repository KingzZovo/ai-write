## MiMo 可用性排查

发现两个名称同为“小米”的供应商，分别指向标准 API 和 Token Plan。只读目录检查中，标准 API 首条凭据在 Bearer 和 api-key 两种头下均 200，Token Plan 首条均 401。目录成功不等于聊天生成可用。

另起本机 58317 隔离 CPA，独立 auth 目录，沿用已有客户端鉴权，关闭额外请求重试。两个供应商各取一条凭据，分别映射独立探针别名，聊天只请求“你好”、上限 128 tokens。未向共享配置写入探针别名。

| 标准 API 探针 | HTTP | 用时 |
| --- | --- | --- |
| 第一条凭据，供应商重名 | 402 | 0.86 秒 |
| 第一条凭据，改为独立名称 | 402 | 0.29 秒 |
| 第二条凭据，独立名称 | 401 | 0.08 秒 |

该结果不支持“改名即可恢复”的假设，也没有排除其他场景中的重名问题。402 的具体账号原因未经上游账户核实，不把它直接认定为余额不足。没有获得正文，不作中文写作能力排名，不更换备用模型。Token Plan 其余凭据没有逐一做生成测试。
