# 卷摘要与整书梗概来源校验（2026-10-06）

## 发现与行为

旧实现只要卷摘要存在便永不更新；整书梗概没有来源凭据，回写早期章节时可注入后卷结局。卷摘要还走独立router，整书梗概强截800字符。本批收敛这些路径，但不把来源一致性当作语义真实或文学质量证明。

- 新增 `aggregate_memory.py`。批量读取章节摘要与SQL核验结果，不把全书正文加载进Python。卷来源包含作品/卷身份、卷名/顺序、全部章节身份/顺序/标题/来源指纹；未完成、缺摘要、来源不符、未知或重复全书章号均不生成可信卷汇总。
- 迁移 `a1001923` 增加 `volume_summaries.source_manifest` 与 `source_hash`，哈希同时绑定来源清单与汇总输出。旧行保留原文且来源为空，不用今天的正文给旧摘要伪造凭据。
- 卷生成/刷新走Registry，模型IO前结束读取事务；保存前核对来源。短事务advisory lock串行化同卷提交，避免并发初建多行。已有有效摘要直接复用，失效旧行可刷新；迟到源版本不用于当前记忆。
- 整书梗概只从连续、全书章号有序的有效卷前缀生成，不能跳过未写或失效中间卷。settings中保存逐卷凭据和输出哈希。相同有效来源复用；并发修改项目设置时条件更新拒绝覆盖。移除800字符机械截断，模型输出仍受provider容量约束。
- ContextPack与旧HierarchicalMemory读取均核对当前来源和历史边界。包含当前/未来全书章号的卷汇总不能进前情；整书梗概含当前或未来卷时整体拒绝。章/卷改稿、增删章、改序、汇总输出被改都会失效。
- 模型期间若会话新增未提交修改，拒绝持久化，避免提交作者未保存内容。

## 本地独立复核

遵循shadow-mind无可信只读隔离时本地回退：主实现与测试后冻结代码，分别复核正确性与架构。

- 正确性：补充旧HierarchicalMemory全书边界、跨卷全书章号单调检查，以及模型期间会话出现待提交修改时不提交的保护；最终100项通过。
- 架构：章摘要与汇总分别由来源服务负责，统一Registry，无Prompt请求事务计数写入；批量SQL核对而非逐章读取正文。汇总来源与输出共同绑定，未知历史不静默认定可信。

## 未完成与限制

- 哈希只能证明“基于哪个版本生成”，不能证明模型摘要没有漏事实或造事实。本批无新真实模型文学验收；Gemini事实错误的既有结论不变。
- 读取校验阻止过期注入，但来源在最终检查后再变化仍可能留下随即失效的汇总。章节/卷修改事件的耐久刷新队列、失败重放和投影协议尚待实现。
- 当前过卷回填仅处理相邻前卷；更早卷编辑后的自动修复、全书批量恢复需接入版本化队列。来源失效会缺少汇总，不能把“未注入旧事实”描述成“记忆全部恢复”。
- 批量来源核验仍需数据库扫描相关正文以计算现有章指纹；500万字的时延/成本未实测，不能宣称规模验收。长卷输入容量失败将明确失败，不截掉中段。
- Neo4j实体版本/租约、Qdrant耐久投影、浏览器完整流程、中文长篇质量及部署仍未完成。
