# 共用润色默认提示更新

## 问题与更改

注册库的旧polishing默认要求增加视觉之外至少两种感官、交替长短句、生理反应代替情绪名词、关键时刻放慢叙述。与按原文及作者要求判断是否需要修改的标准冲突。seed_builtins跳过已存在task_type，单改源代码不能更新旧数据库默认。

抽出`app/services/polish_prompt.py`，注册库默认与后台完整原稿润色候选共用同一常量。新默认保留作者口吻、人物声音、视角、原文事实和结尾；无需为了配额编造细节，大纲保持层级。

迁移`a1001935_polish_default_policy.py`从a1001934升级，SQL只更新task_type=polishing且system_prompt逐字等于已知旧默认的行。端点、模型参数及所有自定义变体保持。迁移保存独立旧/新文本快照，不导入未来可能变化的应用常量。downgrade不恢复已知有问题的旧提示，也不覆盖后续作者修改；这是单向数据修订，无schema变化。应用回退不还原提示。

## 证据

37项相关离线测试通过。SQLite执行同一参数化UPDATE验证精确匹配、自定义保护、其他任务不变、路由参数保留、幂等及downgrade保留新提示；不等同真实PostgreSQL迁移验证。默认一致性测试核对注册库、候选服务和迁移快照。首次脚本替换曾造成Python语法错误，已修正，最终测试正常退出。

按shadow-mind本地两轮复核：兼容性检查确认seed不会改已有提示，故补精确数据迁移；数据保护检查验证只改system_prompt且不触碰用户变体。无可靠只读子代理隔离，未启动子代理。AST/diff通过。
