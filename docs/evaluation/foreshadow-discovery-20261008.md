# 正文伏笔候选与作者登记（2026-10-08）

## 问题与结果

旧 `ForeshadowManager.register_from_text` 只发送前 4000 字，用 512 输出 token 提取线索；模型和解析异常返回空数组，每项又以新 UUID 直接写成已埋伏笔。重复调用可重复登记，逐项写入可只成功一部分，正文改稿后也没有再次核对。实际入口仅在批量生成后的 HookManager；章节实体抽取不包含伏笔，新线索也不能靠现有图谱投影自动产生。

现在完成稿通过已接入的来源通知进入 `ForeshadowReviewJob`，批量保存的草稿和作者主动核查复用同一任务。任务读取完整保存稿，先形成有原句证据的线索候选，再运行已有兑现核查；两种建议、线索回执和任务完成状态在同一 SQL 事务提交。模型不直接新增已埋伏笔。作者核对后才能登记，候选说明不能代替作者判断。

## 中文编辑要求与模型边界

- 新增可配置的 `chapter_foreshadows` Prompt Registry 任务，初始化时沿用 extraction 的端点配置，不更换全局默认模型。新默认提示从人物回避、行动后果、具体异常及未解问题入手，要求读完结尾，不把普通细节、猜测、传闻或梦境升级成真实秘密，不规定伏笔数量或回收时限。
- 输入是完整正文，总提示预算为 24000 字符，包含实际注册提示及补充说明；超出时明确失败，不截取开头、删尾或漏读。输出预算为 4096 token。严格校验整个 JSON 数组、字段类型、重复项和逐字引文；引文必须能唯一定位。任一项不可信即拒绝整批，明确截断/过滤/工具结束也不能算成功。
- 合法 `[]` 表示这一轮未提出候选，仍会留下回执；调用失败、格式失败和超预算保持任务失败。原句匹配只证明取材来源可核对，不证明文学判断正确。
- 没有前文时不能断言线索首次出现；界面明确请作者对照已有记录。跨章节同义线索没有通过字符串或模型分数自动合并。

## 持久记录、来源与重试

迁移 `a1001942`（父 `a1001941`）新增 `foreshadow_discovery_runs`、`foreshadow_discoveries`，以及 `foreshadow_review_jobs.discovery_count`。未执行此迁移，未发布。

- 回执按作品、章节 ID、卷 ID、卷内/全书位置及完整正文摘要去重，保留候选或成功空结果。候选用同一回执下的证据位置获得固定 ID。重复执行不会合并两份不确定的模型清单，也不会重置已忽略或已登记的决定。
- 改标题或将同稿从草稿转为完成，不会重新打开已处理线索。恢复完全相同的正文与位置会复用原记录。worker 仍校验更严格的来源通知 revision、保存来源及执行 token，防止旧任务提交。
- 模型调用期间不持有章节行锁。最终提交锁定章节/卷和当前任务，再复核完整来源；建议、回执和任务完成共同提交，任何一步失败共同回滚。已有 300 秒处理上限、三次自动尝试和 60 秒 Beat 恢复继续生效。
- `discovery_count=NULL` 表示旧任务只做过兑现核查；`0` 表示本稿线索核查成功但没有候选。界面分别展示，空列表不被解释成核查成功。
- 章节或卷删除后保留候选、原句与首次处理账号/时间；删除作品时通过项目外键级联清理。非空回执表拒绝直接降级删除，避免遗失处理证据。

## 作者登记和图谱来源

`GET /api/projects/{project_id}/foreshadows/discoveries` 支持处理状态、分页和来源标签；`POST /discoveries/{id}/accept`、`/dismiss` 显式等待提交后才确认。404 表示候选不在该作品，409 表示状态、来源、作品或登记身份冲突，503 表示没有获得提交确认；错误响应不含底层异常正文。

登记取得既有物化互斥及项目共享锁，重新锁定核对章节正文、位置和候选状态，然后用候选 ID 创建 PG 自有 `source=lifecycle` 记录，并同事务记下作者决定。登记章号来自持久化 `Chapter.global_idx`；不替作者生成未来回收条件或蓝图。若该 ID 已被直接图谱创建请求绑定，拒绝抢用。确认不会调用带内部提交的跨库作者写入助手，避免提前释放章节锁。

确认重试只承认已记录的首次决定。作者随后编辑或删除伏笔，旧确认不会重放内容或重新创建；忽略也保留首次账号/时间，并允许处理来源已经过期的候选。

本地复核还发现旧整批图谱投影会更新 `project_id/source`，同 ID 可覆盖 PG 自有记录。现有通用批量助手增加可选更新条件，伏笔调用改用 `project_foreshadow_rows`：仅更新同作品且来源为 neo4j 的行，逐批核对所有 ID 的归属，遇到未知/本地/其他作品来源冲突整批回滚。未变化值仍跳过更新；保留原 JSONB 比较和参数数量预算。其他实体的默认批量行为保持原接口兼容。

## 作者界面

共用伏笔面板展示“正文线索候选”和“兑现核查建议”。候选提供原句、说明、全书章号、来源状态、登记/忽略和历史筛选；来源过期或读取失败时不能据旧标签登记。提交确认之前保留证据，重复点击共用同一候选 ID，跨作品迟到响应不刷新新作品。读取失败保留已有证据并明确报错。登记记录删除后仍能查看核对历史。
