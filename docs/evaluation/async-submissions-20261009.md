# 异步生成提交与作者原稿保护（2026-10-09）

本批完成代码、离线回归和本地冻结复核，未部署。解决响应丢失后重复建任务、排队期间改稿被执行时当作新基准、派发返回覆盖取消状态，以及旧批量入口与新保护不兼容的问题。

## 提交与执行合同

1. 普通 `/api/generate/async` 和旧 `/api/outlines/from-reference/start` 共用 `generation_submissions.submit_generation`。客户端固定 UUID 直接作为 `GenerationTask.id`，请求摘要绑定作品、任务类型、参数与完整正文前提；同编号不同请求返回 409。重试已受理请求只读取原任务，pending 可再次投递同一个编号，不建立新基准。
2. 新正文任务要求作者看到的完整 `expected_content_text`。作品/章节锁内重读并逐字比较，缺前提 428、正文变化 409；明确提供的卷号/章号与当前章节不符返回 422。提交来源摘要覆盖整篇正文、标题、细纲、章序、摘要来源、状态及目标字数，任务参数只保留有界摘要。
3. 数据库提交确认后才 `apply_async`，Celery ID 与任务 ID 相同。提交等待上限 30 秒、派发等待上限 10 秒；未获确认返回 503 和原任务编号，不把可能已运行的任务改成失败，也不在派发后写回旧 ORM 参数。
4. Worker 以数据库 `pending -> running` 条件更新认领，认领提交确认后才开始生成。正文在共用作品执行锁内重验提交来源；取消后的任务结果/参数写入被拦截，迟到回调不抹掉取消标记。取消先锁内重读并确认提交，再尝试 revoke；待审、待修也属于终态。
5. 批量入口在第一章执行前固定全部选章的来源，不能轮到第二章时再采用作者的新稿。读取刷新 ORM 缓存且禁用 autoflush，细纲/配置使用独立副本。整书适配器仍走已有 pipeline 执行凭证，没有误套独立任务来源要求。
6. 旧参考小说入口要求固定请求编号，使用共用提交与派发；其轮询接口返回作品/任务类型，拒绝其他任务类型，并遵守取消标记。源码内没有发现此旧端点的当前前端调用者；外部调用方仍须升级合同。

## 桌面与移动工作流

`GenerationSubmissionSession` 按作品保留一份未确认请求，发送前将原始 JSON 字符串和固定编号写入本页 sessionStorage。刷新、切作品或响应丢失后，重试仍使用原请求和原稿；回执逐项核对任务、作品、类型、章节和卷号。45 秒本地等待结束也保留请求，只有明确拒绝允许主动清除。

暂存失败的处理区分“首次尚未发送”和“此前已发送但结果未知”；后一种不能被当作未发送而丢弃。暂存读取失败继续阻止新请求，浏览器记录不是服务器稿件备份或自动灾后恢复保证。

桌面任务队列改读最近列表和活动列表，取消逐个活动任务获取候选全文的 N+1 请求；列表读取串行、限时并隔离作品与请求序列。受理/取消回执使旧读取失效。两端合并并行列表时保留终态，较旧的活动状态不能覆盖已完成/失败/取消/待审/待修。移动恢复共享会话回执后重新读取完整任务列表。
