# 伏笔审阅从正文证据进入（2026-10-08）

## 问题与修正

旧入口只核查 ready/ripening；普通 planted 记录即使正文已经回答悬念，也无法进入“建议→作者确认”的流程。此前图谱确认报告将此归为 update_proximity 只写 PostgreSQL，但后续检索未发现该方法及其解析器的仓库调用者。继续增加分数同步不能解决实际入口问题，也会强化模型分数决定收线时机的错误前提。

本轮删除无调用者的成熟度计算方法及阈值，保留历史字段和状态兼容。审阅、作者确认和历史核对共用 planted/ripening/ready 集合；planned/pending/resolved 仍不进入自动核查。没有自动将旧记录改为“已推进”或“已兑现”。

## 已实现行为

- 已埋伏笔即使旧分数为 0，也可从已保存正文取得带连续原句、位置和来源摘要的建议，再由作者确认。PG 来源同事务确认，图谱来源沿用持久确认请求/回执/恢复流程。
- 每次请求最多 8 条线索，各批保留完整正文；所有批次先通过 24000 提示字符预算检查再调用模型，不截稿、不跳过超预算条目。多条响应必须逐条返回精确 ID 和布尔结论，包括否定项；遗漏、重复、外来 ID、无效引用或明确截断均失败。
- 全部调用结束后重验所有候选的来源摘要，包括没有提出兑现建议的条目。模型仍只能提出建议；原句存在不等于文学上的兑现完整。
- 生成提示不再按分数催促近期收线或禁止新伏笔。线索资料以待核对条件和可选计划呈现，承认认识、关系和局势变化也能构成叙事回应，不要求每次揭晓都有外部动作。
- ContextPack 的 CFPGTriplet 不再用接近度生成“接近消解/发酵中”标记，伏笔按登记位置和 ID 排序。旧债务计算仅决定是否提供回看提醒，不将分数或章数间隔当作进展判断。
- 界面移除接近度百分比/进度条，ready 改为“待核对收线”。HookResult 只声明提供参考文本，撤去未经实际接线证明的“已注入上下文”提示。
- 真正执行 SQL 的 SQLite 用例暴露了 UUID 列传入字符串导致的绑定失败；ForeshadowManager 项目条件统一绑定 UUID。

## 验证与复核

- 156 项后端测试通过，覆盖真实 SQLite 候选选择、证据保存、作者确认及历史读取；图谱 worker 替身完整流程覆盖 planted 和 ready；另覆盖 19 条线索分 3 批、预算拆批、后批超限前零调用、批次漏项/重复/外来 ID/错误原句/非布尔结论、否定结果期间来源改变。
- 31 项前端测试通过，包括“旧分数 99% 不显示进度、不宣称该收了”及既有审阅/恢复交互。
- Next.js Webpack 生产构建通过：TypeScript、20 页静态生成和构建追踪完成。
- 按 shadow-mind 冻结主实现后在本地分别复核正确性与完成度；平台没有可信只读子代理隔离，因此未委派。复核确认各确认入口使用同一状态集合，分批先全部预检，再全量来源复查。发现并修正 HookManager 的过时注释和“已注入”提示。
- 实际生成主链使用 ContextPack 的 CFPGTriplet 和债务提醒；没有找到 HookResult.foreshadow_prompts 的独立消费处，不能把其参考文本声称为所有生成入口都会使用。

## 边界与后续

本轮无数据库迁移，代码未部署，已有 a1001940 等待执行。测试使用离线/SQLite/图谱事务替身，没有证明真实 PostgreSQL/Neo4j 跨库并发、Celery 故障恢复或浏览器完整交互已经通过。

候选范围扩大后，长书核查仍可能达到 worker 的 300 秒上限；分批不等于吞吐和费用验收。旧章号混用、旧误标状态、图谱与 PG 历史差异、直接 CRUD 的同步恢复仍需处理。本轮没有新的 CPA 输出或小说对照，不能据工程测试宣称中文正文质量已经合格。
