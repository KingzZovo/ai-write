# 逐章状态变化与字段来源（2026-10-06）

## 问题与修复

旧状态写入把前章累计状态与本章变化合并，再用本章来源哈希标记整行。例如第一章写“筑基”，第二章只写“平静”；后来第一章改掉修为，第二章的合并快照仍携带“筑基”，仅核对第二章来源无法发现。

- VersionedTimeline只合并同一章节、同一来源中的多次变化，不再从前章复制状态字段。图节点标 `source_mode=chapter_delta`，写入仍使用原子图事务与token。
- 累计状态改在读取时按有效逐章变化、逐字段合并，最新明确值胜出，并保留每个字段对应的章节ID、来源哈希和全书章号。前章来源失效时，只移除依赖它的字段，后章自己的变化保留。
- 状态变化历史不再以整条事件的chapter_end过滤，也不取前2000条截断；某条变化的事件区间结束，不代表它写下的全部字段同时失效。关系/位置读取维持原有区间语义。
- 显式null保留为未知值，不从旧章字典中恢复。ContextPack覆盖对应的修为/心理字段时，也不会把旧profile值继续留下。
- PG和Neo4j累计状态、生成前死亡检查复用同一字段合并规则。PG查询可按本次角色集合缩小范围。
- `a1001928`新增PG `character_states.source_mode` 和提取记录 `projection_version`。旧合并状态不伪装成delta，读取先排除；图marker增加schema_version=2，重放同一来源/同一payload也能强制升级旧格式。
- 既有恢复任务接入completed但旧版本的保留payload记录；验证payload哈希、schema和原文证据后才投递升级。正常升级不再调用模型。损坏payload被标记 `InvalidRetainedPayload` 并清空失效缓存，避免升级形成模型调用循环。
- 图已升级但PG版本仍旧时，仍执行物化和卡片写入，完成后才把记录标为projection_version=2。
