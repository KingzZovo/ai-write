# 批量生成固定请求与持久进度（2026-10-09）

本批完成源码、后端离线回归和冻结本地复核，未部署。旧批量接口把批次编号和结果保存在内存中，重复提交会创建另一组任务；现在以客户端固定编号保存整个批次，断开后可读取原进度，重复原请求不重新生成已受理的章节。

## 请求与执行

`POST /api/generate/batch` 新增必需的 `request_id`，每项 `chapter_configs` 必须包含完整 `expected_content_text`。可选的卷 ID、卷号、章号及细纲必须与当前资料一致；未知字段、重复章节、错误归属和无效目录拒绝受理。缺前提 428，原稿或请求冲突 409，无效请求 422，目标不可用 404。

作品、目录和章节锁内按实际卷章序核对整批，复用 `prepare_generation_submission` 的单章来源及就绪校验。所有子任务、原稿来源、章节顺序和批次回执同事务创建；其中一章不符即整批回滚。正文只进入请求比较及摘要，批次进度不额外保存整份原稿。

父批次使用客户端 UUID，子任务使用由批次和稳定章节 ID 推导的固定 UUID。原请求摘要包含完整作者原稿和指令。重试先读取原批次，不以执行时新稿重建来源；相同编号不能绑定不同章节、原稿、作品或要求。

仅 `pending` 批次可以原子认领，确认提交后才继续。子任务带内部批次来源，只有所属批次当前执行凭证可以按序进入既有 `_run_guarded_generation`；普通投递不能独立启动这些子任务。单章 HTTP 也不能伪造批次标记或重建私有子请求指纹。实际生成仍核对每章原始提交来源、共用作品锁并进行单次认领，没有新增正文 Prompt 或另一套生成器。

受理等待上限 30 秒。受理、认领或进度提交未获确认时保留原编号，返回 503 或 SSE `unconfirmed`，不把数据库可能已经提交的工作再执行一遍。子任务结果逐条保存，避免每章都重写整个批次的 JSON 数组。

## 读取、中断与作者稿件

`GET /api/generate/batch/{request_id}?project_id=...` 只读取原批次。SSE 的受理与终态事件携带批次编号，每章事件携带稳定章节和任务 ID。重复请求遇到运行中批次会返回已知进度；该响应的 `[DONE]` 只表示响应结束，不表示批次或小说已完成。

断开时先等待当前执行退出，再保存中断结果、取消尚未开始的子任务。已确认的终态记录保留；已完成章节进入后处理后，取消或作者继续修改不会覆盖此前进度。预后处理和进度观察器的故障不撤销已保存正文。中断或已结束批次的重复请求只读原记录；重新生成需作者核对稿件后另建请求。

持久进度是当时的任务观察，不承诺当前正文仍未被作者修改。最新稿件仍从完整正文接口读取；任务 `completed` 也不是中文小说合格证明。

章节或单个任务删除后保留批次项的原身份和观察记录；永久删除作品才级联清理。清单缺项明确报错，不静默减少总章数或重建丢失记录。

仓库当前没有此前批量 HTTP 接口的前端调用者，本批没有新增前端界面。外部客户端和直接调用 `BatchGenerator.generate_batch` 的调用方必须升级固定编号与逐章原稿合同。旧类内存中的 `pause_job`、`resume_job` 没有仓库调用者，随内存批次实现移除；本批未提供新的恢复入口。
