# 弧规划中的人物材料（2026-10-09）

本批将当前人物档案、逐字段正文状态、有方向的关系和位置接入弧规划的实际调用、修复、恢复及原件审阅。完成源码与离线验证，未连接 CPA 或运行服务、未部署，也未更换默认模型。

## 实际行为

- 新规划来源为 `version=4`，保留 `book_context=2`，增加独立的 `character_context=1`。从当前 Neo4j 读取人物材料，不以 PG 旧投影补回被修改或清空的档案。
- 保存原始 `profile_json` 字符串和真实图谱节点身份；作者编辑、出处未确认的旧登记分别标明。允许历史空 ID/未知来源；明确的作者空对象保留为空。坏 JSON、重复字段、非有限数、同名不同节点等无法核对的材料停止读取，原件保留。不同姓名使用相同称谓或别名仍全部保留。
- 新弧边界来自真实卷章位置：实际最后卷号加一、最大全书位置加一；校验正数、唯一性和卷内/全书先后。不为借用上下文创建假章节，也不猜未知位置。
- 状态按每个字段保存其正文出处，保留 `false`、`null`、零、数组和对象；空后章变化不会给早章字段重新标注来源。同章同字段存在冲突值时要求核对。
- 关系保留原方向、完整措辞、已有原句及待核对的结束范围，作者关系单独作为设定。位置先核对来源再选择最后有效章节，修复失效后章的旧结束位置遮住早章记录、全局 2000 条截断的问题。同章多项位置全部保留，不按返回顺序决定当前位置。
- 元信息、章节批次、失败修复和恢复使用同一完整人物材料；来源变化停止旧规划，暂时不可读保留原阶段和预算。旧 `version=1/2/3` 原件仍可读，不能补造人物来源或重置预算。既有“全书创作材料”面板直接显示实际全文，无前端改动。

## 保存互斥

最终来源核对在既有作品结构锁内，再按 Volume、Chapter 取得行锁。正文实体发布已有的来源锁与此互斥；书纲设定交付和关系编辑继续使用其原有保护。

人物保存/删除及会创建人物节点的位置、组织写入增加 Project `FOR SHARE`，核对作品存在且未删除。图谱操作完成后先释放该锁，再调用另一连接的 PG 投影，避免与规划的 materialization → Project 顺序形成等待环。取消时排空回滚；条件保存、明确清空、固定删除编号及同步待恢复合同保留。位置/组织错误不再向 HTTP 暴露底层诊断。

这些保护约束应用内正式写入路径；并非两个数据库的原子事务，也不能约束外部直接修改图谱。真实锁竞争仍须运行验证。
