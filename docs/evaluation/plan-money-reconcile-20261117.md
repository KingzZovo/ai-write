# 计划层金额收敛:ch07/ch08 的工钱总额终于一致(2026-11-17)

## 1. 问题:字段治好了写手,没治好规划者

上一轮加了 `SceneBrief.money_totals` 之后,写手不再自己发明金额;但**规划者**会。
真实两章链的规划响应里:

- ch07 计划:`校服工钱=八百四十元(三十套 × 每套二十八元)`
- ch08 大纲:`周芸收下八百二`
- ch08 计划:`校服工钱=820元(...)`

两个阶段各自自洽,读者看到的仍是相邻两章对不上。约束必须下在**计划**这一层。

## 2. 改法:与大纲冲突的计划金额条目丢掉(不阻断)

新增 [money_plan.py](/root/ai-write/backend/app/services/money_plan.py) 的
`reconcile_money_totals(money_totals, pinned_text)`:

- 把计划里的金额按**条目**切分(分号 / 逗号 / 顿号 / 换行);
- 条目里**出现了大纲写过的数** → 保留;与权威集合**完全不相交** → 丢掉;
- 丢过东西就追加「以大纲已定的金额为准」,免得写手在多个数之间二选一;
- 大纲侧没有任何金额 → 原样返回(没有权威值就无权改计划);
- **不抛错、不改 status**:金额对不上不该让整章写不出来。

挂钩在 [scene_orchestrator.plan_scenes](/root/ai-write/backend/app/services/scene_orchestrator.py:388) 的
`validate_output` 里,三个调用路径共用。

## 3. 验证过程中发现并修掉的两个真缺陷

| 缺陷 | 现象 | 修法 |
|---|---|---|
| 只按分号切条目 | ch08 计划写成「工钱=820元(…), 铺面租金=800元(…), 结余现金=20元(…)」,被当成**一条**,于是 820 跟着被丢 | 分隔符加逗号(半角/全角) |
| 权威集合漏了**本章自己的大纲** | `numeric_pin_lines()` 只列"其它章"的数,于是 ch08 的 820/800 被判成"无出处",整串丢掉 | 权威集合并入 `pack.current_outline`;判定也从"非子集"改成"**完全不相交**" |

第二条尤其说明问题:如果不把本章大纲算进权威集合,"**照本章大纲写的**"会被判成自造。

## 4. 结果:同名目的漂移修好了

同一项目重生成 ch7/ch8(各 `status: ok`),用 `compare_arms --amounts` 量:

```
[chain4] ch07 总额=[820, 400]  ch08 总额=[820, 820]  冲突=1  二十件校服工钱总额=400
```

- **校服工钱总额:ch07 = 820 = ch08** —— 原来那个 840 / 880 的自造数不再出现;
- 剩下被标出的 `400` 是 ch07 **新引入**的"另一批二十件校服",ch08 没提;这不是与已定数冲突。

改动前同一位置是 `ch07 总额=[840,840,840] vs ch08 [820]`,同一名目直接对不上。

## 5. 仍然存在的边界(必须说清)

`drift_against`(以及写后核对)**分不出"新引入的项"和"与已定数冲突的项"** ——
两者都表现为"这个总额在计划/后章里没有"。实时例子就是上面那条 `400`。

要分开这两类,需要一份**按名目持久化的金额台账**(第一次写出即登记,后续只比对同名目)。
本批没做。因此:

- 写后核对现在**会**对每章新引入的金额报一条 —— 它是"计划未记录"的提示,不是"写错了"的结论;
- 只要同名目的数一致,就不会再报那条真正的漂移(本轮已验证)。
