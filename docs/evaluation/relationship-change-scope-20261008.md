# 关系变化的确切结束范围

2026-10-08。修复单条关系变化关闭同向人物全部旧关系的问题，已完成源码和离线验证，未部署。Gemini路由与默认模型未改动，本轮没有新的模型样稿或文学合格结论。

## 问题与实际行为

原来的图谱区间修复和写作上下文折叠都把一次`changed_relationships`视为结束这两人此前的全部关系。先失败用例中，CH-900的“兄妹、同事、朋友”在CH-901登记“敌对”后只剩“敌对”。证据：`/tmp/aiwrite-rel-scope-20261008-red.log`。

现在的处理如下：

- 新抽取必须明确给出`replaces`数组，只能引用已核对来源、位于本章之前、同方向人物对的具体旧记录。未知ID、跨人物或反向引用、重复引用、同章重复类型及无法逐字定位的引文会触发最多一次格式修复，仍不合法则失败。
- 引用身份绑定作品、原始端点、完整类型、来源章节ID和来源摘要；不使用Neo4j内部ID或规范化关系词代替。图谱重建可恢复相同来源的引用，改稿或章序变化后的引用不转向新的同名记录。
- 图谱和来源核对后的上下文只结束被明确引用的记录；重复观察到完全相同的类型和完整描述时采用较晚记录。不同限定语和并行类型分别保留。同章的多个新变化可以共同结束同一条前文记录。
- 旧缓存缺少结束范围时不重新推测，也不自动调用模型补出目标。较早关系和变化均标注待核对，保留最新待核对变化的来源；即使该变化类型后来再次出现，旧关系上的待核对说明仍能追溯原句。显式`[]`表示没有明确结束其他登记记录，不能据此猜测它们不存在。
- 抽取输入、图谱和写作材料保留完整引文。引文再次经过完整来源正文核对；写作上下文的必要关系块超预算时明确失败，不裁掉限定语或原句。模型明确报告截断、过滤或工具结束时，JSON即使能解析也不写入。
- 作者设定不进入自动结束候选。作者修改后移除正文引用ID、结束范围和引文，原依据仍保存在历史中；作者删改一条结束事件时，同事务重新计算受影响的自动区间。旧来源重放仍受上一阶段的作者抑制记录保护。

新规则在每次调用的实际用户提示词内提供，并继续使用`run_text_prompt`及Prompt缓存；不覆盖作者的Prompt资产或路由。关系候选来自当前图谱，经过PG来源核对后复制为普通数据，读取会话在模型调用前关闭。

## 投影升级与性能

图谱`schema_version`及PG`projection_version`统一升级为3。恢复筛选包含已完成的旧版本记录，重用已验证的持久抽取结果。旧关系ID以每批200条补齐；没有新增SQL迁移。当前源码迁移头仍为`a1001944`，累计迁移尚未在真实PG执行。

冻结复核发现新折叠逻辑最初每章都复制全部有效关系，造成重复扫描。现改为按完整类型和确切引用ID直接查找、删除，最后一次性附加待核对说明。

5000条跨章关系加1条定向结束的同一测试，纯函数耗时从2.550260秒降至0.203720秒，结果保留4999条朋友记录和1条变化。日志为`/tmp/aiwrite-rel-scope-20261008-perf-before.log`、`/tmp/aiwrite-rel-scope-20261008-perf-after.log`。这是本次函数测量，不是500万字整书或真实数据库性能验收。

## 按中文作者/编辑标准看变化

用例的后章原句是“以后别再提朋友二字；衙门的差事照旧”。这句话支持结束私人交情，也明示公事仍需照办；代码不应替作者把人物改成已经离职，更不能凭“反目”抹掉兄妹身份。

后续正文是否合格，仍要看人物为何继续办差、愿意交出多少信息、如何回应或回避对方，是否承接翻脸后的情绪和关系距离。只保留三个正确标签，或把标签复述一遍，都不能证明人物写活了。这里分析的是构造的测试材料，不是新生成章节的审读结论。

继续沿用[中文作者/编辑验收标准](CHINESE_FICTION_EDITORIAL_STANDARD.md)及其中已记录的公开小说阅读范围；本轮没有新增互联网取样。已有CPA核查包含`gemini-3.1-pro`，但先前Gemini候选存在限知视角越界而自动评审给满分，另一模型也存在动作目的和交接问题，见[完整章节对照](context-guidance-20261007/REVIEW.md)。不能据模型名或自评分认定全量切换就能合格。
