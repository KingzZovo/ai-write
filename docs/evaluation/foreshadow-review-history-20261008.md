# 伏笔建议历史与确认后来源核对（2026-10-08）

## 问题和结果

已确认建议保留的是确认前快照。原读取逻辑将当前“已兑现”与快照中的 ready/ripening 直接比较，作者正常确认后也会显示来源变化。

现在仅对 accepted 且原来源为 lifecycle、原状态为 ready/ripening 的记录，按照确认操作的确定性变更（status=resolved、resolved_chapter=该快照全书章号）计算比较值。原快照、摘要、原句和说明均不覆盖。当前章节版本、正文、伏笔描述/条件等其余字段仍必须一致，原句位置仍须有效，才返回 accepted_current。该状态只表示读取时与确认结果一致，不声称期间从未修改。

界面新增待审阅、已确认、已忽略筛选，切换后从第一页读取；历史视图保留原句及来源标签，隐藏确认/忽略按钮。处理请求未结束时禁用筛选，避免旧操作回包与新历史视图相互干扰。服务端状态仍为最终依据。

## 验证与复核

- 71 项后端测试通过：确认后正常匹配、后续正文/描述/兑现章号变化、重新开启、摘要损坏、原句损坏、原快照保留、作品隔离和既有保存/请求路径。
- 25 项前端测试通过：历史筛选、分页归零、历史不提供写操作、空状态及既有核查交互。
- Next.js Webpack 生产构建通过（TypeScript、20页生成、构建追踪）。
- 按 shadow-mind 在冻结实现后进行本地正确性和完成度复核；无可信只读隔离，未启动可写子代理。确认读取不修改历史、不放宽 pending 接受条件、图谱副本不能被本分支报告为权威确认结果。

## 仍未完成

真实 PostgreSQL、浏览器和部署验收未执行；本轮无新增迁移。图谱来源确认仍需可靠同步方案。建议历史不是完整操作审计：没有处理人/处理时间字段，章节或伏笔被删除时现有外键级联会删除记录。完整审计留存、旧误标状态处理、跨章正文质量评测与 CPA 实测仍在整体计划中。
