## 一、它的工作流(用户视角,11 步)

| 步 | 用户动作 | 阶段 | 产物 |
|---|---|---|---|
| 1 | 配置模型(一个文本模型即可) | 系统配置 | 模型路由 |
| 2 | 输入一句灵感 / 选灵感卡 / 热门题材 / 拆书 | 灵感对齐 | 导演任务,候选输入 |
| 3 | 点"生成第一批方案" | 方向候选批次 | 多套候选方向(定位/卖点/主角路径/冲突/推进循环) |
| 4 | **确认方向 + 标题组** | 书名候选组 | 书级方案 ← **用户最后一个必修决定** |
| 5 | 创建小说 | 创建小说 | 项目(正文不会提前开始) |
| 6 | (自动) | 故事宏观 / 书契约 | 定位、核心冲突、推进循环、目标读者、前 30 章承诺、叙述边界 |
| 7 | (自动) | 世界搭建 / 角色生成 | 本书世界、角色候选 |
| 8 | (自动) | 应用角色阵容 | 角色写入正式资产 |
| 9 | (自动) | 卷战略 / 卷骨架 | 卷级路线 |
| 10 | (自动) | 节奏板 / 章节清单 / 章节同步 / 章节细化 | 章节任务单 + 执行资源 |
| 11 | **选择生产方式** | 生产方式交接 | 简易创作(只读书架,AI 接着写完)或专业创作(工作台) |
| — | (循环) | 章节执行 | 生成 → 审核 → 修复 → 记质量债 → 回灌状态 → 下一章 |

**产品哲学**:用户只做两个决定(选方向、选生产方式),其余由"自动导演"推进;
导演**固定推进到"可开写"再停下**让用户选方式;有明确停顿点
(等待方向选择 / 等待角色确认 / 卷战略就绪 / 章节批次就绪 / 等待重新规划)。

## 二、它的章节生产链(工程契约级,我摘最关键的五条)

1. **双通道**:正文热路径(生成 → 接收闸门 → 可选局部修文)与
   **异步资产回灌**(摘要/硬事实/状态快照/角色资源/关系动态/伏笔 delta)。
   热路径只求"尽快产出可读正文并保存",重活(全量伏笔对账等)按风险/周期条件触发。
2. **首章关键路径最小化**:首章前**只同步等待**"精简故事基础 + 开篇世界切片 +
   核心角色 + 3~5 章路线 + 第 1 章执行合同";完整世界、非开篇角色、远期卷规划、
   第 2 章以后的合同**都不是首章前置条件**。
3. **唯一执行链**(它写得最硬的一条):手动单章、批量、自动导演三个入口
   **必须落到同一个章节执行 runner**;正文 writer / 接收闸门 / 补丁修文 / 保存 /
   资产同步 / 复审**复用同一套 runtime 规则**,不允许任何入口"再维护第二套正文执行实现"。
4. **接收闸门 + 质量债终态语义**:一次结构化判断(继续 / 局部修 / 人工确认);
   终态动作要区分 `continue_with_warning`、`local_patch_plan`、`stop_for_replan`
   (全局重规划)、`defer_and_continue`(记质量债,继续产出)。
5. **确定性正文检测**(不调 LLM):AI 自述、占位符、工程词泄漏、截断、复读、
   否定翻转句、碎句、超长段落 —— 与我们做的净化同类,但它挂在接收闸门后、
   构建运行包前这个固定位置。

它还有:任务策略**启动时冻结**(恢复时读快照,不被后来的配置改动影响)、
以正文 **content hash** 判定资产同步幂等、writer **显式关闭推理模式**并按章节目标设输出上限。

## 三、我们融合了什么(11-17 那批,机制层)

| 吸收项 | 我们的落地 | 有测试 |
|---|---|---|
| 用量可见性 + 缓存 token 落库 + 估算标记 | `usage_summary` / `api/usage` / 前端 `/usage`,迁移 a1001960/61 | ✅ |
| 每章 token 预算闸门 | `chapter_budget` | ✅ |
| 修文"新增严重问题即拒" | `chapter_quality_gate._new_severe_findings` | ✅ |
| 伏笔缺铺垫判定 | `foreshadow_setup_check` | ✅ |
| 无嵌入时的词法召回兜底 | `lexical_cognition_rank` | ✅ |
| 结构感知切块 / 流式用量回填 | `chapter_chunker` / `stream_by_route` | ✅ |

**结论:融的都是"零件"。**

## 四、我们**没有**融合的(工作流层,也是今天撞墙的地方)

| 它的设计 | 我们的现状 | 今天撞到的问题 |
|---|---|---|
| **唯一执行链**(三入口同一 runner) | probe / `api/generate` / `tasks` **各有一套** | 规划链从没被真跑过 —— 第一次跑就 5 个缺件 |
| **首章关键路径最小化** | 章纲 prompt 塞整份书纲 + 整卷 100 章(6.6 万 tokens/章) | 已裁剪到 1.5 万,但"只等必要资产"的思路我们没实现 |
| **方向候选 → 用户确认 → 自动规划** | 没有;直接输入 premise 就生成书纲 | 用户没法在开书前挑方向 |
| **书契约 / 故事宏观 / 卷战略 / 节奏板 / 章节清单** 分层 | 只有 book / volume / chapter 三层 | 层与层之间没有"策略/节奏"这级 |
| **质量债终态语义**(defer / local_patch / stop_for_replan) | 只有 completed / needs_review / draft | 没有"带债继续写"的语义 |
| **任务策略冻结快照** | 无 | 恢复时读新配置 → 行为漂移 |
| 简易创作 / 专业创作两种生产方式 | 只有一套工作台 | — |
| 短篇独立流程、世界样本库、角色库、拆书、桌面版 | 无 | — |

## 五、最该吸收的三件事(按对我们的价值排序)

1. **唯一执行链**:把 probe / SSE / 队列三条路的"正文与规划执行"收进同一套 runtime。
   这不是为了好看 —— **我们今天的全部问题都源于这一点**:因为评估工具有自己的近路,
   正路就一直没人走。做完这条,规划链/生成链才有"一条被真跑过的路"。
2. **首章关键路径最小化**:开写第 1 章只等必要资产(精简故事基础 + 开篇世界切片 +
   核心角色 + 前几章路线 + 第 1 章合同),完整世界与远期卷规划**延后**。
   它同时解决"prompt 臃肿"和"必须先把 100 章规划做完才能写第 1 章"两个问题。
3. **质量债终态**:把"有正文但有问题"从"阻塞"改成"记账继续写"
   (`defer_and_continue`),只有结构化 `stop_for_replan` 才停。
   我们现在的 `needs_review` 太像"卡住",长篇里会一路卡死。

其余(方向候选、简易/专业双模式、资产库、短篇)是产品功能,可以后置。
