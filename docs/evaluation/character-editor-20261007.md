# 人物编辑草稿与保存核对

状态：前端实现、回归和类型检查完成，真实浏览器/数据库验收与部署未完成。

## 原有问题

侧栏每个字段失焦时发送整份渲染时的旧档案。连续修改身份和性格会发出两个不同的旧快照，后到请求可能覆盖先前的字段；读回刷新也会干扰正在输入的内容。独立人物页把选中人物作为加载依赖，切换选择会重新读取列表，延迟保存回调还可能把选择切回旧人物。切换项目时两处都缺少完整请求隔离。

## 修改

- 新增 `CharacterProfileEditor`，侧栏字段编辑与独立人物页 JSON 编辑共用。修改受控草稿，点击“保存人物”一次提交全部最新字段；保留未显示的别名和嵌套字段。明确取消旧的失焦即提交行为。
- 保存期间防重复提交，仍可输入。只有 POST accepted 且 GET 读回同名人物完整档案一致，才显示“已保存并核对”；读回失败/尚未同步保留草稿并提示，不用乐观更新冒充完成。
- 保存完成时仅更新已确认基线，不覆盖期间的新输入。读回如果改变人物投影 ID，侧栏按名称保持编辑会话。
- 草稿按项目/人物名称存入 sessionStorage，关闭、切换后可恢复。旧草稿基线与当前档案不同则禁止直接保存，显示草稿供复制核对；浏览器存储不可用时仍可编辑，但不承诺离开后的恢复。
- 两个页面以项目作为会话键，人物编辑器以项目/人物作为键；取消旧请求并忽略迟到结果。独立人物页取消选中人物触发的重复加载以及 1.5 秒延迟刷新覆盖。
- 侧栏列表读取增加顺序保护、卸载取消与定时器清理；失败/不完整响应显示错误和重试，保留现有列表，不伪装为空作品。

## 本地独立复核

按 shadow-mind 的无可靠只读隔离回退执行数据保真和异步界面两次检查。修复旧项目提交后继续发起读取、列表缺字段误报空、StrictMode 清理后的旧 loading 更新及投影 ID 改变重建编辑器的问题；补充回归后 focused/类型检查通过。

## 后续缺口

- 前端读回核对不提供服务器 CAS；两个浏览器、两个作者或后台旧快照仍可能产生版本竞争。下一步需要服务端作者版本/条件写和投影顺序保护。
- 202 accepted 仍可能发生“图已写、PG 未同步”。当前保留草稿并报告未确认，不代替服务端持久回执与恢复。
- 新增/删除人物、世界规则编辑以及删除与进行中保存的并发合同尚需统一；本轮没有把这些流程算作已验收。
- 真实浏览器多标签页、存储不可用、切换和网络异常验收待执行；当前网络限制下未部署。
