# 摘要来源与复用校验

## 本轮实现

新增迁移 `a1001922` 和 `Chapter.summary_source_hash`。指纹以长度分帧的标题、完整正文及摘要内容计算 SHA256；标题或正文更改、另一路径替换摘要，都不能继续通过旧指纹。NULL 表示来源未知，迁移不拿当前正文替旧摘要伪造来源，也不删除原摘要。

`summarize_and_save_chapter` 仅在指纹匹配且数据库中的来源快照仍一致时复用已有摘要。来源不明/不匹配会重新生成，失败返回空结果而不是旧摘要。新摘要及指纹在同一条件 UPDATE 内写入，沿用正文/标题/状态/位置/更新时间的并发校验，并新增指纹自身校验。目标章节有待提交修改时不处理；首次读取禁用 autoflush，避免为检查复用而写入作者修改。

RAG 重建通过共享助手获得这一行为：`force=False` 只保留已验证对应当前稿件的摘要；未知来源的旧摘要需要重新生成。`force=True` 仍强制生成并遵守并发保护。

作者通过章节更新 API 明确提交摘要时，绑定更新后的标题/正文；显式清空摘要也清空指纹。只改正文或标题不会自动替旧摘要重新盖章。整书任务快照及回滚保存、恢复指纹；旧快照无此字段时按未知来源处理。

## 验证与复核

最终完整后端回归 **1571 passed, 5 warnings**（98.33秒），日志 `/tmp/aiwrite-provenance-full-suite.log`。既有短JWT测试密钥、SQLAlchemy未归还连接及Qdrant版本探测警告未抑制。新增回滚来源和HTTP作者更新测试均通过。

真实隔离 PostgreSQL 测试覆盖正文/标题/摘要变更、未知来源、生成失败、并发改指纹、旧ORM缓存、未提交作者摘要、迁移升级/降级/重复升级不改旧内容和整书回滚恢复来源。HTTP 测试覆盖作者同次提交正文+摘要、随后改稿及清空摘要。

首轮全量出现1项新并发用例失败：`db.get` 在检查前 autoflush 了未提交摘要，导致误判可复用。已关闭该读取的自动flush，并对待提交目标返回空结果；相关65项通过。最后新增回滚来源回归，与全量一起验证。

按 shadow-mind 进行本地正确性、架构两轮独立复核（本机没有可信只读子代理隔离）。确认不能只给正文盖章而忽略摘要被替换，也不能仅凭ORM缓存判断来源仍有效；迁移不得用当前稿件补造旧来源。

## 明确未完成

- 当前只收敛共享摘要生成/复用及RAG重建入口。ContextPack、评审邻章、旧层级记忆、卷摘要生成等直接读取 `Chapter.summary` 的位置尚须接入来源判定。
- Qdrant payload尚未携带此指纹并回查当前PG版本；旧向量、压缩记忆、草稿状态、删除或改序后的投影仍需失效/重放协议。
- HookManager、incremental_sync以及大纲同步仍有摘要旁路，未通过共享助手获得来源标记；不能默认把这些输出认作已验证历史。
- 实体 ExtractionMarker仍按项目+全书章号跳过已完成抽取，未绑定稿件，后续必须修复。
- 摘要仍有6000字首尾裁剪、220字截断及伪JSON unicode_escape路径，完整性和中文保真修复尚未完成。指纹匹配不等于事实准确或文学质量合格。
- 未部署。部署时必须先迁移至a1001922（含a1001921），再运行使用新模型字段的服务；未知摘要重建会增加真实模型调用量。
