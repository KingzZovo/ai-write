# 模型失败日志耐久性与评审候选核对

## 已证实的运行问题

上一轮完整章节的最终评审失败，但按章查询 llm_call_logs 只得到规划、正文、前置检查、摘要成功记录。路由六个记录入口都在 log_llm_call 正常退出后才提交；该上下文管理器遇异常会 flush 错误行再重新抛出，外层跳过 commit，关闭会话时又回滚该行。因而“每次回退都有日志”的原注释与实际行为不符。

六个自管入口现把日志提交放入 finally，覆盖任务路由、显式路由和分级回退的普通/流式两种方式。日志上下文也将 CancelledError 与 GeneratorExit 标记为 error 并重新抛出，部分流文本保留；不把取消或主动关闭记为成功。借用日志上下文仍只 flush，由会话所有者决定提交。既有 best-effort commit/rollback 继续保证日志失败不把成功正文变成模型失败，也不替换原模型异常。
