# 跨进程模型路由刷新

日期：2026-10-07。接续端点提交竞态修复；本批没有改变模型默认值或提示词内容。

## 已解决的问题

此前端点 API 只重置所在进程的单例。其他常驻进程，以及在构造时保存了 `self.router` 的服务，可能无限期保留旧端点、旧密钥或旧模型。Prompt 的 300 秒 TTL 不会刷新 ModelRouter。

现在托管路由使用 30 秒单调时钟缓存。缓存过期后，下一次异步获取或模型调用先读取已提交配置；普通/流式生成、显式路由、普通/分层回退及嵌入均覆盖。无请求的进程无需后台轮询。刷新耗时另计；这是请求边界上的有界缓存，不是即时广播或中断已经开始的模型请求。

- 长期保存的旧对象在发起下一次调用时解析到当前快照，已开始的流式输出继续原配置。
- 加载使用独立短事务、REPEATABLE READ，使端点与提示词绑定来自同一已提交快照，不在模型网络请求期间占用该事务。
- 更新途中重置、加载失败与取消均不发布半成品。配置读取失败明确报错，不继续用过期配置；数据库已有端点但全部禁用时，不启用环境变量端点绕过禁用。
- 数据库端点地址/凭据未变时复用客户端，保留用量累计；密钥变更则使用新客户端，不强行关闭仍被运行中调用使用的旧客户端。
- 活跃 Prompt 按任务取最高版本；比较不含计数器的脱离 ORM 快照，内容或绑定变化时清理本进程 Prompt 缓存。Registry 先刷新路由，再解析提示词，避免本次请求先拿旧模板再失效缓存。
- 手工构造的独立 ModelRouter 不自动绑定数据库，保留测试及显式注入用途。

## 验证证据

57 项针对性测试通过，覆盖过期并发只加载一次、旧引用的七种生成入口及嵌入、客户端复用/密钥轮换、失败/取消、不误启用环境端点、运行中流式隔离、提示词缓存失效。

真实 PostgreSQL 验证：

1. 两个独立 Python 子进程预热各自缓存；父进程提交模型/提示词修改，子进程无广播、无重启，缓存到期后均看到新值。端点禁用后两进程均无可用聊天端点。测试推进缓存时间戳，不实际等待 30 秒，不向上游发请求。
2. 在加载器读取端点后，由另一个连接修改端点与 Prompt 并提交；加载器的后续 Prompt SELECT 仍读到旧版，下一份快照读到两者新版，未混用新旧配置。
3. 上轮 CRUD 跨连接可见性、提交失败不失效及加载途中被重置的测试继续通过。

首轮全量 1871 passed/1 failed，失败为旧测试禁止获取路由函数；独立复测确认仍返回缺少章节绑定且没有模型调用。断言调整为禁止实际生成/流式模型调用，保留“不回退通用评分器”的业务约束。最终全量 **1873 passed、4 项既有 warnings，269.18 秒**；日志 `/tmp/aiwrite-router-refresh-full-final.log`。

隔离库只读探针：2 个聊天端点、40 个任务路由、41 份 Prompt 快照；冷加载 0.606 秒，100 次缓存命中合计约 0.000053 秒，5 次强制过期刷新 7–11 毫秒。客户端复用、配置未变通过。此结果不代表生产吞吐 SLA。

## 独立复核及剩余工作

按 shadow-mind 的隔离限制执行本地独立复核，没有启动共享可写目录的影子代理。正确性复核检查了失效/取消交错、缓存时间戳初始化、旧引用与流式快照；架构复核检查全部模型 IO 入口、客户端生命周期、独立事务及提示词解析顺序。发现未初始化时间戳可能被当成有效缓存，已改为 None；无可信时间戳不走缓存命中。

本批刷新不撤销正在执行的调用，也不自动选出合格模型。T2 旧模型下线、备用模型任务质量、中文小说事实评审、上一批闲置事务与 prompt UPDATE 归因、完整工作流与正式上线仍待处理。任何新默认模型仍需真实稿件与对照样本验证，不能用可连接或模型自评分替代文学验收。
